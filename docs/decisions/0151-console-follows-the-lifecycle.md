# ADR-0151. 콘솔을 BPM 생애주기로 묶고 대시보드를 홈으로 — 저작 → 배포 → 운영

## 배경

[ADR-0149](0149-console-menu-follows-the-work.md)가 메뉴를 「일의 흐름대로」 여섯으로 세웠다 —
설계 › 배포 › 운영 › 업무 › 연결 › 관리. 그 뒤 두 가지가 드러났다.

1. **「업무」를 따로 둔 까닭이 틀렸다.** 그때는 「결재는 운영자가 아니라 결재자의 일」이라 갈랐는데,
   **결재의 정식 길은 API다** — 대리 답용 키(`relay`, [ADR-0081](0081-answering-on-behalf.md))가 그것을
   위해 있고 회사 시스템이 `GET /approvals?assignee=<사람>`로 그 사람 몫만 읽어
   `X-BPM-On-Behalf-Of`로 답한다. 사람이 콘솔에 들어와 결재함을 여는 것은 **예외**다.
   콘솔 결재함의 쓸모는 ① **막힌 것 찾기** ② **담당자가 없는 결재 답하기**(대리 답을 받지 않는다,
   ADR-0081) ③ **감사**(`answered_via`로 어느 길로 왔나) 셋이고, 셋 다 운영자의 일이다.
2. **들어와서 「지금 무슨 일이 있나」를 보는 자리가 없다.** 첫 화면이 역할로 갈려 작업공간이나
   프로세스 현황으로 **보내 버린다**([ADR-0145](0145-console-is-workspace-shaped.md) §2) — 어느 쪽이든
   한 화면의 한 가지만 보인다. 실패한 실행·승인 기다리는 후보·막힌 결재는 서로 다른 화면에 있어
   사람이 셋을 돌아다니며 확인한다.

그리고 묶음 이름이 **일**(설계·배포·운영)과 **대상**(업무·연결·관리)으로 섞여 있어, 축이 하나로
읽히지 않는다.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. 지금 여섯을 그대로 두고 대시보드만 더한다 | 손이 가장 적다 | 「업무」가 남아 결재함이 운영자의 손에서 멀다. 축이 여전히 섞여 있다 |
| B. **생애주기 세 기둥 + 대시보드 + 관리 둘** — 대시보드 / 저작 / 배포 / 운영 / 연결 / 권한·조직 | BPMN을 아는 사람의 머릿속 그대로다(만들고 → 내보내고 → 지킨다). 「무엇을 하는 중인가」가 레일에 그대로 있고, 운영자가 쓰는 넷(현황·기록·결재·작업)이 **한 묶음**이다 | 화면 열셋의 「메뉴」 줄이 또 바뀐다(ADR-0149에서 한 번 바뀌었다). 대시보드는 새 화면이다 |
| C. 세 기둥만 (대시보드 없이, 관리도 운영에) | 레일이 가장 짧다 | 조직·계정이 운영 안에 섞인다 — 성격이 다르다(사람·권한). 들어오는 자리는 여전히 없다 |

## 결정

**B.** 레일 여섯을 **생애주기 차례**로 세운다.

| 묶음 | 줄 | 화면 |
| --- | --- | --- |
| **대시보드** | (화면 하나) | **CON-21 (새)** |
| **저작** | 「작업공간」 | CON-20 |
| **배포** | 「배포」 / 「공통 패키지」 | CON-15 / CON-06 |
| **운영** | 「프로세스」 / 「실행 기록」 / 「결재함」 / 「작업 지시」 | CON-02 / CON-01 / CON-04 / CON-05 |
| **연결** | 「연결 앱」 / 「일꾼」 | CON-18 / CON-17 |
| **권한·조직** | 「조직」 / 「관리자 계정」 / 「변경 이력」 | CON-13 / CON-14 / CON-16 |

1. **「업무」 묶음을 해체한다** — 결재함·작업 지시는 「운영」으로 간다 (위 §배경 1).
2. **「변경 이력」은 「권한·조직」으로** — 등록·키·배치 이력은 운영이 아니라 관리다.
3. **대시보드(CON-21)가 홈이다** — **역할로 가르지 않는다**(ADR-0145 §2를 대체). 카드마다
   **숫자 하나와 그 화면으로 가는 링크**뿐이고, 숫자를 세는 코드는 화면이 아니라 `lib/dashboard.ts`에
   둔다(페이지는 `server-only`를 끌고 와 단위 시험에서 못 부른다 — CLAUDE.md의 규칙 그대로).
   **쓰기 단추를 두지 않는다** — 대시보드에서 승인·배포를 누르게 하면 같은 단추가 두 곳에 생긴다.
4. **용어를 「저작」으로 바꾼다** — 콘솔·용어집·화면 문서에서 「설계」 대신 **「저작」**이다. BPM 프로세스를
   그리고 시험하고 배포 후보로 짓는 일 전체를 가리킨다. **업무 예제의 「설계 변경」처럼 업무 낱말인
   것은 그대로**이고, 지나간 결정의 본문도 고치지 않는다 (CLAUDE.md §4).

바꾸지 않는 것: 두 층 틀(레일 56 + 펼침 패널 224 + 위 막대 48, ADR-0145), 지금 자리 줄의 모양
(`<묶음> › <자리>`), 화면 글이 「프로세스」라 쓰는 것(ADR-0121), 상태 표기·색(`status_map`).

## 결과

- 좋아지는 것: 레일이 **한 축**(생애주기)으로 읽힌다. 운영자가 하루에 보는 넷이 한 묶음에 모이고,
  들어오자마자 **실패·막힘·기다림**이 한 화면에 보인다. 「기타」라는 서랍을 만들지 않았다.
- 포기하는 것: 화면 문서의 「메뉴」 줄이 또 바뀐다. 결재만 하러 들어오는 사람은 「운영」을 거친다
  (그 사람의 정식 길은 회사 시스템이다 — ADR-0081). 「저작」과 「설계」가 지나간 글에 섞여 보인다.
- 다시 볼 조건: 대시보드의 카드가 여섯을 넘으면 **역할로 가르는 것**을 다시 본다(지금은 가르지 않는다).
  「권한·조직」에 줄이 넷을 넘으면 가른다. 담당자 없는 결재가 운영에서 자주 막히면 **실행 전 검사의
  경고**로 올린다 (지금은 적어만 둔다 — `docs/09-gaps.md`).
