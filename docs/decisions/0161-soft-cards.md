# ADR-0161. 콘솔은 「부드러운 카드」로 입는다 — 밝은 위 막대, 따뜻한 바탕, 좁은 화면에서는 표가 카드가 된다

| 항목 | 값 |
| --- | --- |
| 상태 | 일부 대체됨([ADR-0164](0164-neutral-pro.md) — 바탕색·위 막대 모양. 반응형·카드 목록은 그대로) |
| 날짜 | 2026-11-20 |
| 관련 | 화면 CON-00(틀·로그인), `docs/07-style-guide.md`, `design/tokens.json`, [ADR-0017](0017-web-nextjs-design-system.md)(Tailwind — **그대로 산다**), [ADR-0152](0152-console-chrome-is-one-top-bar.md)(위 막대 하나 — **구조는 그대로**, 짙은 틀만 이 결정이 대체한다), [ADR-0154](0154-the-login-band-is-mark-and-name.md)(로그인 띠 — 이 결정이 대체한다), [ADR-0157](0157-status-colours-stay-under-the-brand.md)(상태 색 — **그대로 산다**) |

## 배경

사용자가 로그인을 포함한 콘솔 전부의 UI/UX를 새로 입히고 **반응형**으로 만들자고 했다.
Tailwind 4는 이미 깔려 있고 토큰이 Tailwind 테마로 이어져 있어(ADR-0017) 빠진 것은 Tailwind가 아니라 **디자인 언어와 좁은 화면**이었다.
화면 26개를 통틀어 화면 폭에 따라 바뀌는 자리가 20여 군데뿐이었고, 그래서 사실상 넓은 화면 전용이었다 — 표가 휴대폰 폭을 넘어 가로로 밀렸다.
틀은 짙은 남색 막대 + 흰 머리 띠 + 연회색 바탕 + 작은 모서리(4~8)로, 「일하는 화면」(D2)에는 맞았지만 무겁고 딱딱하다는 말을 들었다.

## 선택지

시안 셋을 그려 사용자가 골랐다.

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A 차분한 작업대 — 흰 면, 왼쪽 사이드바, 휴대폰은 아래 탭 막대 | 익숙한 관리 콘솔 모양 | ADR-0152가 걷은 왼쪽 탐색이 돌아온다 |
| B 남색 관제실 — 지금 틀을 다듬어 잇는다 | 바뀌는 것이 적다 | 「전면 개편」이 아니다. 좁은 화면 문제는 그대로 남는다 |
| **C 부드러운 카드** — 따뜻한 바탕, 큰 모서리, 밝은 위 막대, 좁은 화면에서 표가 카드가 된다 | 결재자가 휴대폰으로 들어와도 읽힌다. 위 막대 하나(ADR-0152)의 구조를 그대로 쓴다 | 한 화면에 들어가는 줄이 줄어든다(컨트롤·줄 높이가 커진다) |

## 결정

**C를 고른다.** 구조(위 막대 하나·묶음 여섯·지금 자리 줄)는 ADR-0151·0152 그대로이고 **입는 것과 좁은 화면**이 바뀐다.

1. **바탕은 따뜻한 회색, 면은 흰색, 모서리는 크다** — `bg.canvas`·`bg.subtle`·`border.*`를 따뜻한 쪽으로 옮기고 `radius`를 6/10/14/20으로 키운다. 그림자는 옅고 넓게. 브랜드 `primary`와 상태 7색(ADR-0157)은 **그대로**다 — 화면에서 가장 진한 색은 여전히 주 단추 하나다.
2. **위 막대는 밝다** — Center 콘솔이 짙은 틀(`.chrome`)을 벗는다. 막대는 `bg.surface`에 아래 선 하나, 묶음 여섯은 **알약 하나에 담긴 마디**이고 지금 자리의 묶음은 흰 알약이 떠 있다. `chrome.*` 토큰은 **서비스 앱 콘솔이 아직 쓰므로** 남긴다(그 콘솔은 이번 범위 밖이다).
3. **흰 머리 띠를 걷는다** — 지금 자리 줄과 제목이 바탕 위에 바로 선다. 본문은 가운데 최대 폭(1440) 안에 서고 여백은 좁은 화면 16 → 넓은 화면 32다.
4. **컨트롤이 커진다** — `control.md` 36, `lg` 44(손가락), 표 줄 44. 손으로 누르는 자리는 44 아래로 내리지 않는다.
5. **좁은 화면(768 아래)에서 표는 카드 목록이 된다** — `DataTable` 하나가 그렇게 하므로 목록 화면이 모두 따라온다. 카드마다 첫 열이 제목이고 나머지 열은 「머리 : 값」 줄이다. 업무 값 열 접기(U10)는 그대로다.
6. **모든 화면이 360px에서 읽히고 결재함은 답할 수 있다** (CON-00의 기준을 넓힌다). **작업공간(CON-20)은 1024 아래에서 보기만 한다** — 그림과 시험 결과는 보이고 탐색기·속성 패널·편집은 넓은 화면의 것이다(사용자가 골랐다).
7. **로그인은 따뜻한 바탕 위 카드 하나다** — 화면 폭 띠(ADR-0154)와 배경 그림(`public/brand/login-bg.webp`)을 내리고, 카드 맨 위에 둥근 칸 안의 마크와 「BPM」, 그 아래 두 칸과 **폭 전체의 「로그인」**이다.

## 결과

- 쉬워지는 것: 휴대폰에서 결재·실행 기록을 본다. 목록 화면이 `DataTable` 하나로 반응형이 되어 화면마다 따로 손대지 않는다.
- 어려워지거나 포기하는 것: 넓은 화면에서도 한 번에 보이는 줄이 조금 준다(줄 높이 36 → 44). 서비스 앱 콘솔은 바탕·모서리만 따라오고 틀은 아직 짙다 — 두 콘솔이 잠시 다르게 보인다.
- 다시 볼 조건: 운영자가 「한 화면에 줄이 적다」고 하면 `DataTable`의 `compact`(36)를 목록 화면 기본으로 돌린다. 서비스 앱 콘솔을 손볼 때 `chrome.*`을 걷는다.
