# ADR-0172. 서버 실행기는 「운영」에 제 줄을 갖고, 일정은 작업 지시로 간다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 · **줄의 묶음은 대체됨** ([ADR-0181](0181-menu-puts-approvals-on-top-and-approval-in-deploy.md) — 「서버 실행기」는 「시스템」 아래다. 제 줄을 갖는 것·일정이 작업 지시로 간 것은 그대로) |
| 날짜 | 2026-11-20 |
| 관련 | CON-02·CON-05·CON-12·CON-21, [ADR-0151](0151-console-follows-the-lifecycle.md)(메뉴 여섯 — 묶음은 그대로, 「운영」에 줄 하나), [ADR-0149](0149-console-menu-follows-the-work.md), [ADR-0144](0144-remove-the-pc-runner.md), [ADR-0110](0110-center-keeps-the-schedule.md) |

## 배경

PC 실행기를 걷으며(ADR-0144) CON-02 「프로세스」의 탭이 없어졌고, 「서버」 탭에 있던 서버 실행기
목록(CON-12 「목록」)이 **그 화면 아래에 그대로 붙었다** — 실행기 표·「승인 대기」·Center 대기열,
그리고 그 밑에 「일정」까지. 프로세스 표가 쪽으로 나뉘자(ADR-0167) 이 셋은 쪽 단추 **아래**에
서게 되었고, 사용자는 「다른 곳이나 형태로 관리되었으면」 했다.

- CON-02는 **판마다의 준비도**를 보는 화면이다. 실행기·대기열은 판이 아니라 **실행이 도는 자리**의 것이다.
- `/server-runners`는 `/bots`로 넘기기만 하고, 상세 `/server-runners/<id>`는 메뉴 자리가 「운영 › 프로세스」였다.
- 「일정」은 차례마다 **작업을 만든다**(C5 §일정) — 「언제 돌릴지 시킨다」는 CON-05 「작업 지시」의 말이다.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. 「운영 › 서버 실행기」 줄을 더해 `/server-runners` 목록을 되살린다 | CON-12 「목록」이 손대지 않고 제 화면에 선다. 상세가 제 메뉴 자리를 갖는다 | 「운영」 줄이 다섯이 된다. 실행기는 대개 한 대뿐이다 |
| B. 실행기는 「연결」로, 대기열은 CON-05 「대기」 거르기에 합친다 | 같은 작업이 두 화면에 나오지 않는다 | 실행기는 바깥을 들이는 것이 아니다(「연결」은 부르는 바깥 앱과 그 일꾼). 대기 이유가 CON-05 열로 옮겨야 한다 |
| C. CON-02 위에 실행기 요약 한 줄만 둔다 | 메뉴가 그대로다 | 여러 대·승인 대기·대기열을 한 줄에 담지 못한다. 결국 CON-02에 남는다 |

## 결정

**A로 한다** (사용자가 골랐다).

1. 「운영」 묶음 맨 아래에 **「서버 실행기」** 줄 — 설명 「실행이 도는 곳과 Center 대기열」, 주소 `/server-runners`.
   CON-12 「목록」(실행기 표·「승인 대기」·「대기열」)이 그 화면이고 상세 `/server-runners/<id>`도 이 줄에 선다.
   묶음 여섯과 차례는 그대로다 (ADR-0151).
2. CON-02에는 **프로세스 표만** 남는다 — 아래에 붙은 영역이 없다.
3. 「일정」은 **CON-05 「작업 지시」 아래**로 간다. 없으면 영역이 없는 것은 그대로다.
4. 대시보드 C4 「실행기」 카드는 「운영 › 서버 실행기」로 잇는다.

## 결과

- 쉬워지는 것: CON-02가 판 하나의 화면이 된다. 실행기가 어디 있는지 메뉴가 말한다.
- 포기하는 것: 「운영」 펼침이 줄 다섯이다. 대기열 작업은 CON-05의 「대기」 거르기와 이 화면 두 곳에서 보인다(이 화면은 **왜 기다리나**를 말한다).
- 다시 볼 조건: 실행기가 늘 한 대뿐이고 볼 일이 재시작뿐이라면 상세 한 장으로 줄이는 것을 다시 본다.
