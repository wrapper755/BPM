# ADR-0143. 설계는 콘솔에서 한다 — BPM 프로세스 편집기를 Center 콘솔로 들이고 데스크톱 Studio를 걷는다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-11-12 |
| 관련 | 계약 C1·C2·C5·C14·**C17(새 — 작업공간)**, [ADR-0017](0017-web-nextjs-design-system.md)(웹 스택), [ADR-0022](0022-studio-canvas.md)(캔버스), [ADR-0029](0029-bpmn-js-vendoring.md)(bpmn-js 판 고정), [ADR-0144](0144-remove-the-pc-runner.md)(같은 묶음의 결정), [ADR-0145](0145-console-is-workspace-shaped.md)(그 화면의 모양), [ADR-0142](0142-open-mode.md)(열린 모드 — 이 결정이 그것을 더 급하게 만든다), 화면 STU-01~16 → CON-20 |

## 배경

지금 설계자는 **데스크톱 Studio**(PySide6, 21,000줄)에서 그림을 그리고, 패키지를 zip으로 **내보내** Center에 **올린다**
(STU-12, C5 `POST /packages`). 올린 것은 후보가 되고 관리자가 콘솔에서 승인·배포한다. 그 뒤 실행은 서버에서 한다
(ADR-0016 서버 우선).

사용자가 2026-11-12에 이렇게 짚었다: 「studio에서 제작을 하고 서버로 올리는 작업 자체가 큰 의미가 없다고 봄.」

맞는 지적이다. **서버에서 돌 것을 데스크톱에서 만들어 보내는 중간 단계**가 값을 내지 못한다.

- 캔버스는 이미 **bpmn-js**다 — QtWebEngine 안에 웹을 띄워 두고(ADR-0022), 판을 고정해 파이썬 쪽으로 **복사해
  커밋한다**(ADR-0029). 웹에서 그리면 그 두 장치가 둘 다 필요 없다.
- 설계에 필요한 거의 모든 것이 **이미 서버에 있다** — 리소스 목록(C7)·공유 BPM 프로세스 패키지(C5)·확장 명부(C13)·
  외부 작업(C15). Studio는 그것을 **읽어 오기 위해** 제 키로 Center에 들어오고(ADR-0093), 닿지 못하면 고를 거리가
  비어 설계가 막힌다.
- 올리기는 설계자에게 **한 걸음 더**이고, 거부 사유(200/409/422)를 데스크톱에서 다시 설명해야 한다.
- Studio를 설치·갱신해야 사람이 설계를 시작할 수 있다 — 설치 파일·판 찍기·산출물 워크플로가 그 때문에 있다
  (ADR-0024·0067·0068).

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. 그대로 둔다 | 손이 들지 않는다. 오프라인 설계가 가능하다 | 사용자가 값이 없다고 판단한 중간 단계가 남는다. 데스크톱 산출물·설치·판 찍기를 계속 들고 간다 |
| B. **편집기를 콘솔로 들이고 Studio를 걷는다** — 작업 폴더가 서버에 살고, 「올리기」 대신 **그 자리에서 배포 후보를 짓는다** | 설계·시험·승인·배포·지켜보기가 **한 화면 묶음**이다. 설치할 것이 없다. bpmn-js 복사본 커밋(ADR-0029)·QWebChannel(ADR-0022)·데스크톱 묶기(ADR-0024·0067·0068)가 함께 없어진다. 고를 거리가 늘 서버 것이다 | 가장 크다 — Qt 편집기 21,000줄을 웹으로 다시 짓는다. **오프라인 설계를 잃는다.** 업무 예제 49개를 지키는 오라클(Studio 시험 실행)을 먼저 옮겨야 한다 |
| C. 폴더만 `server/`로 옮기고 데스크톱을 유지한다 | 가장 적게 바뀐다 | 사용자가 말한 문제를 **하나도 풀지 않는다** — 올리기가 그대로다 |
| D. 웹 편집기를 더하고 Studio도 남긴다 | 옮기는 중에 오라클을 잃지 않는다 | 같은 편집기가 둘이다. 두 쪽이 같은 C14를 따로 구현해 **갈라진다**(속성 패널이 가장 넓다) |

## 결정

**B다.** 설계는 **Center 콘솔 안에서** 한다. 데스크톱 Studio는 걷는다.

### 1. 작업 폴더는 서버에 산다

- BPM 프로세스 작업 폴더(`process/`·`libs/`·`cases/`·`process.json`)가 **Center의 데이터 폴더**로 간다.
  그 폴더를 읽고 고치는 길이 **계약 C17 「작업공간」**이다 — 콘솔(BFF)만 부른다.
- **작업공간 하나 = BPM 프로세스 한 벌**이다. 새 개념을 만들지 않는다 — 「다른 이름으로 저장」의 단위가 이미 그것이다
  (한 벌 안에서 정의 하나만 복사하면 process id가 겹친다, ADR-0022).
- 파일이 원본이다. 콘솔은 **XML을 직접 짓지 않고** 캔버스(bpmn-js)를 거쳐 고친다 — ADR-0022가 정한 그 규칙은
  **웹에서도 그대로다**(실행 취소 한 걸음, 「저장 안 한 변경」, DI 순서). 결정표(.dmn)만 캔버스 밖이라 직접 쓴다
  (ADR-0109와 같은 결).

### 2. 「내보내기·올리기」 대신 「배포 후보로 만들기」

- 콘솔의 단추 하나가 **서버에서 zip을 짓고 그 자리에서 후보로 등록한다**. 두 걸음이 한 걸음이 된다.
- 짓는 코드는 **Studio가 쓰던 것 그대로**다 — 매니페스트를 그림에서 모으고(C1), `content_hash`는 받는 쪽이
  다시 계산한다(C2). 사람이 두 번 적지 않는다.
- **승인·배포는 바뀌지 않는다** (C2·C5·CON-06·CON-15). 후보가 바로 배포되지 않는다 — 콘솔에서 설계한 것이
  저절로 현장에 가면 안 된다.
- 공유 BPM 프로세스 패키지(`kind=process_lib`)도 같은 단추의 갈래다.
- `.bpmn` 파일을 **가져오는** 길은 남긴다 — 밖에서 그린 그림·옛 Studio 작업 폴더가 들어오는 자리다.

### 3. 시험 실행은 서버 실행기의 「시험 모드」다

- 콘솔의 「시험 실행」은 편집 중인 작업 폴더를 **그 자리에서 zip으로 묶어** 시험 작업으로 서버 실행기에 넘긴다
  (승인·서명 없이). 배포와 **같은 길**이라 볼륨을 나눠 갖지 않는다.
- 엔진·기다림·재개·결재를 **이미 하는 자리**라 실행 코드가 하나로 남는다. 시험 모드만의 규칙은 Studio가 지키던 것과
  같다 — 케이스가 답하고, **바깥으로 웹훅을 쏘지 않고**(시험 수신기로만), 메일은 담아 두고, 자율 수행이 배운 것은
  돌려주어 **콘솔이** 패키지에 적는다(엔진은 파일을 쓰지 않는다).
- 그래서 「Studio에서는 되는데 현장에서 안 된다」가 줄어든다 — 시험과 운영이 **같은 실행기**다.

### 4. 설계자의 키가 없어진다

- Studio는 제 Center API 키로 들어왔다(ADR-0093 — 요청 코드 승인, STU-16). 콘솔 안에서 설계하면 **콘솔 로그인
  하나**가 그 일을 한다. 「Studio용」 키 종류·STU-16·STU-10의 「다시 요청」이 없어진다.
- **그래서 콘솔 로그인의 무게가 늘었다.** 지금은 열린 모드(ADR-0142)로 지나가지만, 로그인 하나가 **그림까지** 고치게
  되므로 `docs/09-gaps.md` §3-33(어디까지 조일지)에 이 결정이 **그것을 더 급하게 만들었다**고 적는다.
  설계 권한을 보기 전용 계정에 주지 않는다 — 역할은 이미 있다(C16).

### 5. 데스크톱 산출물이 없어진다

[ADR-0144](0144-remove-the-pc-runner.md)가 PC 실행기를 걷으므로, 이 결정과 함께 **묶을 데스크톱 앱이 하나도 남지
않는다.** `packaging/`·설치 파일·`--selftest`·산출물 워크플로·Windows CI가 그 자리에서 할 일이 없어진다
(ADR-0024·0067·0068·0104·0108). **판 찍기(`core.build_info`)는 남는다** — 서버 실행기가 C4 `versions`로 올린다.

### 6. 옮기는 순서 — 오라클을 먼저 옮긴다

`tests/studio/test_m3_acceptance.py`가 업무 예제 49개를 지키는 자리다(Studio 시험 실행). **서버 시험 실행이 같은
49개를 같은 짜 둔 답(`tests/canned_answers.py`)으로 초록으로 만든 뒤에** Qt를 지운다. 반대로 하면 **엔진·케이스·
기대값이 한 줄로 맞물리는가**를 볼 길이 사라진다.

## 결과

- 쉬워지는 것: 설계자가 **설치할 것이 없다**. 설계·시험·승인·배포·지켜보기가 한 묶음이다. 고를 거리가 늘 서버
  것이라 「닿지 못해 비었다」가 없다. bpmn-js를 pnpm 의존으로 쓰고 **복사본을 커밋하지 않는다**(ADR-0029가 풀린다).
  속성 패널이 **한 벌만** 남는다. 시험과 운영이 같은 실행기다.
- 어려워지거나 포기하는 것: **오프라인 설계가 없다** — Center에 닿지 못하면 그림을 고칠 수 없다(전에도 고를 거리는
  못 받았지만 그리기는 됐다). Qt 편집기를 웹으로 다시 짓는 일이 이 묶음에서 가장 크다. 작업 폴더가 서버에 있으니
  **백업이 Center의 일**이 된다. 설계자의 PC 파일(읽기 폴더·표본)을 집던 자리는 업로드로 바뀐다.
- 다시 볼 조건: 오프라인 설계가 실제로 필요해질 때(현장에서 망 없이 그려야 한다면) — 그때는 **가져오기·내보내기**로
  받치고 편집기는 하나로 둔다. 데스크톱 편집기를 다시 들이지 않는다.
