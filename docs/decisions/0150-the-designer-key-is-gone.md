# ADR-0150. Studio 키 종류를 걷는다 — 시험 실행의 외부 작업은 그것을 들고 있는 서버 실행기가 올린다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-11-15 |
| 관련 | [ADR-0143](0143-design-happens-in-the-console.md) §4(설계자의 키가 없어졌다 — 이 결정이 그것을 코드까지 옮긴다), [ADR-0146](0146-design-work-has-its-own-lane.md)(시험 실행·짓기의 자리), [ADR-0102](0102-calling-outside-is-pull.md) §호출 토큰을 대체, [ADR-0149](0149-console-menu-follows-the-work.md)(화면 쪽을 먼저 닫았다), 계약 C5·C7·C15·C17, 공백 [09-gaps](../09-gaps.md) §3-35 |

## 배경

[ADR-0143](0143-design-happens-in-the-console.md) §4가 **「설계자의 키가 없어졌다」**고 정했는데
계약과 Center에는 키 종류 `studio`가 그대로 있었다 (09-gaps §3-35). 화면 쪽은
[ADR-0149](0149-console-menu-follows-the-work.md)가 닫았고(CON-03), 남은 것은 계약·Center·시험이다.

걷을 자리를 세어 보니 **걷기만 해서는 안 되는 자리가 하나** 있다.

- **C15가 「시험 실행의 외부 작업」을 Studio 키에만 열어 두었다.** 실행 id가 `test_…`인 외부 작업과
  **자율 수행**은 Studio 키로만 올릴 수 있다 — 데스크톱 Studio가 시험 실행을 돌릴 때 쓴 자리다.
  시험 실행은 그 뒤 **서버 실행기의 시험 모드**로 옮겼는데([ADR-0143](0143-design-happens-in-the-console.md)·[ADR-0146](0146-design-work-has-its-own-lane.md))
  Center는 실행기 키가 올린 `test_…`를 403 `run_not_owned`으로, 자율 수행을 403 `mode_not_allowed`로
  막는다. **지금 시험 실행이 서비스 앱을 부르면 막힌다** — 업무 예제의 M3 묶음이 서비스 앱을 밟지
  않아 초록인 채로 남아 있었다. 그러니 Studio 갈래를 지우면 그 자리가 **비는** 것이 아니라 **닫힌다**.
- **호출 토큰도 청하는 쪽이 없어진다.** `POST /api/v1/call-tokens`(24시간)은 Studio 키로만 청했다 —
  데스크톱 Studio가 확장 클라이언트에게 제 오래 사는 키 대신 줄 토큰이었다. 서버 실행기의 확장은
  **실행기 제 Center API 키**를 `call_token`이라는 이름으로 받으므로(C13) 청할 사람이 없다.
- **이미 발급된 Studio 키가 남아 있는 Center가 있다.** 관문(`PACKAGE_KEY_TYPE`·`POSTER_KEY_TYPES`)을
  걷으면 그 키로 할 수 있는 일은 없어지지만, **키 종류를 보는 코드가 함께 없어진다**는 것이 문제다 —
  살아 있는 `call_token` 행은 `call_token_scope` 관문이 사라진 뒤 **아무 제한 없는 키**가 된다.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. 종류만 걷고 시험 자리는 공백 목록에 적는다 | 조각이 작다 | 시험 실행이 서비스 앱을 부르지 못하는 것이 그대로 닫힌다. 예제가 그 자리를 밟는 날 「설계에서는 되는데」가 아니라 **설계에서도 안 된다** |
| B. **종류를 걷고 시험 자리를 서버 실행기로 옮긴다** | 자리가 비지 않는다. 「누가 올리나」가 **하나**가 된다 (서버 실행기) | C15·C5를 함께 고쳐야 하고 Center가 시험 실행의 주인을 확인하는 코드가 는다 |
| C. 종류를 남기고 콘솔이 Studio 키를 발급하게 한다 | 고칠 것이 없다 | ADR-0143 §4를 뒤집는다. 설계가 콘솔 안인데 콘솔 밖의 설계자 키를 다시 들이는 셈이다 |

## 결정

**B.**

1. **키 종류 `studio`를 걷는다** — C5 권한표, C7 `KEY_TYPES`·`ISSUABLE_KEY_TYPES`, 등록 요청과 승인
   (`POST·GET /api/v1/studio/enroll`·`StudioEnrollRequest`·`StudioVersions`), Center의 Studio 갈래
   (`enrollments.py`, 같은 PC의 옛 키 폐기, `organization.py`의 `studios` 셈).
2. **패키지 올리기·읽기는 콘솔 토큰만** (C5 권한표). 짓는 길은 콘솔이 쥐고 있다 —
   실행기가 지은 zip은 Center가 **단추를 누른 계정의 이름으로** 등록하므로(ADR-0146) HTTP 관문을
   지나지 않고, `uploaded_by`도 사람 이름 그대로다. 자동화·CI는 관리자 토큰을 쓴다.
3. **시험 실행의 외부 작업은 그 시험 실행을 들고 있는 서버 실행기가 올린다.** Center는 실행 id가
   `test_…`일 때 **그 시험 실행이 도는 중이고 그 작업이 이 실행기로 내려갔는지**
   (`test_runs.job_id` → `jobs.target_id`) 본다. 통과하면 **자율 수행도 받고** 배포 대조
   (`topic_not_required`)는 **하지 않는다** — 시험 실행에는 배포가 없다(그림이 묶음으로 온다).
   아니면 403 `run_not_owned`이다. 운영 실행은 그대로다 (`test_…`를 받지 않고, 결정 수행만).
4. **호출 토큰을 걷는다** — 키 종류 `call_token`, `POST /api/v1/call-tokens`, 관문
   `call_token_scope`, 계약 모델 `CallToken`·`CALL_TOKEN_HOURS`. **확장의 비밀 이름 `call_token`은
   그대로다** (C13) — 그 값은 실행기 제 키이고, 확장에서 보면 이름이 바뀔 까닭이 없다.
5. **남아 있는 Studio 키와 호출 토큰은 폐기 표시한다** (판 올리기 하나). 지우지 않는 까닭은
   패키지의 `uploaded_by`와 변경 이력이 가리킬 곳을 잃기 때문이고, 그대로 두지 않는 까닭은
   종류를 보는 관문이 없어진 뒤 **제한 없는 키**가 되기 때문이다. **대기 중인 Studio 등록 요청은
   거절로 닫는다** — 승인할 길이 없어졌으니 사람이 영원히 기다리게 두지 않는다.

## 결과

- 좋아지는 것: 외부 작업을 올리는 쪽이 **서버 실행기 하나**가 되어 C15의 「누가 올리나」 표가 한 줄이고,
  **시험 실행이 서비스 앱을 부를 수 있다**(닫혀 있던 자리가 열린다). 발급할 수 있는 키 종류가 셋이다
  (실행기·연동용·대리 답용). 09-gaps §3-35가 닫힌다.
- 포기하는 것: 콘솔 밖에서 패키지를 올리려면 **관리자 토큰**이 필요하다 (ADR-0013이 피하려던 것인데,
  설계자 PC가 없어져 피할 까닭도 없어졌다). 24시간짜리 토큰을 다시 쓰려면 새로 정해야 한다.
- 다시 볼 조건: RPA 데스크톱 일꾼이 오면(ADR-0144) **그 일꾼이 무슨 키로 외부 작업을 올리나**를
  정해야 한다 — 일꾼은 가져가는 쪽이라 올릴 일이 없을 것이지만, 데스크톱에서 그림을 돌려 보는 길이
  생기면 §3번 자리를 다시 본다.
