# ADR-0133. Studio 메뉴 막대의 항목은 「프로세스」라 쓰고, Center와 주고받는 일은 「서버」 메뉴로 모으고, 「파일」을 하는 일로 나눈다

| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-11-06 |
| 관련 | [ADR-0121](0121-center-console-says-process.md)(Studio를 「바꾸지 않는 것」에 둔 줄 중 메뉴 막대 몫만 바꾼다), [ADR-0111](0111-bpm-process-and-pc-runner-names.md), `docs/02-glossary.md` §0, 화면 `studio/docs/screens.md` STU-01 |

## 배경

STU-01 「파일」 메뉴는 「새 BPM 프로세스...」·「BPM 프로세스 열기...」·「최근 BPM 프로세스」·「BPM 프로세스 닫기」·「BPM 프로세스 정보...」처럼 항목마다 「BPM」을 붙였다. 프로그램 이름이 BPM Studio라 메뉴를 펼친 사람에게는 같은 말의 되풀이다.

같은 메뉴에 파일로 쓰는 일(저장·내보내기)과 Center로 보내는 일(올리기 둘·「Center 공유 자원...」)이 섞여 있어, 사용자가 올리는 기능을 찾기 어렵다고 짚었다. 「파일」의 나머지 열세 줄도 구분선 하나로만 갈려 열기·닫기·저장이 한데 붙어 있었다.

ADR-0121은 「프로세스」 단독 표기를 Center 콘솔 화면 글에만 허락하고 Studio는 그대로 두었다 — Studio는 OS 프로세스(실행 프로세스)를 함께 보일 수 있어서다.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. 그대로 「BPM 프로세스」 | 문서·화면이 한 말이다 | 메뉴 항목마다 프로그램 이름을 되풀이한다 |
| B. **메뉴 막대의 항목만 「프로세스」** | 짧다. 메뉴 막대에는 OS 프로세스를 다루는 항목이 없어 모호하지 않다 | 메뉴와 그 메뉴가 여는 창의 제목(「BPM 프로세스 정보」 등)이 다르다 |
| C. Studio 화면 글 전체를 「프로세스」 | 한 말이다 | 실행 로그·오류 글에 실행 프로세스가 함께 나온다 — 거기서는 모호하다. 고칠 자리가 많다 |

Center 쪽: 「파일」에 두고 구분선만 긋기 / 새 「Center」 메뉴 / **새 「서버」 메뉴**. 메뉴 이름이 보내는 곳을 말하면 항목이 짧아진다(「Center로」를 항목마다 붙이지 않는다). 설계자에게는 「서버」가 더 바로 읽힌다 — Studio가 주고받는 서버는 Center 하나뿐이다.

내보내기 쪽: 메뉴 막대에 「내보내기」 따로 / **「파일」 안 「내보내기」 하위 메뉴**. 파일로 쓰는 일이라 저장 옆에 두되 한 줄로 접는다.

## 결정

**B**, 그리고 **「서버」 메뉴를 새로 두고 「파일」을 묶음으로 나눈다.**

1. **메뉴 막대의 항목 글**에서 「BPM 프로세스」를 「프로세스」로 쓴다 — 「새 프로세스...」·「프로세스 열기...」·「최근 프로세스」·「프로세스 닫기」·「프로세스 정보...」·「내보내기 ▸ 공유 프로세스...」. 그 항목을 가리키는 안내(「파일 → 프로세스 열기...」 같은 것 — 탐색기 빈 상태 글, 상태 줄)도 메뉴에 적힌 그대로 쓴다.
2. **「서버」 메뉴**(「실행」 다음)에 Center와 주고받는 일만 둔다 — 「프로세스 올리기...」·「공유 프로세스 올리기...」·「공유 자원...」(STU-11). 도구 모음에 올리기 단추는 두지 않는다.
3. **「파일」은 구분선으로 넷** — 열기(「새 프로세스...」·「프로세스 열기...」·「최근 프로세스」) / 프로세스 다루기(「프로세스 정보...」·「정의 추가...」·「이 정의를 진입으로 지정」) / 저장(「저장」·「다른 이름으로 저장...」·「내보내기 ▸」 「패키지...」·「공유 프로세스...」) / 닫기(「프로세스 닫기」·「종료」).
4. **「시험 케이스...」는 「실행」 메뉴로 옮긴다** — 시험 실행을 준비하는 일이다.
5. **설정(STU-10)의 분류도 「서버」다** — 「Center」 분류를 「서버」로, 그 칸을 「서버 주소」로 쓴다. 메뉴 막대와 설정이 같은 곳을 다른 이름으로 부르지 않는다. 그 분류를 가리키는 안내(「설정 → 「서버」에서 「연결 테스트」」)도 같다.
6. **도구 모음도 메뉴처럼 묶는다** — 파일(「새 프로세스」「프로세스 열기」「저장」) | 편집(「취소」「다시」) | 실행(「실행 전 검사」「실행...」) | 기타(「속성 패널 접기」).
7. **「서버」 메뉴가 여는 올리기 창의 제목도 「서버로」다** — 「서버로 올리기 — <이름> <버전>」(STU-12b)·「공유 BPM 프로세스 서버로 올리기」(STU-12). 메뉴에서 「서버」를 고르고 「Center」 창을 만나지 않는다.

바꾸지 않는 것:

- 위 7의 둘을 뺀 창·대화상자 제목과 그 안의 글(「BPM 프로세스 정보」·「Center 공유 자원」·STU-16 「Center에 연결」의 「Center 주소」 등), 탐색기 탭 이름, 문맥 메뉴, 알림·오류 글(「열린 BPM 프로세스가 없습니다」) — 메뉴 막대가 아니다.
- 문서의 설명 글, 코드 식별자, 코드 주석, PC 실행기.

## 결과

- 쉬워지는 것: 메뉴 항목이 짧아지고, 올리기를 「서버」 메뉴에서 한 번에 찾는다. 「파일」이 하는 일 순서(열고 → 다루고 → 저장하고 → 닫는다)로 읽힌다.
- 포기하는 것: 메뉴 항목과 그것이 여는 창의 제목이 다르다(「프로세스 정보...」 → 창 「BPM 프로세스 정보」, 「서버 › 공유 자원...」 → 창 「Center 공유 자원」). 탐색기 문맥 메뉴는 아직 「BPM 프로세스」다 — 화면 설계서 STU-01 표 위의 한 줄이 이것을 말한다.
- 다시 볼 조건: 메뉴 막대에 OS 프로세스(실행 프로세스)를 다루는 항목이 생기면 다시 본다. 문맥 메뉴·창 제목까지 맞추자는 요청이 오면 C를 다시 본다.
