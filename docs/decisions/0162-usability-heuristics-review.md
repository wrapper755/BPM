# ADR-0162. 콘솔을 사용성 휴리스틱 열 가지로 훑고 빈 곳을 메운다 — 읽는 중·오류 화면·돌아갈 길·고르는 칸·눌러 펴는 설명

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-11-20 |
| 관련 | `docs/06-screens.md` §2(U1~U17 — 여기에 U18~U20을 더한다), `docs/07-style-guide.md`, 화면 CON-00, [ADR-0160](0160-the-filter-runs-as-you-type.md)(거르기 — CON-02만 치는 대로), [ADR-0161](0161-soft-cards.md)(부드러운 카드 — 휴대폰에서 쓴다) |

## 배경

사용자가 Nielsen의 **사용성 휴리스틱 열 가지**로 콘솔을 검토해 반영하자고 했다.
U1~U17(`docs/06-screens.md` §2)이 이미 여럿을 덮고 있어(U3 이유를 그 자리에, U7 색만으로 말하지 않기, U9 되돌릴 수 없는 것은 묻기, U11 저장 안 한 변경, U12 빈 상태, U13 요약 먼저) **규칙이 없는 곳**과 **규칙은 있는데 화면이 어긴 곳**을 찾았다.
ADR-0161로 휴대폰에서 쓰게 되자 **말풍선(`title`)이 터치에서 뜨지 않는 것**이 U3 위반으로 드러났다.

| 휴리스틱 | 찾은 것 |
| --- | --- |
| H1 시스템 상태 보이기 | 화면을 여는 데 1~8초인데 그동안 아무 표시가 없다 (`loading.tsx`가 하나도 없다) |
| H2 실제 세계와 맞추기 | Center의 오류 원문(「그 실행 기록이 없다: run_…」)을 그대로 보인다 — 개발자의 말이고 높임이 다른 화면과 다르다 |
| H3 사용자 통제와 자유 | 로그인하면 늘 대시보드다 — 휴대폰으로 받은 결재 링크가 로그인 한 번에 사라진다. 없는 주소는 틀도 돌아갈 길도 없는 영문 404다 |
| H4 일관성 | 거르기 단추가 화면마다 「좁히기」·「보기」로 다르다 (CON-00 [F]는 「좁히기」다) |
| H5 오류 예방 | 큰 빈 곳 없음 — 되돌릴 수 없는 것은 확인 창이 있다(U9) |
| H6 기억보다 알아보기 | 실행기 id(`srv_…`)·BPM 프로세스 id·담당을 외워 쳐야 거를 수 있다 |
| H7 유연성과 효율 | 큰 빈 곳 없음 — 조건이 주소에 남아 즐겨찾기·공유가 된다 |
| H8 미니멀 디자인 | 휴대폰 카드에 「—」뿐인 줄이 대여섯이다 |
| H9 오류 알아보고 회복하기 | 화면이 예외로 죽으면 Next 기본 화면이다 — 다시 해 볼 길이 없다 |
| H10 도움말 | 설명·꺼진 까닭 서른다섯 곳이 말풍선에만 있다 — 휴대폰에서는 아예 보이지 않는다 |

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| 찾은 것 가운데 고른 것만 | 바뀌는 화면이 적다 | 말풍선 문제는 화면마다 남는다 |
| **찾은 것 전부** (사용자가 골랐다) | 휴대폰에서 빠지는 설명이 없다 | 화면 여럿을 함께 고친다 |

## 결정

**찾은 것을 전부 메운다.** 규칙은 U18~U20으로 `docs/06-screens.md` §2에 더한다.

1. **읽는 중을 보인다** (U18, H1) — 경로마다 `loading.tsx`가 틀과 같은 자리에 **뼈대**(회색 칸)를 그린다. 틀(위 막대)은 그대로 남는다.
2. **오류 화면도 콘솔 안이다** (H3·H9) — 없는 주소는 「찾을 수 없습니다」와 대시보드로 가는 길, 예외는 「화면을 그리지 못했습니다」와 「다시 시도」다. 둘 다 위 막대가 있다.
3. **Center 오류는 콘솔이 사람 말로 갈음한다** (H2) — 닿지 못함·401·403·404·5xx는 콘솔이 「무엇이 + 무엇을 하면 되는지」로 말하고 **원문은 「상세 보기」 안에** 둔다. 409·422처럼 **업무 사유가 담긴 답은 Center의 글 그대로**다(콘솔이 사유를 지어내지 않는다).
4. **로그인 뒤 가려던 곳으로 간다** (U19, H3) — 로그인이 필요한 화면은 `/login?next=<경로>`로 보내고 로그인하면 그리로 간다. **같은 사이트의 경로만** 받는다(`/`로 시작하고 `//`가 아닌 것 — 바깥으로 튀는 길을 열지 않는다). 없으면 대시보드다.
5. **거르기 단추는 「좁히기」 하나다** (H4) — CON-02만 치는 대로 돈다(ADR-0160).
6. **외워 칠 값은 고르게 한다** (H6) — 실행기는 등록된 것에서 **고르는 칸**, BPM 프로세스·담당은 **치면 후보가 뜨는 칸**(`datalist` — 모르는 값도 칠 수 있다).
7. **휴대폰 카드는 값이 없는 줄을 그리지 않는다** (H8) — 표에서는 열이 맞아야 하므로 「—」를 그대로 둔다.
8. **말풍선은 덧붙임뿐이다** (U20, H10 — U3를 넓힌다) — 꺼진 까닭·상태의 까닭·칸의 설명은 **화면 글**(단추·칸 아래 한 줄)이거나, 자리가 좁으면 **눌러 펴는 「?」**(`InfoTip` — 터치·키보드로 열린다)다. 말풍선에 남는 것은 **줄여 보인 id·해시의 전체**(U2)와 **아이콘 단추의 이름**(`aria-label`과 같은 말)뿐이다.

## 결과

- 쉬워지는 것: 휴대폰으로 받은 결재 링크가 로그인 뒤에도 그 결재다. 느린 화면도 눌렸다는 것을 안다. 휴대폰에서 꺼진 단추의 까닭이 보인다.
- 어려워지거나 포기하는 것: 화면 글이 조금 는다(꺼진 까닭 한 줄). 새 설명을 말풍선으로만 다는 것은 시험이 아니라 리뷰가 막는다 — 스타일 가이드 §7의 점검표에 넣는다.
- 다시 볼 조건: Center의 409·422 글이 사람에게 읽히지 않는다는 말이 나오면 사유 코드별 문구를 콘솔에 둔다(지금은 코드가 많고 Center 글이 이미 사유를 말한다).
