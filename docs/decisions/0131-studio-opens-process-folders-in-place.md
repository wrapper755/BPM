# ADR-0131. Studio는 BPM 프로세스 폴더를 제자리에서 연다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-11-05 |
| 관련 | `studio/docs/screens.md` STU-01·STU-02·STU-05·STU-10, `studio/app/workspace.py`, `studio/app/settings.py` |

## 배경

Studio는 BPM 프로세스를 **작업 폴더**(`<사용자 데이터>/studio/workspace/<그룹>/<id>/`) 한 곳에서만 찾았다. 그래서 「BPM 프로세스 열기...」로 바깥 폴더를 고르면 진입 정의 하나를 작업 폴더로 **복사**해 새 BPM 프로세스를 만들었고, 원본 폴더(업무 저장소의 체크아웃 등)에서 고친 것은 다시 「가져오기 → 바꾸기」를 해야 따라왔다. 케이스·DMN·호출 대상은 따라오지 않았다. 사람이 바라는 것은 그 폴더에서 바로 일하는 것이다. 이 모양을 정한 ADR은 없었다 — 탐색기와 설정이 BPM 프로세스를 id로만 기억해서 생긴 결과였다.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. 지금처럼 복사해 가져온다 | 코드가 그대로다 | 원본과 두 벌이 되고 진입 정의 외에는 따라오지 않는다 |
| B. 작업 폴더를 바꿔 쓰게 한다 (`BPM_STUDIO__DATA_DIR`) | 코드가 그대로다 | 폴더가 `<그룹>/<id>/` 모양이어야 하고, 한 번에 한 뿌리뿐이다 |
| C. 고른 폴더를 제자리에서 열고 경로를 기억한다 | 원본 하나, 케이스·DMN이 다 있다 | 설정이 경로를 들고, 같은 id 두 벌을 막아야 한다 |

## 결정

**C. `process.json`이 있는 폴더가 BPM 프로세스의 뿌리이고, Studio는 고른 폴더를 복사하지 않고 그 자리에서 연다.**

- **작업 폴더는 「새 BPM 프로세스」가 만들어지는 기본 자리**다(「새 BPM 프로세스...」·「다른 이름으로 저장...」·「PC BPM 프로세스로 나누기」). 기본값은 지금과 같고 STU-10 「일반」의 「기본 폴더」로 바꾼다(설정 `workspace_root`).
- **기본 폴더 밖에서 연 것은 경로로 기억한다** — 설정 `open_folders`(탐색기에 올라 있는 바깥 BPM 프로세스)와 `recent_processes`(파일 → 「최근 BPM 프로세스」, 최근 것부터 10개). 탐색기 목록 `open_processes`는 그대로 id다.
- **그룹은 뿌리의 상위 폴더 이름**이다 — 기본 폴더의 「기본」은 지금과 같고, 바깥 폴더도 같은 규칙이다. 이름이 같은 다른 폴더는 한 그룹에 모인다.
- **같은 id가 목록의 다른 폴더에 있으면 열지 않고 그렇게 말한다** — 패키지·Center·재생 명세·탐색기가 id로 가르기 때문이다.
- **바깥 파일을 복사해 들이는 길(STU-05 「가져올 파일」·「기존 것을 바꾸기」)은 없앤다.** 예제는 「새 BPM 프로세스...」의 「예제에서 가져오기」가 그대로 들인다.

## 결과

- 쉬워지는 것: 업무 저장소의 체크아웃을 바로 열어 고치고 커밋한다. 케이스·DMN·`libs/`가 그 폴더 그대로다. 「바꾸기」로 버전을 맞추던 일(#230)이 필요 없어진다.
- 어려워지는 것: 설정이 경로를 들므로 폴더를 옮기거나 지우면 최근 목록의 줄이 낡는다 — 누를 때 없으면 그렇게 말하고 목록에서 뺀다. 같은 id 두 벌을 함께 열 수 없다.
- 다시 볼 조건: 같은 id의 두 판(예: 브랜치 둘)을 나란히 봐야 하는 일이 잦아지면.
