# ADR-0174. 실행 상세는 요약 아래 탭 넷으로 나눈다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-11-20 |
| 관련 | CON-01 상세, [ADR-0136](0136-run-detail-shows-the-diagram.md)(다이어그램 — 도형을 누르면 타임라인 줄로 간다) |

## 배경

실행 상세(`/runs/<id>`)는 섹션 아홉이 한 줄로 쌓인다 — 요약·다이어그램·노드 타임라인·이어 돈 기록·외부 작업·AI 태스크 단계·사람 개입·로그·원본 이벤트.
다이어그램 하나가 화면 높이를 거의 차지해서, 로그나 결재를 보려면 한참 내려가야 했다. 사용자가 탭이나 메뉴로 나눠 달라고 했다.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. 요약은 위에 두고, 그 아래 탭 넷(흐름 / 기다림·외부 작업 / AI·사람 / 로그) | 짝이 되는 섹션이 한 탭에 남는다(도형 → 타임라인 줄). 탭이 적어 휴대폰에서도 한 줄이다 | 다른 탭의 섹션은 누르기 전까지 안 보인다 |
| B. 섹션마다 탭 하나 | 한 탭이 가장 짧다 | 탭이 여덟이라 휴대폰에서 밀린다. 도형을 눌러 가던 타임라인이 다른 탭이 된다 |
| C. 한 페이지 + 왼쪽 목차 | 다 이어서 읽을 수 있다 | 스크롤 길이는 그대로다 |

## 결정

**A로 한다** (사용자가 골랐다).

1. 「요약」은 늘 맨 위에 있다 — 상태·프로세스·시각은 어느 탭에서도 본다.
2. 그 아래 탭 넷이다.
   - **「흐름」**(기본): 다이어그램 + 노드 타임라인.
   - **「기다림·외부 작업」**: 이어 돈 기록 + 외부 작업. **둘 다 없으면 탭이 없다**(빈 섹션을 그리지 않는 것과 같은 결).
   - **「AI·사람」**: AI 태스크 단계 + 사람 개입.
   - **「로그」**: 로그 + 원본 이벤트(접힘).
3. 탭 이름 옆에 건수를 단다(흐름은 달지 않는다). 고른 탭은 주소 `?tab=`에 남는다 — 새로 고쳐도, 링크로 건네도 같은 탭이다. 탭은 링크라 **JS 없이도 돈다**. 모르는 값이나 없는 탭이면 「흐름」이다.

## 결과

- 쉬워지는 것: 처음 보이는 것이 요약과 흐름뿐이다. 로그는 한 번 누르면 맨 위에서 시작한다.
- 포기하는 것: 한 화면에서 모든 섹션을 이어 내려 읽을 수 없다.
- 다시 볼 조건: 사람들이 탭을 오가며 같은 노드를 찾는 일이 잦으면, 노드 하나를 고르면 탭마다 그 노드만 거르는 길을 본다.
