# ADR-0149. 콘솔 메뉴를 일의 흐름대로 묶는다 — 설계·배포·운영·업무·연결·관리

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-11-14 |
| 관련 | [ADR-0121](0121-center-console-says-process.md)(§결정 2 메뉴 묶음을 대체 — 「프로세스」라 쓴다는 결정은 그대로 산다), [ADR-0145](0145-console-is-workspace-shaped.md)(두 층 틀은 그대로, 묶음 목록만 바뀐다), [ADR-0143](0143-design-happens-in-the-console.md)(CON-03을 없애는 까닭), 화면 `server/docs/screens/center-console.md` |

## 배경

메뉴 묶음은 [ADR-0121](0121-center-console-says-process.md)이 「운영 현황」·「로그」로 가르고
[ADR-0145](0145-console-is-workspace-shaped.md)가 레일 여섯으로 세운 것이다. 그 뒤
**PC 실행기와 Qt Studio를 걷었고**([ADR-0144](0144-remove-the-pc-runner.md)·[ADR-0143](0143-design-happens-in-the-console.md))
설계가 콘솔 안으로 들어왔다. 그러고 보니 세 가지가 어긋난다.

1. **CON-03 「앱」에 볼 것이 없다.** 그 화면은 Studio 키 목록 하나였고(승인 하나가 키 하나다),
   설계가 콘솔로 들어온 뒤로는 발급하는 사람이 없다. 그 화면의 주석이 이미
   「설계가 콘솔로 들어오면 이 화면도 없어진다」고 적어 두었다.
2. **「프로세스」가 두 묶음에 같은 이름으로 있다** — 「운영 현황 › 프로세스」와 「로그 › 프로세스」.
   ADR-0121이 그것을 알고 **화면 제목으로** 가르게 했지만(「프로세스」·「프로세스 로그」),
   메뉴에서 고를 때는 똑같은 두 줄이라 어느 쪽인지 눌러 봐야 안다.
3. **「배포·자원」에 방향이 다른 둘이 섞여 있다** — 내보내는 것(공통 패키지·배포)과
   바깥을 들이는 것(연결 앱·일꾼)이다.

「앱」이라는 말도 이제 Studio·서버 실행기·연결 앱·일꾼 넷을 가리켜 어느 것인지 알 수 없다.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. CON-03만 지우고 나머지는 그대로 | 손이 가장 적다 | 「운영 현황」에 줄이 하나만 남아 묶음일 까닭이 없어진다. 겹치는 이름·섞인 묶음은 그대로 |
| B. **일의 흐름대로 여섯으로 다시 묶는다** — 설계 → 배포 → 운영 → 업무 → 연결 → 관리 | 묶음 이름이 **그 자리에서 하는 일**이다. 겹치는 이름이 없어지고 방향이 다른 둘이 갈린다. 레일 아이콘 수는 그대로 여섯 | 화면 열셋의 「메뉴」 줄과 지금 자리 줄이 모두 바뀐다 |
| C. 넷으로 줄인다 (설계 / 운영 / 배포·연결 / 관리) | 레일이 단순하다 | 「운영」에 **보는 일**(현황·기록)과 **답하는 일**(결재·작업 지시)이 섞인다 — 결재는 운영자가 아니라 결재자의 일이다 |

## 결정

**B.** 묶음 여섯을 **일의 흐름대로** 세운다. 레일의 차례도 이 차례다.

| 묶음 | 줄 | 화면 |
| --- | --- | --- |
| **설계** | 「작업공간」 | CON-20 |
| **배포** | 「배포」 / 「공통 패키지」 | CON-15 / CON-06 |
| **운영** | 「프로세스」 / 「실행 기록」 | CON-02 / CON-01 |
| **업무** | 「결재함」 / 「작업 지시」 | CON-04 / CON-05 |
| **연결** | 「연결 앱」 / 「일꾼」 | CON-18 / CON-17 |
| **관리** | 「조직」 / 「관리자 계정」 / 「변경 이력」 | CON-13 / CON-14 / CON-16 |

1. **CON-03 「앱」을 없앤다** (ADR-0143). 거기 있던 것 중 남는 것은 없다 —
   Studio 키 목록은 쓰는 앱이 없고, 「승인 대기」는 서버 실행기 쪽이 CON-02에 따로 있다.
   지나간 Studio 등록·키는 **「변경 이력」(CON-16)이 그대로 보인다** — 이력은 지우지 않는다.
2. **「로그」 묶음을 해체한다.** 실행 기록은 운영자가 현황과 **같은 자리에서** 보는 것이라
   「운영」으로 가고, 앱의 등록·키·배치 이력은 운영이 아니라 관리라서 「관리」로 간다.
   ADR-0121이 가른 「지금 모습 / 지나온 이력」은 **묶음이 아니라 두 줄의 이름**으로 남는다.
3. **화면 이름 둘을 고친다** — 「프로세스 로그」 → **「실행 기록」**, 「앱 로그」 → **「변경 이력」**.
   메뉴 줄과 화면 제목이 같아지고(ADR-0121이 변통으로 가르던 것이 없어진다),
   「앱」이라는 모호한 말이 메뉴에서 사라진다.
4. **「배포」가 묶음 이름이 된다** — 「자원」을 떼고, 바깥을 들이는 둘은 **「연결」**로 묶는다.
   「연결 앱」·「일꾼」은 이미 한 문서(`center-console-connections.md`)에 있던 짝이다.
5. **「조직」은 「관리」로 옮긴다** — 회사·부서·직원을 손보는 일은 업무를 처리하는 일이 아니다.
6. **설정에 적을 Center 주소 줄은 CON-17 「일꾼」으로 옮긴다** (CON-03에 있었다).
   지금 그 주소를 손으로 적어 넣는 사람은 **일꾼을 띄우는 사람뿐이다** — 서버 실행기는 Center와
   함께 배포되어 compose가 이미 적어 두었고, Studio는 없어졌다. 토큰 창이 「일꾼 설정의 Center
   토큰에 넣으세요」라고 말하면서 **주소는 어디에도 없던** 것도 이것으로 메워진다.

바꾸지 않는 것: 두 층 틀(레일 56 + 펼침 패널 224 + 위 막대 48, ADR-0145), 지금 자리 줄의
모양(`<묶음> › <자리>`), 첫 화면을 역할이 가르는 것, 화면 글이 「프로세스」라 쓰는 것(ADR-0121).

## 결과

- 쉬워지는 것: 묶음 이름이 **하려는 일**이라 처음 보는 사람도 어디를 누를지 안다.
  같은 이름의 두 줄이 없어지고, 메뉴에서 「앱」이라는 모호한 말이 사라진다.
  빈 화면 하나(CON-03)와 그 화면만 쓰던 코드가 없어진다.
- 포기하는 것: 화면 열셋의 「메뉴」 줄과 문서의 지금 자리 표기가 모두 바뀐다.
  익숙해진 운영자는 「로그」를 찾다 한 번은 헤맨다.
  「관리」에 줄이 셋이 되어 성격이 조금 넓다(조직·계정·이력).
- 다시 볼 조건: 「관리」가 넷을 넘으면 가른다. 설계 쪽에 작업공간 말고 줄이 생기면
  (리소스 탐색기 — `docs/09-gaps.md` §3-34) 그때 「설계」 묶음을 다시 본다.
