# ADR-0155. 리소스는 탐색기의 둘째 탭이다 — 끌어다 놓기와 「캔버스에 추가」가 같은 명령을 부른다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-11-15 |
| 관련 | 화면 CON-20b, 계약 C7·C5·C1 `provides.processes`, [ADR-0143](0143-design-happens-in-the-console.md)(저작이 콘솔에서), [ADR-0044](0044-canvas-drag-and-drop.md)(데스크톱의 끌어다 놓기), [ADR-0045](0045-contributed-resource-children.md)(기여 뿌리의 둘째 단계), [ADR-0051](0051-shared-process-conveniences.md)(설치 여부는 줄에 덧붙인다), [ADR-0114](0114-remove-ui-automation.md)(깔린 확장이 없다), `docs/09-gaps.md` §3-34 |

## 배경

M11이 웹 편집기를 다 옮기고 **하나만 남겼다** — 옛 STU-03 리소스 탐색기의 「캔버스에 추가」다
(§3-34). 지금은 부를 것이 있어도 **팔레트에서 빈 태스크를 만들고 앱 이름·작업 이름을 손으로
적어 넣어야** 한다. 틀린 이름은 그림을 저장할 때가 아니라 **실행 전 검사(B14)에서야** 드러난다.

데스크톱에서 하던 일은 그대로 남아 있다 — 캔버스의 `createTask(spec)`가 **자리까지 받아** 만들고
(`at`), 만드는 재료도 Center에 다 있다(C5 `?kind=process_lib`의 `provides.processes`, C7
`?type=service_app`의 `operations`). **없는 것은 그것을 고르는 화면뿐이다.**

먼저 정할 것은 **그 목록을 어디에 두느냐**였다. 작업공간은 이미 왼쪽 탐색기·캔버스·오른쪽 상세
패널·아래 탭으로 꽉 차 있어서, 넷째 패널을 더하면 캔버스가 좁아진다 — 레일을 걷은 지
얼마 되지 않았다([ADR-0152](0152-console-chrome-is-one-top-bar.md)).

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| **A. 왼쪽 탐색기가 탭 둘** (「파일」·「리소스」) | 패널이 늘지 않는다. **왼쪽 → 캔버스**가 끌어다 놓기의 방향이다. 접는 길도 그대로다 | 파일과 리소스가 **다른 것**인데 한 패널을 쓴다 |
| B. 오른쪽 상세 패널에 탭 | 왼쪽이 파일 전용으로 남는다 | 고른 요소의 속성과 자리를 다툰다. 끌어오는 방향이 **오른쪽 → 왼쪽**이다 |
| C. 캔버스 팔레트에 묶음을 더한다 | 만드는 몸짓이 다른 노드와 똑같다 | 팔레트가 좁고 아이콘 중심이라 **이름이 긴 목록·찾기**를 담지 못한다 |
| D. 찾기 창 하나 (`Ctrl+K`) | 상시 자리가 0이다 | **무엇이 있나**를 훑어볼 길이 없다 |

## 결정

**A** — 왼쪽 탐색기가 「파일」·「리소스」 **두 탭**이 된다. 그리고 **끌어다 놓기와 줄의
「캔버스에 추가」를 둘 다** 둔다.

- **두 몸짓이 같은 캔버스 명령 하나**(`CanvasEditor.createTask`)를 부른다 — 다른 것은 자리뿐이다
  (끈 자리 / 보이는 곳의 빈 자리). 그래서 **실행 취소가 한 걸음**이다 (ADR-0044가 데스크톱에서
  정해 둔 결). 터치·좁은 화면에는 메뉴 쪽이 남는다.
- **뿌리는 둘이다** — 「공유 프로세스」(C5 `process_lib`)와 「서비스 앱」(C7). **확장이 기여한
  자원의 뿌리는 두지 않는다**: 지금 깔린 확장이 **하나도 없어**(ADR-0114) 그릴 것도 시험할 것도
  없다. 확장을 다시 들일 때 같은 틀에 셋째 뿌리로 붙는다.
- **둘째 단계는 그대로 둔다** — 패키지 → 그 안의 정의, 앱 → 그 안의 작업. ADR-0045가 없앤 것은
  **확장 기여 뿌리**의 둘째 단계이고(플랫폼이 `data`를 해석하지 않아서다), 이 둘은
  **플랫폼이 아는 것**이라 그 결정 밖이다.
- **만드는 것은 부를 대상까지다.**
  - 공유 프로세스의 정의 → `bpmn:CallActivity` + `calledElement`(C1 `provides.processes[].process_id`)
  - 서비스 앱의 작업 → `bpmn:ServiceTask` + `bpm:serviceCall{app_id, operation}`
  - **입력·출력 짝은 짓지 않는다** — 내 변수 이름을 알아야 하는 일이라 지어내지 않는다
    (STU-03의 규칙 그대로). 만든 뒤 오른쪽 상세 패널에서 잇는다.
- **설치되지 않은 공유 프로세스의 줄은 끈다** — 멤버십은 Center 목록 그대로이고 **설치 여부만
  줄에 덧붙인다**(ADR-0051). 끈 줄은 까닭을 말풍선에 적고 「정보」 탭의 설치로 보낸다 —
  설치되지 않은 호출은 **B14가 막아** 「왜 안 되나」가 된다.
- **찾기 칸 하나**로 거른다(이름·id). 패널이 256px이라 뿌리를 둘 다 펼치면 길다.
- **만들 것이 없는 줄은 끌리지 않는다** — 묶음 머리(패키지·앱 이름)와 꺼진 줄이 그렇다.
- 보기 전용 계정에게는 **탭이 보이고 만드는 길만 없다** — 무엇을 부를 수 있는지 보는 것은 읽기다.

## 결과

- 이 결정으로 쉬워지는 것: 부를 것을 **이름을 외우지 않고** 고른다. 틀린 `app_id`·`calledElement`가
  B14까지 가지 않는다. 캔버스 폭이 그대로다.
- 어려워지거나 포기하는 것: 왼쪽 패널 하나를 **파일과 리소스가 나눠 쓴다** — 파일을 보며
  리소스를 끌 수 없다(탭을 옮겨야 한다). 확장이 기여한 자원은 **아직 고를 수 없다**.
- 다시 볼 조건: 확장을 다시 들일 때(셋째 뿌리와 `creates_task_field`), 그리고 목록이 길어져
  찾기 한 칸으로 모자랄 때(그때는 D의 찾기 창이 **이 탭 위에** 얹힌다 — 자리를 바꾸는 일이 아니다).
