# ADR-0186. 줄이 하나인 묶음은 이름이 하나다 — 「프로젝트」·「라이브러리」, CON-02 주소는 `/processes`

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-11-21 |
| 관련 | CON-00 [A]·[M]·[H], CON-02·CON-06·CON-20, [ADR-0149](0149-console-menu-follows-the-work.md)(줄 이름 = 화면 제목 — 그대로), [ADR-0151](0151-console-follows-the-lifecycle.md)(생애주기 차례 — 그대로), [ADR-0181](0181-menu-puts-approvals-on-top-and-approval-in-deploy.md) §4(묶음과 줄 이름이 다른 것을 받아들인 것을 **대체한다**) |

## 배경

콘솔을 제품 수준으로 다시 보며(2026-11-21) 메뉴와 화면 이름을 맞춰 보았다.

- **줄이 하나인 묶음은 펼치지 않고 바로 간다**(CON-00 [M]). 그래서 위 막대의 「저작」을 누르면 「프로젝트」가, 「라이브러리」를 누르면 「공통 패키지」가 열린다. 누른 말과 열린 화면의 제목이 다르다. ADR-0181 §4는 이것을 「묶음과 줄의 관계일 뿐」이라 했지만, 펼치지 않는 묶음에서는 줄이 보이지 않으니 사람은 그 관계를 볼 길이 없다.
- 지금 자리 줄도 「저작 › 프로젝트」·「라이브러리 › 공통 패키지」로 두 말이 선다. 빈 상태 안내가 「「저작 › 프로젝트」에서…」처럼 그 두 말을 다 적는다.
- CON-02 「프로세스 현황」의 주소가 아직 `/bots`다. PC 실행기(Bot) 시절의 이름이고, 화면 어디에도 그 말이 없다.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. 그대로 둔다 (ADR-0181 §4) | 손이 가지 않는다 | 누른 말과 열린 제목이 다르다 |
| B. 메뉴가 화면을 따른다 — 「프로젝트」·「공통 패키지」 | 제목은 그대로 | 생애주기 낱말이 메뉴에서 빠지고, 「공통 패키지」는 위 막대 묶음 중 가장 길다 |
| C. 화면이 메뉴를 따른다 — 「저작」·「라이브러리」 | 생애주기 낱말이 남는다 | 「저작」은 일의 이름이지 목록의 이름이 아니다 — 프로젝트 목록의 제목으로는 어색하다 |
| D. **섞는다** — 저작 쪽은 「프로젝트」, 서가 쪽은 「라이브러리」 | 각 자리에서 **사람이 찾는 말**이 이긴다. 프로젝트를 찾는 사람은 「프로젝트」를 누르고, 서가는 사용자가 이미 「라이브러리」로 골랐다(ADR-0181 §4) | 위 막대에서 「저작」이라는 낱말이 사라진다 |

## 결정

**D로 한다. 줄이 하나인 묶음은 묶음 이름 = 줄 이름 = 화면 제목이다.**

1. 위 막대의 묶음 「저작」은 **「프로젝트」**다. 줄도 「프로젝트」, 화면 제목도 「프로젝트」(CON-20a). 「저작」은 용어(일 전체를 가리키는 말)로 남는다 — 용어집·화면 문서·편집기의 「저작」 탭은 그대로다.
2. CON-06의 화면 제목은 **「라이브러리」**다. 묶음·줄도 「라이브러리」. 제목 아래 설명이 「지어 올린 공통 패키지」라고 말한다 — 「공통 패키지」는 **그 안에 놓인 것의 종류 이름**으로 남는다(프로젝트의 「공통 패키지」 칸, 승인 대기의 「종류」 열 그대로).
3. 그래서 「대시보드」·「결재함」·「프로젝트」·「라이브러리」 넷은 지금 자리 줄을 그리지 않는다(같은 말이 둘 서지 않는다 — CON-00 [H]의 규칙 그대로). 상세 화면에서는 「프로젝트 › <이름>」·「라이브러리 › <id>」다. 빈 상태 안내도 한 말로 적는다(「「프로젝트」에서…」).
4. CON-02의 주소는 **`/processes`**다(상세 `/processes/<id>/<판>`). **옛 주소 `/bots`·`/bots/…`는 새 주소로 넘긴다**(영구 넘김 — 책갈피와 다른 화면에 남은 링크가 깨지지 않는다). `/workspaces`·`/packages`는 그대로 둔다 — 화면 이름과 어긋나지 않거나(공통 패키지 주소), 작업공간 하나하나가 그 아래 살아서(편집기) 옮기는 값보다 깨지는 링크가 크다.

## 결과

- 쉬워지는 것: 누른 말이 곧 열린 화면의 제목이다. 지금 자리 줄과 안내 글이 한 말로 짧아진다. 주소에 옛 제품 이름이 남지 않는다.
- 포기하는 것: 위 막대만 보고는 「저작 → 배포 → 운영」의 첫 낱말이 보이지 않는다(「프로젝트」가 그 자리다). `/workspaces`는 화면 이름(프로젝트)과 다른 주소로 남는다.
- 다시 볼 조건: 「프로젝트」나 「라이브러리」 묶음에 줄이 둘 이상 생기면 묶음 이름을 다시 정한다.
