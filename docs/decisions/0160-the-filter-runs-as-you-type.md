# ADR-0160. 거르기는 치는 대로 돈다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-11-17 |
| 관련 | [ADR-0159](0159-con-02-is-a-table-like-the-others.md)(CON-02 표), `server/docs/screens/center-console.md` CON-02 |

## 배경

CON-02의 거르기는 **GET 폼**이었다 — 이름을 치고 「상태」·「정렬」을 고른 뒤 **「좁히기」를 눌러야**
들었다. JS 없이 돌고 주소에 남는 것이 장점이었지만, 쓰는 사람에게는 **고르고도 한 번 더 눌러야 하는**
화면이다. 콤보를 바꾸고 단추를 안 누르면 **표는 옛 조건 그대로**인데 폼은 새 값을 보이고 있어, 화면이
거짓말을 하는 순간이 있다.

그리고 거르기는 **서버에 묻는 일이 아니다.** CON-02의 서버 쪽은 거르기와 상관없이 늘 같은 것을
읽는다 — 패키지 전부, 그리고 **BPM 프로세스마다 실행 요약 질의 하나**(지금 스무 개 남짓). 추리는 일은
이미 화면을 모르는 `lib/summary.ts`(`filterGroups`)에 있다.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A 글쇠마다 서버로 (`router.replace`) | 지금 구조 그대로 | 글자를 칠 때마다 Center에 질의 스무 개가 다시 간다. 디바운스를 걸어도 쉴 때마다 한 벌 |
| B 브라우저에서 추리고 주소만 맞춘다 | 즉시 듣는다. Center에 아무것도 더 묻지 않는다 | 거르기가 브라우저 쪽 구성요소가 된다 |
| C 그대로 둔다 | 고칠 것이 없다 | 「좁히기」를 눌러야 하고, 안 누르면 폼과 표가 어긋난다 |

## 결정

**B — 거르기를 브라우저에서 돌리고 「좁히기」를 걷는다.**

- 서버는 **줄을 다 보낸다**(거르지 않는다). 표(`app/bots/table.tsx`)가 `filterGroups`·`sortGroups`·
  `flattenGroups`를 **그 자리에서** 돌린다. 추리는 코드는 그대로다 — 자리만 옮겼다.
- 주소는 **`window.history.replaceState`**로 맞춘다. Next가 그것을 라우터·`useSearchParams`와 묶어
  주고 **페이지를 다시 그리지 않는다**. 주소에 남으니 그대로 복사해 건네도 같은 화면이 열린다.
- **친 글자는 200ms 뒤에** 주소에 남긴다. 글쇠마다 남기면 뒤로 가기가 한 글자씩 되돌아간다.
  표는 **기다리지 않고** 바로 추린다 — 늦추는 것은 주소뿐이다.
- 「좁히기」를 없앤다. 「초기화」는 남되 **그 자리에서 비우는 단추**가 된다(주소도 `/bots`를 가리켜
  JS가 없으면 그냥 그리로 간다).
- **JS가 없어도 돈다.** 폼은 `method="get"` 그대로라 Enter면 `?q=…`로 간다. 서버는 그 값을 표에
  **첫 값으로** 건네고, 표는 서버에서 그려질 때도 같은 함수로 추린다.

**이 결정은 CON-02에만 적용한다.** 다른 목록(CON-01 실행 기록·CON-15 배포 …)은 거르기가 **서버에
묻는 일**이다 — 줄이 수천이라 다 보낼 수 없다. 그 화면들의 「좁히기」는 그대로 둔다.

## 결과

- 이 결정으로 쉬워지는 것: 고르면 바로 듣는다. 폼과 표가 어긋나는 순간이 없다. 글자를 쳐도 Center에
  아무것도 더 묻지 않는다.
- 어려워지거나 포기하는 것: 거르기가 브라우저 쪽 구성요소라 `app/packages/page.tsx`에 있던
  `STATUS_LABEL`·`packageHref`를 `lib/packages.ts`로 옮겼다(페이지는 `server-only`를 끌고 온다).
- 다시 볼 조건: **BPM 프로세스가 수백이 되어** 줄을 다 보내는 것이 무거워지면 A로 돌아간다 —
  그때는 Center에 거르는 질의를 더하고 실행 요약도 한 번에 받아야 한다.
