# ADR-0141. HTTP 어댑터 정의는 Center가 원본이고 콘솔(CON-18)에서 고친다 — 업무 처리기가 코드로 맡는 앱의 정의는 지금처럼 일꾼이 올린다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 (2026-11-09) |
| 날짜 | 2026-11-09 |
| 관련 | 계약 C13(외부 확장 등록·E1~E6)·C15(§외부 확장 정의 올리기·어댑터 일꾼)·C1·C2(`extension` 봉투), 화면 CON-18, [ADR-0060](0060-pinning-external-definitions.md)(정의 고정), [ADR-0090](0090-center-admin-accounts.md)(Center 대리 서명), [ADR-0102](0102-calling-outside-is-pull.md), [ADR-0122](0122-consumer-folder.md), [ADR-0135](0135-agentic-automation-and-unified-consumer.md), [ADR-0138](0138-console-app-catalog.md), [ADR-0140](0140-unified-consumer-runs-in-the-server-compose.md) |

## 배경

외부 확장 정의(C13 `tier: external`)는 **그것을 수행하는 일꾼이 파일로 들고 있다가** 뜰 때 올리고, Center는 검사·서명해 보관만 한다(ADR-0122). 주소도 일꾼 설정이 정한다(ADR-0102, ADR-0138 「가」). CON-18 「연결 앱」은 보기만 한다 — ADR-0138은 「콘솔에서 정의 고치기」(선택지 C)와 「콘솔에서 주소 바꾸기」(나)를 원본이 둘이 된다는 까닭으로 고르지 않았다.

사용자는 **외부 서비스와 주고받는 변환을 콘솔에서 고칠 수 있기를** 원한다(2026-11-09). 그런데 콘솔에 보이는 외부 앱은 두 가지다.

| | 순수 HTTP 어댑터 앱 | 업무 처리기 앱 |
| --- | --- | --- |
| 동작을 정하는 것 | **정의 데이터** — 주소, 요청 템플릿, 제한 JSONPath, `error_when`(C13 §4) | **처리기 코드**(통합 일꾼에 실린 회사 패키지) |
| 정의의 `adapter` 칸 | 그대로 쓰인다 | 계약이 요구해 자리만 채운다 |
| 콘솔에서 고치면 | 동작이 바뀐다 | 이름·설명·묶음만 바뀌고 동작은 그대로다. 처리기 코드와 작업 목록이 어긋날 수 있다 |

콘솔 편집이 값을 하는 쪽은 앞의 것뿐이다.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. 지금대로 — 파일을 고치고 일꾼을 다시 띄운다 | 바꿀 것이 없다 | 바깥 서비스 하나를 붙이거나 고치는 데 일꾼 서버의 파일·재시작이 필요하다 |
| B. **어댑터 앱의 정의는 Center가 원본** — 콘솔에서 만들고 고치면 Center가 검사·서명하고, 일꾼은 Center에서 받는다. 처리기 앱의 정의는 지금처럼 일꾼이 올리고 콘솔은 보기만 한다 | 코드 없이 콘솔에서 바깥 연결이 끝난다. 받는 쪽이 Center에서 가져가는 결(ADR-0102 Pull)과 같다. 정의마다 원본이 하나다 | 원본이 앱마다 다르다(콘솔 / 일꾼). C13·C15에 길이 하나씩 는다 |
| C. 모든 외부 정의를 Center가 원본으로 | 규칙이 하나다 | 처리기 앱의 작업 목록은 코드와 같이 바뀌어야 한다 — 콘솔에서 고치면 코드와 어긋난다 |
| D. 일꾼이 올리고 콘솔이 덮어쓴다 | 지금 길을 그대로 둔다 | 원본이 둘이다. 일꾼이 다시 뜨면 콘솔에서 고친 것이 지워지거나 판이 부딪힌다 |

## 결정

**B** (사용자 결정, 2026-11-09). 화면 구성은 화면 문서(`server/docs/screens/`)로 먼저 보이고 정한다.

1. **정의마다 원본은 하나다** — `console` 또는 `consumer`. 콘솔에서 만든 외부 앱은 `console`, 일꾼이 `PUT /consumers/self/extension`으로 올린 것은 `consumer`다. 같은 id를 다른 쪽이 올리면 409로 거절한다. 원본이 `consumer`인 앱은 지금처럼 보기만 한다.
2. **콘솔에서 고치는 것은 새 판이다.** Center 관리자가 CON-18에서 만들기·고치기를 하면 Center가 판을 올리고(고친 것은 끝자리를 하나 올린다, 관리자가 다른 판을 적을 수 있다) E1~E4를 검사해 C2 `extension` 봉투에 서명한다(ADR-0090과 같은 대리 서명). 옛 판은 철회하지 않는다.
3. **정의를 고정한 BPM 프로세스는 새 판을 쓰지 않는다**(C1 `definition_hash`, ADR-0060). 다시 승인·배포해야 새 판으로 돈다. 콘솔은 고치기 전에 「이 판을 고정한 배포」를 보여 준다. 고정하지 않은 BPM 프로세스는 지금 규칙대로 범위 안의 판을 받는다.
4. **일꾼은 원본이 `console`인 정의를 Center에서 받는다** — 새 C15 길(맡은 토픽의 정의 목록과 판). 어댑터 일꾼·통합 일꾼(`api`)은 판이 바뀌면 다음 가져가기 전에 다시 받고 봉투를 다시 검증한다(E6 그대로). 파일(`BPM_ADAPTER__DEFINITIONS`·`BPM_CONSUMER__DEFINITIONS`)에 같은 id가 있으면 Center 것이 이기고 일꾼이 경고를 남긴다.
5. **주소는 정의와 함께 콘솔에서 고친다**(`base_url`·`test_base_url`). 일꾼 설정(`…__EXT__<확장>__BASE_URL`)이 있으면 그것이 이긴다 — 지금처럼 CON-18 「쓰는 주소」가 실제로 쓰는 주소를 보인다. **키는 콘솔에 두지 않는다** — 비밀은 일꾼 설정·OS 비밀 저장소에만 둔다(CLAUDE.md §5).
6. **처리기 앱의 화면 글**(이름·설명·묶음)은 처리기 패키지의 정의 파일이 원본이다. 콘솔에서 고치지 않는다.
7. **계약을 먼저 고친다** — C13(관리자 등록·고치기 길, 원본 칸), C15(일꾼이 정의를 받는 길, 파일과 겹칠 때), 화면 CON-18. 이 ADR은 ADR-0138의 「쓰기는 두지 않는다」와 ADR-0122의 「외부 확장 정의는 일꾼이 올린다」(C15 「어댑터 일꾼은 정의를 Center에서 받지 않는다」)를 **어댑터 앱 몫만** 대체한다.

## 결과

- 이 결정으로 쉬워지는 것: 바깥 서비스를 붙이거나 요청·응답 변환을 고치는 일이 콘솔에서 끝난다. 일꾼 서버의 파일과 재시작이 필요 없다. 고친 이력이 판으로 남는다.
- 어려워지거나 포기하는 것: 앱마다 원본이 달라 화면이 그것을 분명히 말해야 한다. 정의를 고정한 BPM 프로세스는 콘솔에서 고쳐도 바로 바뀌지 않는다(다시 배포). 콘솔에서 잘못 고친 변환은 바로 일감 실패로 이어진다 — 고치기 전에 시험할 길(시험 주소·`origin: test` 일감)을 화면에 둬야 한다.
- 다시 볼 조건: 처리기 앱도 콘솔에서 고칠 칸(예: 작업 끄기)이 필요할 때, 정의 편집 권한을 앱마다 나눠야 할 때.
