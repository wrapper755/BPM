# ADR-0188. 결재 폼 칸에 조건(`when`)을 둔다 — 앞의 칸 하나의 값이 목록 안일 때만 보이고 필수다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-11-21 |
| 관련 | 계약 C6 `FormField`·C14 `bpm:approval.fields`·B12, CON-04 상세, [ADR-0148](0148-dmn-grid-lives-in-center.md)(브라우저에 둘째 문법을 들이지 않는다), [ADR-0025](0025-expression-language.md)(`bpm-expr`) |

## 배경

결재 그림에 「결정: 승인 / 보완 요청」 다음 「보완 대상(보완 요청일 때)」 같은 칸이 생겼다. 조건이 **칸 이름 글자에만** 있어 결재 화면(CON-04)은 그 칸을 늘 보이고, 「보완 요청인데 보완 대상이 비었다」를 막지 못한다 — 필수로 두면 승인할 때도 채워야 하고, 선택으로 두면 보완 요청에서 빠져도 지나간다. 결재 폼의 모양은 C6이 정하고 Center와 실행하는 쪽이 같은 `validate_answer`로 판정하므로, 규칙은 계약에 있어야 한다.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. **`when: {field, in: [값…]}`** — 앞의 칸 하나, 값 목록 | C14가 가리키는 칸의 있음·차례·값이 선택지 안인지를 다 본다. 브라우저는 값 비교만 한다 | 「A이고 B일 때」는 못 적는다 |
| B. `when: "<bpm-expr 식>"` | 여러 칸·비교를 섞는다 | 브라우저가 식을 풀어야 해 문법이 두 벌이 된다(ADR-0148과 같은 문제). 값이 선택지 안인지 검사가 못 본다 |
| C. `when: {field, equals: 값}` | 가장 좁다 | 「반려 또는 보완일 때」는 칸을 둘로 나눠야 한다 |

사용자가 A를 골랐다.

## 결정

**결재 폼 칸에 선택 칸 `when: {field, in}`을 둔다.** `field`는 같은 폼의 **앞에 오는** `choice` 또는 `bool` 칸의 `key`이고, `in`은 그 칸의 값 목록(비지 않음, `choice`면 `choices` 안, `bool`이면 `true`·`false`)이다.

- **조건이 맞는 칸만 있다.** 맞을 때만 보이고 `required`가 뜻을 가진다. 맞지 않으면 필수로 보지 않고 타입도 보지 않는다.
- **맞지 않는 칸에 온 값은 버린다** (거부하지 않는다) — JS 없이 모든 칸이 보이는 폼이나 결정을 바꾼 사람이 걸리지 않고, 「승인」 뒤에 보완 대상이 남아 엉뚱한 갈래를 타는 일이 없다. 버린 칸도 **변수는 된다**(`None`, C6 「폼의 칸은 모두 변수가 된다」).
- **조건은 이어진다** — 가리키는 칸도 조건이 맞지 않으면 이 칸도 맞지 않는다. 앞에 오는 칸만 가리키므로 고리가 생기지 않는다.
- **판정은 한 자리다** — `contracts.approvals.field_applies`. `apply_defaults`가 기본값을 채운 **뒤** 맞지 않는 칸을 지우고, `validate_answer`가 맞지 않는 칸을 건너뛴다. Center·실행하는 쪽·시험 실행이 같은 두 함수를 쓴다.
- **값 비교는 엄격하다** — `bool`과 수를 섞지 않는다(`True`는 `1`이 아니다).
- **C14 B12가 오류로 막는다** — 가리키는 칸이 없음·뒤에 옴·자기 자신·`choice`/`bool`이 아님, `in`이 빔·선택지 밖의 값.
- **CON-04는 조건이 맞을 때만 보인다** — 작은 클라이언트 조각이 폼의 값을 보고 숨긴다. JS가 없으면 모든 칸이 보이고, 보내진 값은 Center가 판정한다(맞지 않는 칸은 버린다). 화면 쪽 비교는 보이기 위한 것이고 판정이 아니다.
- **편집기(CON-20)는 따로 자리를 만들지 않는다** — 결재 칸은 지금 JSON 칸으로 적으므로 `when`도 거기 적는다. 칸 편집이 표 모양이 되면 그때 조건 칸을 더한다.

## 결과

- 이 결정으로 쉬워지는 것: 「보완 요청일 때만 필수」가 그림에 적히고 Center가 지킨다. 칸 이름에서 「(…일 때)」를 뺄 수 있다.
- 어려워지거나 포기하는 것: 여러 칸에 걸친 조건(「반려이고 금액이 1억 넘을 때」)은 적지 못한다 — 칸을 나누거나 두 번째 결재로 한다. 숨은 칸에 적은 값이 말없이 사라진다(화면은 숨겨 보이므로 사람이 놀랄 일은 적다).
- 다시 볼 조건: 여러 칸 조건이 실제 그림에서 둘 이상 필요해지면 B(식)를 다시 본다 — 그때는 식을 Center가 풀어 화면에 「보일 칸」을 내려 주는 길을 먼저 본다.
