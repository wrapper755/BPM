# ADR-0168. 목록 머리의 「새 …」 단추는 칠하지 않는다 — 옅은 `primary` 면

| 항목 | 값 |
| --- | --- |
| 상태 | 일부 대체됨([ADR-0170](0170-menu-notes-become-tooltips.md) — `tonal` 면의 짙기) |
| 날짜 | 2026-11-20 |
| 관련 | 화면 CON-00 [H]·CON-14·CON-15·CON-17·CON-18·CON-20, [ADR-0164](0164-neutral-pro.md)(남보라 하나·「⋯」), [ADR-0157](0157-status-colours-stay-under-the-brand.md)(가장 진한 색은 주 단추 하나) |

## 배경

배포(CON-15)를 보고 사용자가 「바탕에 비해 단추 색이 너무 강하다」고 했다. 줄마다 서던 빨간 「철회...」는 「⋯」로 들어갔는데도(ADR-0164) 남은 「새 배포...」가 옅은 회색 바탕과 흰 표 위에서 **화면에서 가장 큰 덩어리**였다.

ADR-0157·0164는 「화면에서 가장 진한 색은 주 단추 하나」라고 했다. 그런데 목록 화면의 「새 …」는 **할 일의 끝**(저장·배포·답하기)이 아니라 **창이나 폼을 여는 입구**다. 목록 화면에서 사람이 먼저 하는 일은 읽기이고, 입구가 표보다 크게 소리치면 읽기를 방해한다.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| `primary` 색을 전체로 옅게 한다 | 한 곳만 고친다 | 폼의 「배포」·「저장」도 흐려진다. 대비(흰 글자 4.5:1)를 다시 맞춰야 한다 |
| 「새 …」를 `secondary`(흰 면 + 테두리)로 | 조용하다 | 「철회된 것도 보기」 같은 다른 동작과 무게가 같아 입구가 안 보인다 |
| **옅은 `primary` 면(`primary.subtle` + `primary` 글자)인 `tonal`을 더해 목록 머리의 「새 …」에 쓴다** | 입구라는 것은 색으로 남고 칠한 면이 없다 | 단추 종류가 하나 는다 |

## 결정

1. `Button`에 **`tonal`**을 더한다 — 바탕 `primary.subtle`, 글자 `primary`, 테두리 없음, 누르면 조금 짙게(`primary.subtle` 위에 `primary` 8%).
2. **목록 화면 머리의 「새 …」(창·폼을 여는 입구)는 `tonal`이다** — 「새 배포...」·「새 계정...」·「새 일꾼...」·「새 연결 앱...」·「새 작업공간...」.
3. **칠한 `primary`는 할 일을 끝내는 단추에만** 남는다 — 폼·창 안의 「배포」·「만들기」·「저장」·「답하기」, 로그인. 「영역마다 하나」는 그대로다.

## 결과

- 목록 화면에는 칠한 면이 없다 — 가장 진한 것은 상태 점과 글자다.
- 새 목록 화면을 만들 때 「새 …」에 `primary`를 쓰지 않는다(스타일 가이드 §3 Button 줄).
