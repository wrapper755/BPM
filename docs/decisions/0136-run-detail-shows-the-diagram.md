# ADR-0136. 실행 상세(CON-01)에 BPM 다이어그램을 Studio와 같은 bpmn-js 뷰어로 그리고 노드 상태를 색으로 얹는다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 (2026-11-08) |
| 날짜 | 2026-11-08 |
| 관련 | 계약 C5(`GET …/diagram`·`…/nodes`), C3(노드 이벤트), ADR-0022(Studio 캔버스)·ADR-0029(bpmn-js 판 고정), `server/docs/screens/center-console.md` CON-01 |

## 배경

CON-01 실행 상세는 노드를 타임라인 막대와 표로만 보인다. 노드가 서른 개를 넘으면 「지금 흐름의 어디쯤인가」·「어느 갈래로 갔나」를 막대 순서로 읽기 어렵다 — 사용자가 「다이어그램이 같이 보이면 모니터링이 쉽겠다」고 했다. 그림의 재료(BPMNDI 좌표)는 이미 올라온 패키지의 `.bpmn`에 있고(SC01: 도형 66·연결선 70), 실행 기록(C3)은 노드 id로 상태를 준다. 콘솔에는 정의 파일을 읽을 길이 없었다.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. bpmn-js 뷰어(NavigatedViewer)를 콘솔 클라이언트 컴포넌트로, 상태는 마커(CSS 클래스) | Studio에서 본 그림과 **같은 모양**(아이콘·레인·라벨). 끌기·확대. 판은 Studio와 같게 고정 | 새 의존성(브라우저 JS 수백 KB), 그 부분만 JS가 있어야 보인다 |
| B. 콘솔이 BPMNDI 좌표만 읽어 SVG를 직접 그린다 | 의존성 없음, JS 없이 돈다 | 모양이 Studio와 다르다(아이콘·레인·이벤트 종류). BPMN 그리기를 새로 만드는 일 |
| C. 실행 기록에 그림을 싣는다 | — | C3는 값이 아니라 사건이다. 그림은 설계물이라 패키지에 이미 있다 |

## 결정

**A.** CON-01 상세의 「요약」 아래에 「다이어그램」 섹션을 두고 bpmn-js NavigatedViewer로 그린다.

- **정의는 Center가 패키지에서 읽어 준다** — C5 `GET /packages/{id}/{version}/diagram`(진입 정의 `entry`의 XML 그대로). 저장하지 않고 읽을 때 꺼낸다(`nodes`와 같은 결). 패키지 읽기 권한과 같다 — 정의에는 업무 값이 없다(원칙 6).
- **브라우저는 Center를 부르지 않는다** — Next.js 서버 쪽이 받아 클라이언트 컴포넌트에 글자로 건넨다(BFF 규칙 그대로).
- **상태는 색만이 아니다** — 노드에 「실행·노드」 상태 색 테두리를 얹고(색은 `status_map`·토큰), 기다린 노드는 점선, 지나지 않은 노드는 흐리게. 뜻은 아래 타임라인·표가 글로 말한다(스타일 가이드 §7). 도형을 누르면 그 노드의 타임라인 줄로 간다.
- **판은 Studio와 같다** — `bpmn-js`를 `studio/canvas`와 같은 판으로 고정한다. 둘이 갈라지면 같은 정의가 두 모양으로 보인다.
- 정의를 못 읽으면(패키지가 지워짐·DI 없음) 섹션은 한 줄로 그 까닭을 말하고 나머지 상세는 그대로다.

## 결과

- 쉬워지는 것: 실행이 흐름의 어디에 있는지, 어느 갈래를 탔는지 한눈에 보인다. Studio와 같은 그림이라 설계자·운영자가 같은 것을 본다.
- 어려워지는 것: 콘솔에 브라우저 JS 의존성이 하나 는다. 이 섹션만은 JS가 꺼져 있으면 보이지 않는다(나머지 상세는 JS 없이 돈다). bpmn-js 판을 올릴 때 Studio와 콘솔 두 곳을 함께 올린다.
- 다시 볼 조건: 하위 BPM 프로세스(`libs/`·호출)까지 펼쳐 보여 달라는 요구, 또는 bpmn-js 크기가 콘솔 첫 화면을 눈에 띄게 늦출 때.
