# ADR-0134. 속성 패널의 긴 글은 읽기 전용으로 보이고 편집 창에서 고치며, 결재 설명은 Markdown이다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-11-07 |
| 관련 | 계약 C14(`bpm:approval.description`)·C6(`description`), 화면 `studio/docs/screens.md` STU-04, `docs/06-screens.md` CMN-01, `server/docs/screens/center-console.md` CON-04 |

## 배경

속성 패널(STU-04)은 좁은 오른쪽 카드다. 결재 「설명」·AI 태스크 「목표」·보내기 본문 같은 여러 줄 글을 그 자리 글상자에서 쓰면 몇 줄만 보이고 고치기 불편하다고 사용자가 짚었다. 높이를 늘려도 패널이 길어질 뿐이다.

결재 「설명」은 결재하는 사람에게 보이는 글이다. 제목·목록·굵게처럼 짜임이 있으면 읽기 쉬운데, 지금은 결재 창(CMN-01)과 콘솔 결재함(CON-04)이 글을 그대로 찍는다.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. 그 자리 글상자를 크게 | 고칠 것이 적다 | 패널이 길어지고 여전히 좁다 |
| B. **읽기 전용으로 보이고, 누르면 편집 창** | 패널은 짧게, 쓸 때는 넓게 | 한 번 더 누른다 |
| 결재 설명: 글 그대로 | 바꿀 것이 없다 | 짜임 없는 긴 글 |
| 결재 설명: **Markdown** | 미리보기와 결재 창이 같은 모양 | 결재 창 둘(Qt·웹)이 같은 것을 그려야 한다 |

## 결정

**B, 그리고 결재 「설명」은 Markdown이다.**

1. 속성 패널의 **여러 줄 글 칸은 모두** 읽기 전용 상자로 보이고, 누르면(또는 포커스에서 Enter·Space) **편집 창**이 열린다. 창의 「확인」만 칸에 넣고 「취소」는 버린다. 칸에 넣은 뒤에도 그림에 가는 것은 편집기의 「적용」이다(지금과 같다).
2. **Markdown인 칸**(결재 「설명」·AI 태스크 「목표」·「폼」 탭 「설명」(BPMN documentation))은 읽기 전용 상자에 **그려서** 보이고, 편집 창에 「편집」·「미리보기」 탭이 있다. **글 그대로인 칸**(보내기 본문·템플릿, 지시문 목록, 스크립트)은 같은 창에 「편집」만 있다 — 템플릿의 `{이름}`·지시문의 줄 나눔을 Markdown이 바꾸지 않게.
3. **결재 설명(C14 `bpm:approval.description` → C6 `description`)은 Markdown이다** — 문단·줄바꿈, 제목(`#`~`###`), 굵게·기울임, 인라인 코드·코드 블록, 글머리·번호 목록, 링크(`http`·`https`만). **HTML은 그리지 않는다**(글자로 보인다). 저장되는 값은 글 그대로이고 계약의 타입(str)은 바뀌지 않는다.
4. 그리는 곳은 셋이다 — Studio 미리보기·읽기 전용 상자와 결재 창(CMN-01)은 **한 함수**(`bpm.qt.markdown`)이고, 콘솔 결재함(CON-04)은 위 3의 목록만 그리는 작은 함수(`lib/markdown.ts`)다.

## 결과

- 쉬워지는 것: 속성 패널이 짧아지고, 긴 글을 넓은 창에서 쓴다. 결재하는 사람이 짜인 설명을 읽는다.
- 포기하는 것: 칸을 한 번 더 누른다. 콘솔은 위 목록 밖(표·각주 등)을 그리지 않고 글로 둔다 — Studio 미리보기에서는 그려져도 콘솔에서는 글이다.
- 다시 볼 조건: 결재 설명에 표·그림을 넣자는 요청이 오면 콘솔 쪽 그리는 함수를 다시 본다.
