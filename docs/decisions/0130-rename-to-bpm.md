# ADR-0130. 프로젝트 이름을 Chaeksas에서 BPM으로 바꾼다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 (2026-11-04) |
| 날짜 | 2026-11-04 |
| 관련 | ADR-0019(패키지 이름 — 이 ADR이 이름 부분을 대체한다), ADR-0111(코드 식별자는 그대로 둔다), ADR-0068(설치 파일), ADR-0129(제품 폴더) |

## 배경

환경변수(`BPM_`)·CLI(`bpm-center` 등)·BPMN 접두사(`bpm:`)는 이미 BPM이다. 남은 것은 저장소 이름, 파이썬 배포·import 이름(`chaeksas-*`·`chaeksas.*`), 데이터 폴더·비밀 저장소 이름, 창 제목·설치 파일, 문서의 「Chaeksas」다. 지금 main에서 764개 파일에 3277번 나온다(대부분 import 줄).
ADR-0129로 거의 모든 경로를 한 번 옮기므로, 이름도 같은 흐름에서 바꾸면 진행 중인 브랜치가 충돌하는 일을 한 번으로 끝낼 수 있다.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. 보이는 이름만 바꾼다 (창 제목·문서·저장소) | 코드가 그대로다 | 코드는 `chaeksas`, 화면은 BPM으로 이름이 둘이다 |
| B. **모두 바꾸되, 이미 파일·현장에 박힌 식별자는 둔다** | 이름이 하나가 된다. 이미 만든 BPMN 파일·배포된 패키지·현장 PC가 깨지지 않는다 | 옛 이름이 몇 군데 남는다 (아래 표) |
| C. 식별자까지 모두 바꾼다 | 옛 이름이 하나도 남지 않는다 | 이미 만든 `.bpmn`이 「모르는 확장 속성」이 되고, 배포된 패키지·현장 PC의 데이터와 키를 잃는다 |

## 결정

**B. 모두 BPM으로 바꾼다. 파일·현장에 이미 저장된 식별자는 그대로 두고, 현장 PC의 데이터 폴더·비밀은 처음 뜰 때 한 번 옮긴다.**

### 바꾸는 것

| 무엇 | 지금 | 바꾼 뒤 |
| --- | --- | --- |
| 저장소·로컬 폴더 | `wrapper755/Chaeksas`, `~/Workspace/Chaeksas` | `wrapper755/BPM`, `~/Workspace/BPM` (GitHub이 옛 주소를 넘겨 준다) |
| 파이썬 import | `chaeksas.<이름>`, `chaeksas.ext.<id>` | `bpm.<이름>`, `bpm.ext.<id>` (`src/bpm/`, `__init__.py` 없는 네임스페이스 — ADR-0019 규칙 그대로) |
| 배포 이름 | `chaeksas-<이름>` | `bpm-<이름>` |
| 확장 엔트리 포인트 무리 | `chaeksas.extensions` | `bpm.extensions` (지금 확장이 없어 옮길 것이 없다) |
| 웹 패키지 범위 | `@chaeksas/*` | `@bpm/*` |
| 계약 JSON Schema `$id` | `urn:chaeksas:contracts:*` | `urn:bpm:contracts:*` (생성물이고 저장해 두는 곳이 없다) |
| 창 제목·트레이·자동 시작 이름 | 「Chaeksas Studio」·「Chaeksas PC 실행기」 | 「BPM Studio」·「BPM PC 실행기」 |
| 실행 파일·빌드 기록 | `ChaeksasStudio.exe`·`ChaeksasBotUI.exe`·`chaeksas-build.json` | `BPMStudio.exe`·`BPMBot.exe`·`bpm-build.json` |
| 컨테이너 사용자 | `chaeksas` (uid 10001) | `bpm` (**uid는 그대로** — 볼륨 안 파일 주인이 바뀌지 않는다) |
| 문서의 「Chaeksas」 | | 「BPM」 (`docs/reference/README.md`의 프로토타입 대응표는 그대로) |

### 그대로 두는 것

| 무엇 | 까닭 |
| --- | --- |
| BPMN 확장 이름 공간 `urn:chaeksas:bpmn:1` | 모든 `.bpmn`(업무 예제 81개, 사람이 만든 그림, 배포된 패키지)에 박혀 있다. 바꾸면 옛 그림의 `bpm:*`를 모두 「모르는 속성」으로 읽는다. 접두사 `bpm:`은 이미 BPM이라 화면에 보이는 것은 없다 (ADR-0111과 같은 결 — 식별자는 그대로) |
| Studio가 쓰는 DMN 이름 공간 `urn:chaeksas:studio` | 같은 까닭 (저장된 `.dmn`에 있다) |
| 설치 파일 `AppId` (고정 GUID) | 바꾸면 덮어쓰기가 아니라 두 번째 설치가 된다 (ADR-0068). 이미 깔린 PC는 옛 설치 폴더를 그대로 쓴다 |
| compose 볼륨 이름 | compose 프로젝트 이름을 `bpm`으로 바꾸면 볼륨 이름이 바뀌어 Center가 빈 DB로 뜬다. 볼륨마다 `name:`으로 지금 이름(`chaeksas_…`)을 고정한다 |

### 현장에 이미 있는 것을 옮기기

| 무엇 | 지금 | 옮기는 법 |
| --- | --- | --- |
| 사용자 데이터 폴더 (PC 실행기·Studio·서버 실행기·Center) | `platformdirs` 이름 `chaeksas` (Studio는 `Chaeksas`/`Chaeksas`) | 처음 뜰 때 새 자리가 없고 옛 자리가 있으면 옛 폴더를 **통째로 옮긴다**(복사가 아니라 이름 바꾸기 — 두 벌이 생기지 않는다). 옮기지 못하면 옛 자리를 그대로 쓰고 로그에 남긴다. 컨테이너는 `/data`를 쓰므로 해당 없다 |
| OS 비밀 저장소 | `chaeksas-bot-ui`·`chaeksas-studio`·`chaeksas-server-runner` | 읽을 때 새 이름 → 옛 이름 순으로 찾고, 옛 이름에서 찾으면 새 이름에 쓰고 옛 것을 지운다 |
| 자동 시작 (작업 스케줄러·XDG) | 「Chaeksas PC 실행기」·`chaeksas-bot-ui.desktop` | 등록할 때 옛 이름의 등록을 지운다 (옛 실행 파일을 가리키고 있어서다) |

- 옮기는 코드는 한 모듈(`bpm.core.legacy_names` 같은 자리)에 두고 **다음 큰 판에서 걷는다**. 그때까지 옛 이름은 그 모듈에만 적는다.
- 운영 서버(hetzner)는 데이터가 볼륨에 있으므로 볼륨 이름을 고정하면 옮길 것이 없다. 올리기 전에 DB를 백업하는 절차는 그대로다.

### 순서 (ADR-0129와 합친 것)

1. 코드 자리 옮기기 (ADR-0129 1번)
2. 시험 자리 옮기기 (ADR-0129 2번)
3. **코드 이름 바꾸기** — `src/chaeksas/` → `src/bpm/`, 배포·import·웹 범위·`$id`, 옛 이름 옮기기 모듈, 생성물 다시 만들기
4. 문서 자리 옮기기 + 문서 속 이름 (ADR-0129 3번)
5. GitHub 저장소 이름과 로컬 폴더 이름을 바꾼다 (원격 주소 갱신)

3번 뒤에는 Windows CI와 데스크톱 묶기 워크플로를 돌리고, 실제 Windows PC에서 **옛 판이 깔린 채로 새 판을 설치해** 데이터·키·자동 시작이 넘어오는지 본다.

## 결과

- 이 결정으로 쉬워지는 것: 코드·화면·문서의 이름이 BPM 하나가 된다.
- 어려워지거나 포기하는 것: 옛 이름이 BPMN·DMN 이름 공간, 설치 `AppId`, 볼륨 이름, 옛 이름 옮기기 모듈에 남는다. `bpm`은 흔한 말이라 PyPI의 다른 `bpm` 패키지와 같은 환경에 깔리면 섞일 수 있다(ADR-0019가 `core`·`qt`에서 걱정한 것과 같은 종류) — 우리 패키지는 PyPI에 올리지 않고 워크스페이스·묶은 실행 파일로만 쓰므로 받아들인다.
- 다시 볼 조건: 패키지를 PyPI 같은 공개 저장소에 올리게 되면 import 이름을 다시 정한다. 옛 판이 깔린 현장이 없어지면 옮기기 모듈을 걷는다.
