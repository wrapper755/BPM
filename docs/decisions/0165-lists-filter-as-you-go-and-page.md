# ADR-0165. 목록은 고르는 대로 거르고, 쪽으로 나눈다 — 「좁히기」를 걷고 이름을 먼저 보인다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-11-20 |
| 관련 | 화면 CON-00 [F]·CON-01·CON-04·CON-05·CON-18, [ADR-0160](0160-the-filter-runs-as-you-type.md)(거르기는 치는 대로 — **CON-02만**이라던 것을 이 결정이 넓힌다), [ADR-0162](0162-usability-heuristics-review.md)(U2 — 이름 먼저, id는 뒤), [ADR-0164](0164-neutral-pro.md) |

## 배경

결재함(CON-04)을 보고 사용자가 넷을 짚었다.

1. **「초기화」·「좁히기」가 필요한가** — 조건을 고른 뒤 단추를 한 번 더 눌러야 들었다. CON-02는 이미 치는 대로 돈다(ADR-0160)라 화면마다 결이 달랐다.
2. **「담당」은 자동 완성으로** — 이름 한 칸에 무엇을 칠 수 있는지 알 수 없었다.
3. **제목이 좁았다** — 결재함에서 사람이 먼저 읽는 것이 제목인데 네 줄로 접혔다.
4. **요청 id 대신 BPM의 이름을** — `apr_run_20261110_131613_ddd491_Approve_Report_1`은 사람이 읽는 말이 아니다(U2).

그리고 **목록 전체를 쪽으로 나누자**고 했다 — 줄이 백 개면 표가 끝없이 길었다.

ADR-0160은 「줄이 수천인 목록은 서버에 묻는다」며 치는 대로 거르기를 CON-02에 한정했다. 브라우저에서 추리는 일은 그렇지만, **조건이 바뀔 때마다 서버에 다시 묻는 것**은 줄 수와 상관없이 할 수 있다.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| 「좁히기」를 두고 「찾기」로 이름만 바꾼다 | 바뀌는 것이 적다 | 단추를 누르는 한 번이 그대로다. CON-02와 결이 다르다 |
| **고르는 대로 서버에 다시 묻는다** | 화면마다 같은 결. 단추가 없다 | 글자를 칠 때마다 묻지 않게 잠깐 기다려야 한다 |

쪽 나누기:

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| 서버 쪽(`offset`) | 줄이 아주 많아도 가볍다 | 계약마다 `offset`·`total`이 다 있지 않다. 화면마다 손이 간다 |
| **받은 줄을 표가 나눈다** | `DataTable` 하나가 하므로 목록이 모두 따라온다 | 받는 양은 그대로 「최근 n건」(서버의 `limit`)이 정한다 |

## 결정

1. **목록의 거르기는 고르는 대로 돈다** — 고르는 칸은 바뀌는 즉시, 글자 칸은 멈춘 뒤 0.4초에 **주소를 바꿔 서버에 다시 묻는다**(쪽은 처음으로). 「좁히기」를 걷는다. **Enter도 그대로 든다**(JS가 없으면 GET 폼으로 돈다). 「초기화」는 **조건이 있을 때만** 「조건 지우기」로 보인다. CON-02는 ADR-0160 그대로(브라우저에서 추린다).
2. **알 만한 값을 치는 칸은 자동 완성이다** (`Autocomplete`) — 치는 동안 후보가 아래에 펴지고 화살표·Enter로 고른다. 모르는 값도 칠 수 있다. 결재함의 「담당」은 결재에 적힌 담당과 조직의 직원 이름이 후보다.
3. **결재함의 첫 읽을거리는 제목이다** — 제목 열을 가장 넓게 두고, **요청 id 열을 걷어 그 자리에 「단계」(BPM 그림의 그 노드 이름)**를 둔다. 「BPM 프로세스」도 이름이다(이름이 없으면 id). id는 상세 화면에 있다(U2). 「변수 키」는 앞의 둘과 「외 n개」.
4. **목록은 20줄씩 쪽으로 나눈다** — `DataTable`이 받은 줄을 나누고 표 아래에 「1–20 / 134」와 앞·뒤·쪽 번호를 둔다. 줄이 20 이하면 그리지 않는다. 조건이 바뀌면 첫 쪽이다. 휴대폰 카드 목록도 같은 쪽을 쓴다.

## 결과

- 쉬워지는 것: 조건을 고르면 바로 목록이 바뀐다. 결재함에서 무엇을 결재하는지가 먼저 읽힌다. 긴 목록이 화면 몇 장으로 끝난다.
- 어려워지거나 포기하는 것: 쪽은 **받은 줄 안에서**다 — 「최근 n건」보다 오래된 것은 조건을 좁혀 찾는다. 결재함은 노드 이름을 얻으려 BPM 프로세스 판마다 한 번 더 묻는다(판이 같으면 한 번).
- 다시 볼 조건: 한 목록이 수천 줄을 자주 받게 되면 그 목록만 서버 쪽 `offset`으로 바꾼다.
