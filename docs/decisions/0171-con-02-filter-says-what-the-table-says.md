# ADR-0171. CON-02의 거르기는 표에 있는 말로 하고, 줄에 번호를 단다

| 항목 | 값 |
| --- | --- |
| 상태 | 일부 대체됨([ADR-0184](0184-list-filters-are-a-toolbar.md) — §1 「상태」 기본이 「철회 빼고」) |
| 날짜 | 2026-11-20 |
| 관련 | CON-02, [ADR-0159](0159-con-02-is-a-table-like-the-others.md)·[ADR-0160](0160-the-filter-runs-as-you-type.md)·[ADR-0168](0168-list-header-buttons-are-tonal.md)(CON-15 「번호」) |

## 배경

CON-02 「프로세스」의 거르기 칸을 보고 사용자가 셋을 짚었다.

- 「상태」의 기본값 「철회 빼고」가 「승인됨」·「후보」 같은 **상태 이름들 사이에 홀로 「무엇을 뺀다」**는 말이라 어색하다.
- 「정렬」의 「문제 먼저」 — 표의 열에 「문제」가 없다. 무엇을 기준으로 줄을 세우는지 읽히지 않는다. 칸 이름이 이미 「정렬」이니 고르는 값에 「먼저」·「순」을 덧붙일 까닭도 없다.
- 「초기화」가 칸 줄의 오른쪽 끝에 홀로 서 있어 거르기와 떨어져 보인다.

그리고 줄에 번호가 없어 「몇째 줄」을 말로 가리키기 어렵다 (CON-15 「배포」에는 「번호」 열이 있다).

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. 「상태」 기본을 「전체」로, 철회는 고르는 값 하나 | 고르는 값이 모두 상태 이름이다. 숨긴 줄이 없다 | 철회된 판이 쌓이면 줄이 는다 |
| B. 「전체」 + 「철회된 판도 보기」 체크 따로 | 기본에서 철회가 빠진다 | 칸이 둘이 되고, 「전체」가 전체가 아니다 |

## 결정

**A로 한다** — 거르기는 표에 있는 말로만 한다.

1. 「상태」: 「전체」(기본)·「승인됨」·「후보」·「지원 종료」·「철회」. 기본에서 숨기는 줄이 없다. 옛 주소의 `status=active`는 모르는 값이라 「전체」로 읽는다.
2. 「정렬」: 「경고」(기본)·「이름」 — 값은 **열 이름**이다. 「경고」의 차례(경고가 있는 것 → 대표 판의 성공률이 낮은 것 → 표본이 없는 것 → 이름)는 그대로다.
3. 「초기화」는 **「이름」 칸 바로 옆의 아이콘 단추**(↺)다. 이름은 보조기기 이름과 말풍선 「초기화」(아이콘 단추 이름은 말풍선에 둘 수 있다 — U20).
   **작업공간 목록(CON-20a)도 같은 결이다** — 「이름」 칸 + 옆 ↺. 거기서는 `AutoFilter`(서버에 묻는 쪽, ADR-0165)가 칸을 비우고 다시 묻는다(그 목록의 「조건 지우기」 글자 자리 대신). 다른 목록은 아직 「조건 지우기」다.
4. 표 맨 앞에 **「번호」** — 지금 거르기·정렬로 보이는 차례이고 위에서부터 1이다(쪽을 넘겨도 이어진다). 휴대폰 카드의 제목은 「프로세스」다(CON-15와 같은 결).

## 결과

- 쉬워지는 것: 거르기 칸의 말이 표의 말과 같아 따로 배울 것이 없다. 「3번 줄」로 가리킬 수 있다.
- 포기하는 것: 철회된 판이 기본 화면에 선다. 표에서 「철회」 상태로 보이고 「경고」 칸은 비어 있으므로(ADR-0159) 「경고」 정렬에서는 뒤로 간다.
- 다시 볼 조건: 철회된 판이 많아 기본 화면을 덮으면 기본값을 다시 본다.
