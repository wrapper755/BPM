# ADR-0181. 결재함을 맨 위로, 후보 승인을 「배포」로 — 콘솔 메뉴를 다시 묶는다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-11-20 |
| 관련 | 화면 CON-00 [A]·[M]·CON-02·CON-04·CON-15·CON-21, [ADR-0151](0151-console-follows-the-lifecycle.md)(**묶음 목록을 대체한다** — 생애주기 차례는 그대로), [ADR-0176](0176-projects-have-shared-packages.md)(「라이브러리」 묶음 — 그대로 둔다), [ADR-0172](0172-server-runners-get-their-own-menu-line.md)(서버 실행기 줄의 묶음을 옮긴다), [ADR-0149](0149-console-menu-follows-the-work.md)(줄 이름 = 화면 제목 — 그대로 지킨다), [ADR-0081](0081-answering-on-behalf.md)(결재의 정식 길 — 그대로) |

## 배경

닐슨 10원칙으로 콘솔을 검토하니 위 막대의 묶음 일곱(대시보드 · 저작 · 라이브러리 · 배포 · 운영 · 연결 · 권한·조직)에
다섯 가지가 걸렸다.

1. **승인이 생애주기 밖에 있다** — 흐름은 저작 → 후보 → 승인 → 배포인데 후보는 「운영 › 프로세스」(CON-02)에서 승인한다.
   「배포」를 열면 승인할 것이 없고, 「배포된 것이 지금 어떤 상태인가」라는 줄 설명과 달리 그 표에 후보가 섞인다.
2. **「프로세스」가 두 뜻이다** — 저작 › 프로젝트 안의 프로세스(작업공간)와 운영 › 프로세스(패키지 판).
3. **결재함이 깊다** — 결재하는 사람의 주 화면인데 「운영 ▾」 안에 있고 건수가 보이지 않는다.
4. **「운영」에 세 가지가 섞였다** — 사람의 일(결재함·작업 지시), 업무 현황(프로세스·실행 기록), 기반 시설(서버 실행기).
   서버 실행기와 「연결 › 일꾼」은 둘 다 일이 도는 자리인데 묶음이 갈렸다.
5. **「라이브러리」(메뉴)와 「공통 패키지」(화면 제목)의 이름이 다르다** — 공통 패키지는 프로젝트 안에서 만들기도 한다.
   (이것은 문제로 보지 않기로 했다 — 결정 4.)

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. 전체 다시 묶기 — 결재함을 맨 위로, 배포에 승인 대기, 「시스템」 묶음 | 1~4를 푼다 | 줄 자리가 많이 옮겨 익힌 사람이 다시 찾는다 |
| B. 최소 — 승인을 배포로, 결재함만 맨 위로 | 바뀌는 것이 적다 | 2·4·5가 남는다. 묶음이 여덟이 되어 좁은 노트북에서 막대가 찬다 |
| C. A에서 결재함은 「운영」 안에 두고 묶음 이름에 건수만 | ADR-0081(결재의 정식 길은 API)과 결이 맞다 | 결재하는 사람이 여전히 한 번 더 편다 |

## 결정

**A를 고른다** (사용자, 2026-11-20). 위 막대는 아래 여덟 묶음이고, 왼쪽에서 오른쪽으로 읽히는 생애주기 차례는 그대로다.

| 묶음 | 줄 |
| --- | --- |
| 대시보드 | 대시보드 (CON-21) |
| **결재함** | 결재함 (CON-04) — **묶음 이름 옆에 대기 건수** |
| 저작 | 프로젝트 (CON-20) |
| 라이브러리 | 공통 패키지 (CON-06) — 그대로 |
| 배포 ▾ | **승인 대기** · 배포 (둘 다 CON-15, 탭이 다르다) |
| 운영 ▾ | **프로세스 현황** (CON-02) · 실행 기록 (CON-01) · 작업 지시 (CON-05) |
| **시스템** ▾ | 서버 실행기 (CON-12) · 앱 (CON-18) · 일꾼 (CON-17) |
| 권한·조직 ▾ | 조직 (CON-13) · 관리자 계정 (CON-14) |

1. **결재함은 제 묶음이다.** 결재하는 사람이 들어와서 가장 먼저 찾는 자리이고, 건수(`state: open`)가 막대에 보여야
   「기다리는 것이 있다」를 다른 화면에서도 안다. 건수를 못 읽으면 배지를 그리지 않는다(「0」과 「모른다」는 다르다).
   결재의 정식 길이 대리 답용 키의 API라는 것(ADR-0081)은 바뀌지 않는다 — 콘솔 결재함은 여전히 막힌 것 찾기·담당자 없는
   결재 답하기·감사의 자리이고, 그 일이 운영자에게 자주 일어나므로 위로 올린다.
2. **승인은 「배포」의 첫 걸음이다.** CON-15에 탭 둘 — 「승인 대기 n」(상태 `후보`인 판 전부, BPM 프로세스·공통 패키지)과
   「배포됨」(지금의 배포 목록). 새 화면을 늘리지 않고 승인한 뒤 바로 옆 탭에서 배포한다. 대시보드 C3 「승인 기다리는 후보」도
   그 탭으로 간다. CON-02 줄의 「⋯」 메뉴(승인 철회·지원 종료·삭제, 지원 종료된 판의 재승인)는 **판을 관리하는 메뉴**라
   그대로 둔다 — 후보의 승인을 받는 **대기열**은 승인 대기 탭 한 곳이다.
3. **CON-02의 제목은 「프로세스 현황」이다.** 저작의 「프로세스」(작업공간)와 가른다. 줄 이름 = 화면 제목(ADR-0149)을 지킨다.
4. **「공통 패키지」는 「라이브러리」 묶음에 그대로 둔다** (ADR-0176). 처음 안은 「저작」 아래로 옮겼으나 사용자가 되돌렸다 —
   그 화면은 **만드는 자리가 아니라 이미 지어 올린 것을 보고 고르는 서가**라 「저작」(만드는 일)보다 「라이브러리」가 뜻에 맞다.
   만드는 자리는 프로젝트의 「공통 패키지」 칸 그대로다. 묶음 이름(라이브러리)과 줄 이름(공통 패키지)이 다른 것은 묶음과 줄의
   관계일 뿐이고 줄 이름 = 화면 제목(ADR-0149)은 지켜진다.
5. **「시스템」은 일이 도는 기반이다** — 서버 실행기·바깥 앱·그 앱의 일꾼. 「운영」에는 업무 현황과 사람이 시키는 일(작업 지시)만 남는다.

## 결과

- 쉬워지는 것: 결재할 것이 있는지 어느 화면에서나 보인다. 저작 → 배포(승인 → 배포) → 운영이 메뉴 차례 그대로 이어진다.
  「프로세스」가 두 뜻으로 겹치지 않는다.
- 어려워지는 것: 묶음이 여덟이 되어 좁은 노트북 폭(1024 근처)에서 막대가 빠듯하다. 익숙한 줄 자리(서버 실행기·앱·일꾼·CON-02 이름)가 옮겨 처음 얼마간 다시 찾는다.
  막대가 화면마다 결재 수를 읽으므로 화면마다 Center 호출이 하나 는다(실패해도 화면은 그린다).
- 다시 볼 조건: 결재가 콘솔이 아니라 거의 다 API(회사 시스템)로 답해져 결재함 건수가 늘 0이면 결재함을 「운영」으로 되돌린다(C안).
  막대가 1024~1280 폭에서 오른쪽 계정 줄과 겹치면 묶음 수를 다시 본다.
