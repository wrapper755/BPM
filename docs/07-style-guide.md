> 상태: **확인.** 모든 화면(Center 콘솔, 서비스 앱 관리 콘솔)이 이 문서와 `design/tokens.json` 하나를 따른다 ([ADR-0017](decisions/0017-web-nextjs-design-system.md)). 틀은 [ADR-0152](decisions/0152-console-chrome-is-one-top-bar.md)가 정한 **위 막대 하나**이고 입는 것은 [ADR-0161](decisions/0161-soft-cards.md)의 **부드러운 카드**다 — 데스크톱 쪽은 Qt와 함께 걷었다 ([ADR-0143](decisions/0143-design-happens-in-the-console.md)).

## 2. 토큰

원본은 `design/tokens.json`. 아래 표는 이름과 쓰임만 적는다 (값은 원본에서). 토큰 이름은 `--bg-surface`처럼 점을 `-`로 바꾼 CSS 변수가 된다.

### 2-1. 색 — 바탕·선·글자

| 토큰 | 쓰임 |
| --- | --- |
| `bg.canvas` | 페이지·창의 바탕 (차가운 옅은 회색, ADR-0164) |
| `bg.surface` | 패널·카드·표·대화상자 |
| `bg.subtle` | 표 머리, 줄 위에 올렸을 때, 읽기 전용 칸 |
| `bg.inverse` / `text.inverse` | 툴팁 |
| `border.default` / `border.strong` | 구분선 / 입력칸·보조 단추 테두리 (`border.strong`은 `bg.surface` 위 **3:1 이상** — WCAG 1.4.11, 생성기가 막는다, ADR-0163) |
| `text.primary` / `text.secondary` / `text.muted` | 본문 / 표 머리·보조 설명 / 설명 줄·빈 상태 (모두 바탕 셋 위에서 4.5:1 이상 확인됨) |
| `primary` / `primary.hover` / `primary.subtle` / `primary.fg` | 주 단추·링크·고른 메뉴 묶음의 밑줄 / 위에 올림 / 고른 메뉴 줄·고른 탭의 바탕 / 주 단추 글자 |
| `focus` | 포커스 테두리 (2px, 2px 띄움) |
| `chrome.bg` / `chrome.fg` / `chrome.muted` / `chrome.hover` / `chrome.border` / `chrome.side` / `chrome.side.hover` / `chrome.edge` | **서비스 앱 콘솔만** 쓰는 **남색 틀** — Center 콘솔은 밝은 위 막대로 바꿨다 (ADR-0161) — 위 막대 바탕(가장 짙다) / 글자 / 보조 글자 / 위 막대에서 올림 / 구분선 / 왼쪽 탐색 바탕(**서비스 앱 콘솔만** 쓴다 — Center 콘솔의 레일·패널은 걷었다, ADR-0152) / 탐색에서 올림 / 위 막대 아래 띠(라벤더 2px — 위 막대와 본문을 가른다). 남색 단계는 로그인 배경 그림(ADR-0120)에서 골랐다(`.chrome-side`가 탐색에 바꿔 끼운다). 틀 안에서는 `.chrome`이 `bg.surface`·`text.*`·`border.*`를 이것으로 바꿔 끼워 구성요소를 그대로 쓴다 (글자는 바탕·`chrome.hover` 위 둘 다 4.5:1 이상 확인됨) |
| `danger.fg` | 위험 단추 글자 (`status.failed.solid` 바탕 위) |

브랜드 색은 `primary` 하나다(남보라 — NowView와 같은 값, [ADR-0119](decisions/0119-match-nowview-style.md)). 남색 틀(`chrome.*`)은 서비스 앱 콘솔의 틀에만 쓴다. 그 밖의 색은 모두 **상태 색**이다.

### 2-2. 색 — 상태 7가지

상태마다 세 값: `fg`(글자), `bg`(배지 바탕), `solid`(점·막대·아이콘). `fg`는 `bg`와 `bg.surface` 위에서 모두 4.5:1 이상.

**상태 색은 맑게, 대신 점으로만** ([ADR-0164](decisions/0164-neutral-pro.md) — ADR-0157을 대체한다) — 일곱의 `solid`은 또렷한 값이고 **지름 7px 점**으로만 쓴다. 상태 배지는 점 + 글자이고 **바탕을 칠하지 않는다**. `bg`·`fg`는 띠(오류·경고 알림)에만 쓴다. 그래서 상태 색이 큰 면이 되는 일이 없고 **화면에서 가장 큰 색 면은 주 단추 하나**다(ADR-0157이 지키려던 것). 위험 단추(`danger.fg` on `failed.solid`)는 4.5:1을 생성기가 본다.

| 상태 토큰 | 뜻 | 대표 예 |
| --- | --- | --- |
| `neutral` | 아직·멈춤·의미 없음 | 대기, 취소됨, 비활성, 폐기됨 |
| `active` | 지금 움직이는 중 | 실행 중, 전달됨, 요청 처리 중 |
| `done` | 정상·성공 | 완료, 연결됨, 정상, 사용 중 |
| `failed` | 실패·막힘 | 실패, 오류, 실행 불가, 응답 없음 |
| `waiting` | **사람이나 차례를 기다림** | 결재 대기, 확인 대기, 대기열, 검증 전 |
| `warning` | 주의 (곧 문제가 될 수 있음) | 만료, 연결 끊김, 다시 띄우는 중, 저하 |
| `replayed` | 학습한 대로 다시 함 | 재생됨 |

화면 표기 → 상태 토큰 대응은 `tokens.json`의 `status_map`이 원본이다 ([docs/06-screens.md](06-screens.md) §3의 표와 같아야 한다). 새 상태를 만들면 `status_map`에 먼저 넣는다.

| 구성요소 | 규칙 | 구성요소 이름 |

| **LogView** | mono 13px, 최대 5000줄, 실패 줄은 `failed.fg` | `LogView` |
| **Section (묶음)** | 한 화면 안의 기능 묶음. 제목은 **카드 안쪽 맨 위**에 `text.primary`·굵게(`weight.bold`)·`size.body-lg`로 쓰고, **그 아래 묶음 폭 전체에 옅은 선**(`border.default` 1px, 카드 양끝까지)을 긋는다. 꾸밈(세로 막대·이름표·아이콘)은 달지 않는다 — 진한 막대는 화면마다 줄지어 너무 셌고, 아이콘은 묶음이 하는 일이 아니라 갈래라 뜻을 싣지 못한다(§6은 하는 일로 고른다). 제목과 내용 사이는 `space.3`, 묶음과 묶음 사이도 `space.3`. 테두리 위에 걸친 회색 제목은 쓰지 않는다 — 내용과 붙어 보이고 묶음이 갈리지 않는다 | — |
| **Tabs / Nav** | 탭은 둥근 알약(`radius.md`) — 선택된 것은 `primary.subtle` 바탕 + `primary` 글자 + 굵게, 나머지는 흰 바탕 + 선. 작업공간 안의 탭은 밑줄이다(고른 것만 `primary` 2px). 펼친 메뉴의 고른 줄은 `primary.subtle` 바탕 + 굵게이고, **위 막대의 묶음은 글자뿐이며 고른 묶음은 `primary` 2px 밑줄 + 굵게**다 (ADR-0164) | `Tabs`, `SideNav` |
| **링크** | **밑줄을 긋지 않는다** — 이름은 굵게(`weight.medium`), 올리면 `primary`. 판 번호는 `v0.3.0`(본문 글꼴·보조 글자색). mono는 실행 id·키 같은 **기계 값**에만 (ADR-0164) | — |

- **웹 화면에서 손으로 쓴 칸·묶음도 같은 모양이다** — `<select>`·`<input>`·`<textarea>`는 입력칸(Field)처럼 `radius.md` + `border.strong` + 높이 `control.md`, `details`·`fieldset` 묶음은 카드처럼 `radius.lg` + `bg.surface`. 상태 배지는 `radius.full`. 섹션 제목(h2)은 굵기 `semibold` 하나다.

## 4. 배치

### 4-1. 웹 콘솔 (CON-00, SVC-00)

```
+-------------------------------------------------------------------+
| [T] top bar 56px: mark BPM  ( groups pill )  user [Re] [Logout]   |
+-------------------------------------------------------------------+
|        [M] menu card (under the clicked group)                    |
|   +-----------------------------------------------------------+   |
|   | [H] here > place                                          |   |
|   |     h1 title                              [sec] [prim]    |   |
|   | [F] filter card                                           |   |
|   | [B] body: table (cards below 768) -> detail               |   |
|   +-------------------- max width 1440 -----------------------+   |
+-------------------------------------------------------------------+
```

- **틀은 위 막대 하나다** ([ADR-0152](decisions/0152-console-chrome-is-one-top-bar.md)) — 화면 폭 전체의 **흰 띠**(`size.topbar.height` 56, `bg.surface` + 아래 `border.default`)에 **마크 + 「BPM」**(ADR-0153)과 **묶음 여섯**이 가로로 선다. **띠의 안쪽은 본문과 같은 최대 폭·같은 여백**이라 마크의 왼쪽 끝이 본문 제목의 왼쪽 끝과 맞는다. 묶음은 글자이고 고른 묶음은 `primary` 밑줄이다 ([ADR-0164](decisions/0164-neutral-pro.md) — 짙은 남색 틀은 Center 콘솔에서 걷었다. 서비스 앱 콘솔은 아직 남색이다).
- **묶음을 누르면 그 아래로 펼쳐지고 줄마다 한 줄 설명이 붙는다** — 설명은 **그 화면에 무엇이 있는지**를 말한다. 넓은 화면(1024~)에서는 줄의 **말풍선**이고 좁은 화면의 한 장 메뉴에서는 글이다 (ADR-0170 — 말풍선이 뜨지 않는 자리에서는 글로, U20). **줄이 하나인 묶음은 펼치지 않고 바로 간다.** 밖을 누르거나 `Esc`면 닫힌다.
- 본문 바탕은 `bg.canvas`(차가운 옅은 회색), 카드·표는 `bg.surface`(흰색, `radius.lg`). **흰 머리 띠는 없다** — 지금 자리 한 줄과 제목이 바탕 위에 바로 서고(상세가 목록으로 돌아가는 길이다) 화면 전용 단추·링크는 제목 오른쪽(좁은 화면에서는 제목 아래로 내려간다), 필터는 흰 카드 하나.
- 본문은 **가운데 최대 폭 1440** 안에 서고 여백은 16 → 24(`md`) → 32(`lg`)다.
- **제목은 한 단 낮다** — 표가 많은 화면에서 제목이 내용보다 커 눈이 먼저 제목에 갔다 (ADR-0145 §4).
- **모든 화면이 360px에서 읽힌다** (ADR-0161) — 1024 아래에서는 묶음이 단추 하나로 접히고 누르면 묶음·줄 전부가 한 장에 펼쳐진다. 768 아래에서는 표가 카드 목록이 되고 여러 열의 칸 배치는 한 열로 쌓인다. **결재함(CON-04)은 휴대폰에서도 답할 수 있어야** 한다.
- 목록 → 고르면 아래에 상세. 상세가 길면 오른쪽 패널(폭 480, 좁은 화면에서는 아래로).
- **작업공간(CON-20)은 본문을 가득 쓴다** — 머리 띠도 패딩도 틀이 그리지 않고 그 화면이 스스로 그린다 (ADR-0145 §3). **1024 아래에서는 보기만 한다** — 그림과 시험 결과만 보이고 탐색기·속성 패널은 넓은 화면의 것이다.
- 쓰기 단추는 「관리자」 모드에서만 보인다 (CON-00 쓰기 권한).

## 6. 아이콘

- **웹은 Lucide** 한 벌만 (`lucide-react`, ISC). 선 굵기 기본(2)을 바꾸지 않는다.
- 웹에서 아이콘을 두는 곳: 보조 단추, 표의 잔일 단추, 좁은 화면의 메뉴 단추. **메뉴 줄에는 두지 않는다** — 줄은 이름과 한 줄 설명이 말한다 (ADR-0152).
- 크기 16 (본문 옆·줄), 20 (단추).
- 아이콘만 있는 단추는 툴팁·`aria-label` 필수.

### 6-1. BPM 흐름 마크

화면에 저장소 이름(Chaeksas)을 쓰지 않는다 ([ADR-0118](decisions/0118-no-product-name-on-screens.md)). 그 자리(웹 콘솔 위 막대 맨 왼쪽·로그인 머리 띠·브라우저 탭)에는 **BPM 흐름 마크**를 두고, Center 콘솔에서는 그 옆에 **「BPM」**이 선다 ([ADR-0153](decisions/0153-the-console-stands-as-bpm.md)): 시작 이벤트(빈 원) → 태스크(채운 둥근 네모) → 배타 게이트웨이(빈 마름모) → 끝 이벤트(굵은 원), 색은 `primary` 하나. 선은 **2.8**이다 — 1.8은 위 막대(20px)에서 흐렸다 (ADR-0163).

**앱 타일**(`AppTile`)은 `primary` 둥근 정사각(`radius.md`)에 흰 정사각 기호이고 **Center 콘솔의 위 막대와 로그인**이 마크 대신 쓴다 — 옆에 「BPM」이 선다 (ADR-0164). 위 막대에서는 **24**이고 「BPM」은 16 `bold`, 묶음·배지·계정·단추는 모두 14다 (ADR-0166·0167).

**정사각 기호**(`design/bpm-symbol.svg`, `BpmSymbol`)는 마크의 **가운데 두 도형(태스크 → 배타 게이트웨이)**만 남긴 것이고 **마크가 들어갈 폭이 없는 자리**(브라우저 탭 아이콘)에만 쓴다 (ADR-0163 — 가로로 긴 마크를 정사각에 넣으면 16px에서 실선이 된다). 마크를 고치면 기호도 같이 본다.

- 원본은 `design/bpm-mark.svg` 하나(`currentColor`)다. `scripts/gen_tokens.py`가 웹 구성요소 `BpmMark`·`BpmSymbol`(`server/web/packages/ui/src/bpm-mark.tsx`)과 콘솔마다 탭 아이콘 `app/icon.svg`(**기호**로, 밝게·어둡게 `primary`)를 짓는다 — **생성물이니 직접 고치지 않는다**.
- 그림만 있는 자리에는 툴팁·`aria-label`로 이름을 준다(「Center 콘솔」, 서비스 앱 이름). 글 옆에 붙는 자리(로그인 제목)는 장식이라 읽지 않는다.
- 마크가 서는 자리는 **위 막대 맨 왼쪽**이다 (ADR-0152 §1) — 「BPM」과 함께 서고, 누르면 첫 화면.

## 7. 구현 규칙 (코드 리뷰 체크리스트)

- [ ] 색·크기·간격 값을 직접 쓰지 않았다 (`#`, `px` 검색). 토큰만.
- [ ] 상태 표시는 `StatusBadge`(또는 같은 규칙)로, `status_map`에 있는 표기만.
- [ ] 빈 상태·오류·불러오는 중 세 가지를 모두 그렸다.
- [ ] 설명·꺼진 까닭을 **말풍선(`title`)에만** 두지 않았다 — 화면 글이나 `InfoTip`(눌러 펴는 「?」). 말풍선은 줄인 id의 전체와 아이콘 단추 이름뿐 (U20, ADR-0162).
- [ ] 360px에서 가로로 밀리지 않는다 (ADR-0161).
- [ ] 키보드만으로 동작하고 포커스가 보인다. 아이콘 단추에 이름이 있다.
- [ ] 밝게/어둡게 둘 다 확인했다 (스크린샷 테스트는 M3부터).
- [ ] 문구가 §5와 용어집을 따른다.
- [ ] 웹: 브라우저로 토큰·비밀이 내려가지 않는다 (BFF).

## 8. 바꾸는 법

1. `design/tokens.json`을 고친다 (새 토큰은 이름 규칙 `<분류>.<이름>[.<변형>]`).
2. 생성기를 돌린다 (`uv run python scripts/gen_tokens.py`) → `server/web/packages/ui/src/{tokens.css,theme.css,status-map.ts}`, `design/preview.html`, BPM 흐름 마크(§6-1)가 바뀐다. **모두 생성물이니 직접 고치지 않는다.**
3. 명암비 검사가 통과해야 한다 (생성기가 §2의 기준으로 검사하고, 실패하면 **아무것도 쓰지 않고** 멈춘다). `--check`가 CI와 pytest에 들어 있다.
4. 이 문서의 표를 함께 고친다.
