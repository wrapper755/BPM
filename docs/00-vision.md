# 00. 비전과 범위

## 한 문장

업무 담당자가 **BPMN으로 BPM 프로세스를 그리면**, Center가 그것을 **서버 실행기**에 배포하고, 각 단계의 실제 일(문서 읽기, 판단, 서버 API 호출)은 **AI·서비스 앱이 수행**하며, 사람은 **정해진 지점에서만 결재·확인**한다.

## 핵심 원칙: 지도 · 운전사 · 실행 · 손

| 역할 | 담당 | 정하는 것 | 넣지 않는 것 |
| --- | --- | --- | --- |
| 지도 | BPMN | 순서, 분기, 결재, 마감, 감사 기록 | 셀렉터, 클릭 좌표, 프롬프트 요령 |
| 운전사 | AI (AI 태스크, 서비스 앱의 LLM) | 각 단계 목표에 도달하는 방법, 도구 선택, 실패 시 복구 | 업무 순서, 승인 규칙 |
| 실행 | 서버 실행기가 BPM 프로세스를 실행 (설계 중에는 **시험 실행**도 같은 실행기가 돌린다) | 태스크를 차례로 수행하며 운전사·손·서비스 앱을 부른다 | 화면 조작 자체 |
| 손 | 확장이 주는 결정적 수행기 | 요청받은 일을 정해진 대로 한다 | 업무 판단, 업무 흐름 |

> 지금은 **손을 주는 확장이 깔려 있지 않다** — 화면 조작(UI 자동화 확장)은 걷었고 다시 정리해 들인다 ([ADR-0114](decisions/0114-remove-ui-automation.md)).

프로토타입 4개 모두에서 유지된 가장 중요한 설계 규칙이다 ([ADR-0008](decisions/0008-map-driver-hands-boundary.md)).
BPM 프로세스가 호출하는 서버 기능은 **서비스 앱**으로 늘려 간다. 같은 BPM 프로세스도 설계 중의 시험 실행에서는 **자율 수행**(AI가 방법을 찾고 학습), 운영에서는 **결정 수행**(학습된 대로)으로 돈다 ([ADR-0010](decisions/0010-service-apps.md)).

## 누가 쓰는가

| 사용자 | 하는 일 | 주로 쓰는 것 |
| --- | --- | --- |
| BPM 프로세스 설계자 | BPM 프로세스를 그리고, 시험 실행으로 학습시키고, 배포 후보로 만든다 | Center 콘솔 (웹, [ADR-0143](decisions/0143-design-happens-in-the-console.md)) |
| 운영 관리자 | 패키지 승인·배포, 서버 실행기 상태 확인, 작업 지시, 실행 이력 조회, Center API 키 발급 | Center 콘솔 |
| 서비스 앱 관리자 | 서비스 앱 API 키 발급, 앱 상태·사용 기록 확인 | 각 서비스 앱 관리 콘솔 |
| 업무 결재자 | BPM 프로세스가 올린 결재 요청에 답한다 | Center 콘솔 결재함 (또는 현장 PC의 결재 창) |

## 대표 시나리오 (프로토타입에서 검증된 것)

새 플랫폼의 기능 범위와 인수 시험의 기준으로 쓴다. 자세한 내용은 [reference/lessons-learned.md](reference/lessons-learned.md).

| # | 시나리오 | 확인하는 능력 | 프로토타입 결과 |
| --- | --- | --- | --- |
| 1 | 신규 거래처 등록 심사 | 포함 게이트웨이, 조건별 검토 켜기 | 케이스 3/3 통과 |
| 2 | 입사 첫날 온보딩 | 하위 프로세스, 묶음 마감 타이머, 수동 작업 | 케이스 3/3, 재생 3/3 |
| 3 | 세금계산서 발행 | 웹에서 조회 → 데스크톱 앱에 입력 (웹 + 데스크톱) | 케이스 2/2, 재생 2/2 |
| 4 | 계약서 조항 검토 | Call Activity, 변수 매핑, 같은 절차 반복 | 진행 중이었음 |

> 시나리오 3은 화면 조작이 있어야 돈다 — UI 자동화 확장을 다시 들일 때까지 범위 밖이다 ([ADR-0114](decisions/0114-remove-ui-automation.md)).

## 만드는 것 (범위)

1. **Center** — 패키지 레지스트리, 실행기 등록·상태, 배포, 작업 지시, 결재함, 실행 이력, 리소스 목록, Center API 키. Linux 서버. 웹 화면은 **Center 콘솔**이고 **BPM 프로세스를 그리고 돌려 보는 자리도 그 안**이다 (작업공간 — [ADR-0143](decisions/0143-design-happens-in-the-console.md)). 데스크톱 앱은 없다.
2. **서버 실행기** — BPM 프로세스를 여러 건 동시에 실행한다. **모든 업무가 여기서 돈다** (서버 우선, [ADR-0016](decisions/0016-server-first.md)·[ADR-0144](decisions/0144-remove-the-pc-runner.md)). Center가 배포·작업·관리. Linux 서버.
3. **확장** — BPM 프로세스에 공통 기능을 더하는 묶음 (VS Code의 확장처럼). 내장(이 저장소)·사내(다른 저장소)·외부(정의 파일만, 외부 앱) 등급 ([ADR-0018](decisions/0018-extensions.md)). **지금 깔린 내장 확장은 없다** — UI 자동화는 걷었고 다시 들인다 ([ADR-0114](decisions/0114-remove-ui-automation.md)).
   **서비스 앱**은 확장의 서버 부분이다 — BPM 프로세스가 Center의 외부 작업으로 부르는 서버 앱들(대부분 LLM 앱). 앱마다 관리 콘솔을 가진다. Linux 서버.
4. **공통 계약 패키지** — 위 구성요소가 주고받는 모든 데이터 모델의 단일 원본.

## 만들지 않는 것 (비범위)

- 범용 BPM 제품과의 호환. BPMN 2.0 파일 형식은 따르되, 실행 엔진은 우리 것 하나.
- 사람이 실시간으로 화면을 원격 조종하는 기능.
- 비밀 값 보관 서버. Center는 바깥 기능의 주소·키를 들지 않는다 (외부 앱의 키는 어댑터 일꾼의 설정에만 있다, [ADR-0102](decisions/0102-calling-outside-is-pull.md)). 패키지에도 비밀을 넣지 않는다.
- 멀티 테넌시 (조직 하나 기준). 필요해지면 ADR로 다시 연다.
- macOS 지원.

## 성공 기준

> 제안: 아래는 첫 릴리스(M6) 기준이다. 숫자는 논의로 확정한다.

- 서버 BPM 프로세스인 시나리오 1·2·4는 서버 실행기(M7)에서 끝까지 돈다. 시나리오 3(현장 PC, [ADR-0055](decisions/0055-m6-field-scenario-is-scenario-3.md))은 UI 자동화 확장을 다시 들인 뒤의 기준이다 ([ADR-0114](decisions/0114-remove-ui-automation.md)).
- 새 개발자가 `docs/04-setup.md`만 보고 1시간 안에 Center와 콘솔을 띄운다.
- 모든 구성요소 간 통신이 `docs/03-contracts/`의 명세와 일치한다 (계약 테스트로 확인).
- 모든 화면이 `docs/06-screens.md`(공통)·`<제품>/docs/screens`의 설계와 일치한다.

## 열린 질문

| 질문 | 상태 |
| --- | --- |
| 제품 이름 "BPM"를 사용자 화면에도 쓰는가, 저장소 이름만인가? | **확정: 저장소 이름만이다.** 화면에는 쓰지 않고 웹 콘솔의 머리는 BPM 흐름 마크다 ([ADR-0118](decisions/0118-no-product-name-on-screens.md)) |
| 배포 단위의 화면 이름 | **확정: 설계·운영 화면 모두 "BPM 프로세스"** ([ADR-0111](decisions/0111-bpm-process-and-pc-runner-names.md)) |
| 서비스 앱 키를 어디에 지정하나 | **확정: 서비스 앱 키는 없다** — 바깥 기능은 Center의 외부 작업으로 부르고 「불러도 되나」는 Center가 배포로 가린다 ([ADR-0102](decisions/0102-calling-outside-is-pull.md)) |
| 결재를 기다리는 BPM 프로세스가 실행 자리를 놓는가 | **확정: 놓는다** — 상태를 저장하고 쉬다가 답이 오면 이어 간다 ([ADR-0054](decisions/0054-server-run-state-and-concurrency.md)) |
| 업무를 어디서 돌리나 | **확정: 서버 하나다** — PC 실행기는 걷었고 RPA는 나중에 데스크톱 일꾼으로 ([ADR-0144](decisions/0144-remove-the-pc-runner.md)) |
| BPM 프로세스가 다른 패키지의 BPM 프로세스에 한 부분을 맡기는가 | **확정: Call Activity의 `bpm:call.delegate`로 맡기고 기다린다** ([ADR-0082](decisions/0082-batch-start.md)) |
| 서버 앱 분류 이름 | **확정: "서비스 앱"** ([ADR-0010](decisions/0010-service-apps.md)) |
| 결정 수행이 실패하면 자율 수행으로 넘어가는가? | 기본은 넘어가지 않고 실패. 앱·작업별 예외는 manifest 정책 ([ADR-0010](decisions/0010-service-apps.md)) |
| RPA(화면 조작)를 어떻게 다시 들이나 | **나중에 검토** — 데스크톱 일꾼이 C15 Pull로 가져가는 쪽이다 ([ADR-0144](decisions/0144-remove-the-pc-runner.md) §나중에) |
