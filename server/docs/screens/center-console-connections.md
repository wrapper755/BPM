# Center 콘솔 — 일꾼·연결 앱

[center-console.md](center-console.md)의 나머지다 — 바깥 기능을 맡는 **일꾼**(CON-17)과 BPM 프로세스가 부르는 **연결 앱**(CON-18). 한 파일이 500줄을 넘어 나눴다(CLAUDE.md §4). 공통 틀(CON-00)·표기 규칙은 그 파일과 [06-screens.md](../../../docs/06-screens.md)를 따른다.

## CON-17 일꾼 (신규)

메뉴 「연결 › 일꾼」, 주소 `/consumers` ([ADR-0137](../../../docs/decisions/0137-consumers-are-managed-in-the-console.md)). **일꾼**(C15 — Center에서 외부 작업을 가져가는 프로그램: 서비스 앱·어댑터 일꾼·통합 일꾼)을 만들고, 맡는 토픽을 바꾸고, 토큰을 새로 발급하고, 지운다. 바뀐 것은 일꾼의 **다음 요청부터** 반영된다 — Center를 다시 띄우지 않는다. 목록은 콘솔 계정 모두가 보고, 단추와 「...」는 **Center 관리자**에게만 보인다(회사 관리자·보기 전용에게는 없다 — 일꾼은 Center 공용이다).

> 상태: **돈다** (`app/consumers`). 재료는 C15 `GET /consumers` 하나다. 일꾼 폴더(`<이름>.consumer.json`)는 첫 설치에 **처음 한 번 들이기만** 하고, 들어온 뒤로는 여기서 고친다.

```
+--------------------------------------------------------+
| [H] title                              [New consumer]  |
| [L] consumers table                                    |
+--------------------------------------------------------+
```

| 영역 | 내용 |
| --- | --- |
| [H] | 제목 「일꾼」, 오른쪽에 「새 일꾼...」(Center 관리자만) |
| [L] | 일꾼 표, 이름 순 |

| 열 | 내용 |
| --- | --- |
| 「이름」 | |
| 「토픽」 | 맡은 토픽(서비스 앱 id·외부 확장 id)을 쉼표로 |
| 「종류」 | 이 일꾼의 종류(Center 관리자가 정한다, C15 `kinds`, [ADR-0139](../../../docs/decisions/0139-consumer-kinds-are-set-in-the-console.md))를 「AI·API·RPA」 순으로. 정하지 않았으면 「정하지 않음」(툴팁 「모든 종류의 일감을 가져갑니다. 「편집...」에서 정하세요.」). 맡은 토픽의 작업 종류(`topic_kinds`) 가운데 이 일꾼이 맡지 않는 것이 있으면 값 옆에 「⚠」, 툴팁은 토픽마다 「<토픽>은 API 작업이 있는데 이 일꾼은 API를 맡지 않습니다 — 그 일감을 가져가지 않습니다.」 |
| 「맡은 앱」 | 일꾼이 올린 manifest의 `app_id@version`과 외부 확장의 `id@version`. 없으면 「—」 |
| 「마지막 가져감」 | **연도까지**. 한 번도 없으면 「아직 없음」 |
| 「들어온 길」 | 「콘솔 · <만든 계정>」 / 「일꾼 폴더」 / **「열린 모드」**(스스로 들어온 일꾼 — [ADR-0142](../../../docs/decisions/0142-open-mode.md)), 아래 작은 글자로 들인 때(연도까지) |
| (끝 칸, Center 관리자) | 「...」 — 「편집...」 / 「토큰 새로 발급...」 / 「삭제...」 |

**제목 오른쪽에 「일꾼 설정에 적을 Center 주소: <주소>」와 「복사」가 있다** ([ADR-0149](../../../docs/decisions/0149-console-menu-follows-the-work.md) §6, 글·동작은 CON-00) — 토큰만으로는 일꾼이 Center를 찾지 못한다. 전에는 CON-03(앱)에 있었다.

빈 상태: 「등록된 일꾼이 없습니다.」 + Center 관리자면 「「새 일꾼...」으로 만들고 받은 토큰을 일꾼 설정에 넣으세요.」

- **「새 일꾼...」** → 창: 「이름」(도움말 「로그와 실행 상세에 보이는 이름입니다. 1~64자, 다른 일꾼과 겹치지 않게.」), 「종류」 체크박스 셋 「AI」·「API」·「RPA」(하나 이상, 도움말 「이 일꾼이 가져갈 일감의 종류입니다. 고르지 않은 종류의 일감은 같은 토픽이어도 가져가지 않습니다.」), **「맡을 연결 앱」**(아래 「토픽 고르기」), 「만들기」. Center가 거절하면(이름 겹침 `name_taken`·토픽 모양) 그 까닭을 창 안에 보이고 닫지 않는다. 되면 **같은 창**이 토큰을 보인다(아래 「토큰 창」).
- **「편집...」** → 창 「<이름> 편집」: 「종류」 체크박스(지금 종류가 체크돼 있다 — 정하지 않은 일꾼은 셋 다 비어 있고 하나 이상 골라야 저장된다)와 「맡을 연결 앱」(지금 토픽이 체크돼 있고, 목록에 없는 토픽은 「직접 적기」에 채워져 있다)과 「취소」·「저장」.
- **토픽 고르기 — 「맡을 연결 앱」** (만들기·편집 같은 칸). 토픽은 곧 연결 앱 id다(CON-18, 앱 하나 = 토픽 하나). CON-18과 같은 재료(C7 외부 확장·서비스 앱)의 연결 앱을 이름 순 체크 목록으로 보인다 — 줄마다 첫 줄에 앱 이름과 고정폭 `id`, 둘째 줄에 「<구현> · <종류> · 이미 맡은 일꾼 <이름들>」(구현은 CON-18과 같은 「외부 정의」/「일꾼 앱」, 종류는 「AI·API」, 맡은 일꾼이 없으면 「맡은 일꾼 없음」) — 앱을 고른다는 것이 보이게 한다. 목록이 길면 칸 안에서 스크롤한다. 그 아래 **「직접 적기 (목록에 없는 앱 id, 한 줄에 하나)」** 글 칸 — 아직 일꾼이 올리지 않아 목록에 없는 앱(새 일꾼이 처음 올릴 정의·manifest)을 적는다(도움말 「서비스 앱 id나 외부 확장 id — 영문 소문자·숫자·.·-. 일꾼이 뜰 때 그 앱을 올리면 연결 앱에 나타납니다.」). 맡는 토픽은 체크한 것과 적은 것을 합친 것이고 하나 이상이어야 한다. 연결 앱을 못 읽으면 목록 자리에 「연결 앱 목록을 읽지 못했습니다 — 직접 적으세요.」만 보이고 직접 적기는 그대로 된다. 툴팁·도움말: 「다음 가져가기부터 반영됩니다. 빠진 토픽의 일감은 이 일꾼이 더 가져가지 않고, 맡을 일꾼이 없어진 외부 확장은 등록이 해제됩니다.」
- **「토큰 새로 발급...」** → 확인 창(기본 「취소」): 「지금 토큰은 바로 거부됩니다 — 일꾼은 새 토큰을 넣고 다시 띄울 때까지 일감을 가져가지 못합니다. 새 토큰은 한 번만 보입니다.」 → 「새로 발급」을 누르면 같은 창이 토큰을 보인다.
- **「삭제...」** → 확인 창(기본 「취소」): 「이 일꾼의 토큰을 폐기하고 목록에서 지웁니다. 쥐고 있던 일감은 잠금이 풀리면 다시 줄에 섭니다. 맡을 일꾼이 없어진 외부 확장은 등록이 해제됩니다. 되돌릴 수 없습니다.」 일꾼 폴더에 그 파일이 남아 있어도 다시 들어오지 않는다(토큰이 폐기됐다).
- **토큰 창** — 토큰 원문 한 줄(고정폭 글자, 골라 복사할 수 있게)과 「복사」, 그 아래 「이 창을 닫으면 다시 볼 수 없습니다. 일꾼 설정의 Center 토큰에 넣으세요.」(주소는 제목 오른쪽에 있다) 「닫기」만 있다. 「복사」가 안 되는 브라우저(https가 아닌 주소)면 「글자를 골라 복사하세요」라고 말한다(CON-00과 같다). **원문은 콘솔 서버가 Center 답에서 받아 그 창에만 넘기고 어디에도 남기지 않는다** — 브라우저가 Center를 부르지 않는다.

## CON-18 연결 앱 (신규)

메뉴 「연결 › 연결 앱」. BPM 프로세스가 부르는 **바깥 앱 — 앱 하나 = 토픽 하나 —과 그 작업**을 보는 카탈로그다 ([ADR-0138](../../../docs/decisions/0138-console-app-catalog.md), Camunda의 커넥터 목록과 같은 결). 구현은 둘이다: **외부 정의**(C13 `tier: external` — HTTP 어댑터 정의, Center가 서명한다)와 **일꾼 앱**(C11 manifest — 일꾼이 코드로 처리한다. AI·사이트 처리기·모의 앱). 원본이 **콘솔**인 외부 정의는 Center 관리자가 여기서 만들고 고친다(아래 §만들기·고치기, [ADR-0141](../../../docs/decisions/0141-adapter-definitions-are-edited-in-the-console.md)). 원본이 **일꾼**인 것은 **보기만 한다** — 정의·manifest는 맡은 일꾼이 뜰 때 올린다(C15, [ADR-0122](../../../docs/decisions/0122-consumer-folder.md)). 원본이 둘이라는 말은 제목 옆 「?」 툴팁에만 둔다. 일꾼 폴더·키·기여 자원은 여기 없다(ADR-0128).

> 상태: **돈다** (`app/connected-apps`, `app/connected-apps/[appId]`).

### 목록 (`/connected-apps`)

재료: C7 `GET /resources?type=extension`(`tier: external`)·`?type=service_app`(외부 정의가 없는 토픽 — C7이 이미 가른다), C15 `GET /consumers`(맡은 일꾼)·`GET /external-topics`.

```
+----------------------------------------------------------------+
| [F] search ________________                     reset | narrow  |
+----------------------------------------------------------------+
| [G] > app_group name                         apps n             |
|     name (id) | impl | kind | ver | worker | ops | status | ... |
| [G] > other                                                     |
+----------------------------------------------------------------+
```

| 영역 | 내용 |
| --- | --- |
| [F] 찾기 | 「찾기」 글 칸 하나 — 앱 이름·id·`keywords`에 든 글(대소문자 무시). `?q=`, JS 없이. 「초기화」·「좁히기」 |
| [G] 앱 묶음 | 앱의 `app_group`(C13 정의·C11 manifest)마다 접고 펴는 칸(`<details>`, 처음엔 펼침). 머리: 묶음 이름 · 「앱 n」. 묶음 이름 순, 묶음 없는 앱은 맨 뒤 「기타」. **어느 앱에도 묶음이 없으면 묶지 않고 한 표** |

열:

| 열 | 내용 |
| --- | --- |
| 「이름」 | `name`, 아래에 작게 `id`(고정폭). 누르면 상세 |
| 「구현」 | 「외부 정의」(C13) / 「일꾼 앱」(C11). 툴팁: 「외부 정의 — 일꾼이 HTTP로 바깥 앱을 부릅니다」 / 「일꾼 앱 — 일꾼이 코드로 처리합니다」 |
| 「종류」 | 작업들의 `kind`를 겹치지 않게 — 「AI」·「API」·「RPA」(가운뎃점으로 잇는다). 외부 정의는 「API」 |
| 「버전」 | 정의·manifest의 `version` |
| 「맡은 일꾼」 | 일꾼 이름(여럿이면 쉼표). 없으면 「—」 |
| 「작업」 | 작업 수 |
| 「상태」 | 토픽 상태 — `ok` 「정상」 / `unreachable` 「응답 없음」 / `unknown` 「확인 전」(`status_map` 「서비스 앱」). 툴팁에 까닭 |
| 「기다리는 일감」 | 그 토픽의 `waiting` |
| 「마지막으로 가져간 때」 | 연도까지. 없으면 「—」 |

빈 상태: 「연결된 앱이 없습니다.」 + 「앱은 그것을 맡은 일꾼이 뜰 때 올립니다.」 찾기에 걸리는 것이 없으면 「「<글>」에 맞는 앱이 없습니다.」

### 상세 (`/connected-apps/<id>`)

```
+----------------------------------------------------------------+
| [H] name   id@version   impl                         [?]       |
|     publisher | worker | address | auth | status                |
+----------------------------------------------------------------+
| [F] search ________________                     reset | narrow  |
+----------------------------------------------------------------+
| [O] operations  n / total                                       |
|  v group name (n)              | wait | work | 7d ok | 7d fail |
|    |- name (desc) | kind | modes | idem | wait | work | ...     |
|    |    > input / output                                       |
+----------------------------------------------------------------+
```

| 영역 | 내용 |
| --- | --- |
| [H] 머리 | 이름(크게)과 `id@version`(작게), 「구현」. 아래 한 줄: 만든 곳(외부 정의의 `publisher`) · 맡은 일꾼 · **쓰는 주소**와 인증(외부 정의만 — 일꾼 앱은 주소를 일꾼만 안다) · 상태. 외부 정의의 해시는 `id@version`의 툴팁 |
| [F] 찾기 | 작업 이름·설명·`keywords`에 든 글. `?q=`, JS 없이 |
| [O] 작업 | 제목 「작업 <보이는 수> / <전체 수>」. 작업 묶음(`groups`)이 있으면 **묶음 → 작업 트리 격자**, 없으면 작업만 같은 격자 |

**「쓰는 주소」** (외부 정의만) — 외부 앱 주소는 **일꾼 설정이 정한다**(ADR-0102 — 콘솔에서 바꾸지 않는다). 일꾼이 정의를 올릴 때 지금 쓰는 주소를 함께 올리고(C15 `address`) 콘솔은 그것을 보인다.

| 경우 | 보이는 것 |
| --- | --- |
| 일꾼이 올린 주소 = 정의의 `base_url` | 주소 + 작게 「정의 기본값」 |
| 다르다 | 주소 + 작게 「일꾼 설정」. 툴팁 「정의 기본값: <정의 주소>」 |
| 시험 주소(`test_base_url`)가 있다 | 툴팁에 「시험 일감: <주소>」를 더한다 |
| 일꾼이 주소를 올리지 않았다(옛 일꾼·일꾼 없음) | 정의의 `base_url` + 작게 「정의 기본값」 |

주소 옆 「?」 툴팁: 「주소는 맡은 일꾼의 설정 `BPM_ADAPTER__EXT__<확장 id 대문자>__BASE_URL`에서 바꿉니다 (정의의 허용 호스트 안에서만). 바꾼 뒤 일꾼을 다시 띄우면 여기 보입니다.」

**작업 묶음 — 트리** (C13 `adapter.groups`·C11 `groups`, 작업의 `group`):

```
+----------------------------------------------------------------+
| op           | kind | modes | idem | wait | work | 7d ok | 7d fail | last |
| v group A (8)                | 0 | 0 | 150 | 3 | ... |
|   |- name (desc)  | API | ... | 0 | 0 | 27 | 2 | ... |
|   `- name (desc)  | AI  | ... |                       |
| > group B (13)               | 0 | 0 | 98  | 0 | ... |
+----------------------------------------------------------------+
```

- **표 하나에 머리 줄 하나**이고 묶음과 작업이 **같은 열**에 맞춰 선다(트리 격자). 묶음 줄이 부모, 그 아래 작업이 자식이다.
- 묶음 줄: 「▸/▾」 + 묶음 이름 + 「(작업 수)」, 일감 열에는 **자식의 합**(기다림·처리 중·7일 끝남·7일 실패)과 가장 늦은 「마지막으로 끝난 때」. 실패 합이 1 이상이면 경고색. 묶음 설명은 이름의 툴팁. 누르면 접고 편다(`<details>`, JS 없이).
- 작업 줄은 들여 쓰고 왼쪽에 **가는 연결선**(세로선 + 가로 가지)을 둔다 — 어느 묶음의 자식인지 보이게.
- 순서는 `groups`에 적힌 순서, 묶음 안 작업은 정의 순서. 묶음 없는 작업은 맨 뒤 「기타」.
- **기다림·실패가 있는 묶음은 펼쳐서** 열고 나머지는 접혀 있다. 「찾기」를 하면 걸린 작업이 있는 묶음만 펼쳐 보인다.
- 앱에 `groups`가 없으면 묶음 줄 없이 작업만 같은 격자로 선다 — 「기타」 하나만 보이지 않게.
- 폭이 좁으면 격자가 가로로 넘친다(표 안에서 가로 스크롤 — 쪽 전체는 넘치지 않는다).

[O] 열 (묶음 줄은 같은 열에 합을 보인다):

| 열 | 내용 |
| --- | --- |
| 「작업」 | **이름(고정폭) 먼저**, 아래에 설명(`description`, 작게·흐리게) — 작업은 API라 부르는 이름이 곧 식별자다(그림의 `operation`과 같은 글). 설명이 없으면 이름만. 누르면 그 자리에서 펼쳐(`<details>`) 「입력」·「출력」 칸 표(칸 이름 / 타입 / 필수 / 설명 — `input_schema`·`output_schema`의 `properties`), 「요청」(외부 정의의 `METHOD path`), 「키워드」를 보인다. 칸이 없으면 「칸 없음」 |
| 「종류」 | `kind` — 「AI」/「API」/「RPA」, 모르는 값은 그대로 |
| 「수행 모드」 | `modes` — 「자율」·「결정」 |
| 「다시 불러도 됨」 | **외부 정의만** — `idempotent` 「예」/「아니오」. 툴팁: 「아니오면 결과를 모르는 실패를 자동으로 다시 부르지 않습니다」. 일꾼 앱에는 열이 없다(C11에 그 칸이 없다) |
| 「기다림」 / 「처리 중」 | C15 `TopicOperationStatus.waiting`·`working`. 일감이 없었던 작업은 「0」 |
| 「7일 끝남」 / 「7일 실패」 | `completed_recent`·`failed_recent`. 실패가 1 이상이면 경고색 글자, 툴팁에 마지막 오류 코드 |
| 「마지막으로 끝난 때」 | `last_finished_at`, 연도까지. 없으면 「—」 |

- 찾기에 걸리는 것이 없으면 표 대신 「「<글>」에 맞는 작업이 없습니다.」
- 집계(C15)를 읽지 못하면 일감 열 다섯을 「—」로 두고 표 위에 「일감 집계를 읽지 못했습니다」. 작업은 그대로 그린다.
- 없는 id면 「연결된 앱이 아닙니다: <id>」와 목록으로 가는 링크.

### 만들기·고치기 — HTTP 어댑터 앱 ([ADR-0141](../../../docs/decisions/0141-adapter-definitions-are-edited-in-the-console.md))

> 상태: **돈다** (`app/connected-apps/editor.tsx`, 정의 짓기는 `lib/adapter-editor.ts`) — 작업은 폼 + JSON 탭, 시험 호출은 저장한 판으로만, 내리기를 둔다(사용자 결정 2026-11-09). 확인 창·시험 창은 편집 창 **위에 겹쳐** 뜬다(편집 창을 닫지 않는다 — 고친 것과 Center의 사유가 남는다).

**원본이 콘솔인 외부 정의만** 만들고 고친다. 일꾼이 올린 정의(원본 「일꾼」)와 일꾼 앱(C11)은 지금처럼 보기만 한다. Center 관리자만 단추가 보인다.

**목록에 더하는 것**

```
+----------------------------------------------------------------+
| title  [?]                                   [New app...]       |
| [F] search ...                                                  |
|     name (id) | impl | source | kind | ver | worker | ... | [...]|
+----------------------------------------------------------------+
```

| 영역 | 내용 |
| --- | --- |
| 「새 연결 앱...」 | 제목 줄 오른쪽. 만들기 창을 연다 |
| 「원본」 열 | 「콘솔」 / 「일꾼」. 일꾼 앱은 「일꾼」. 툴팁: 「콘솔 — 여기서 고칩니다」 / 「일꾼 — 맡은 일꾼이 뜰 때 올립니다」 |
| 줄 끝 「...」 | 원본 「콘솔」인 줄만 — 「편집...」·「시험 호출...」·「내리기...」 |

**만들기 창** (「새 연결 앱」) — 앱 정보만 받는다. 작업은 만든 뒤 상세에서 더한다.

| 칸 | 내용 |
| --- | --- |
| 「앱 id」 | 영문 소문자로 시작, 소문자·숫자·`-`, 2~50자(C13 `ExtensionId`). 토픽이 된다 — 만든 뒤 바꿀 수 없다(BPM 그림이 부른다) |
| 「이름」·「설명」 | 화면에 보일 글 |
| 「앱 묶음」 | 있는 묶음에서 고르거나 새로 적는다(`app_group`) |
| 「주소」·「시험 주소」 | `base_url`·`test_base_url`. https만. 허용 호스트는 주소에서 채우고 「더 보기」에서 더한다 |
| 「인증」 | 「없음」 / 「Bearer 키」 / 「헤더 키」 — 키 값은 받지 않는다. 툴팁: 「키는 맡은 일꾼의 설정 `BPM_ADAPTER__EXT__<id>__KEY`에 넣습니다」 |
| 「맡을 일꾼」 | 일꾼을 고른다(CON-17과 같은 체크 목록). 고른 일꾼의 토픽에 이 id가 더해진다 |

「만들기」를 누르면 판 `0.1.0`, 작업 없이 등록하고 상세로 간다. 작업이 없는 앱은 목록에서 「작업 0」이다.

**상세에 더하는 것**

```
+----------------------------------------------------------------+
| [H] name   id@version   impl   source         [Edit...] [...]  |
+----------------------------------------------------------------+
| [O] operations  n / total                     [Add operation...]|
|  v group name (n)                                               |
|    |- name (desc) | kind | ...                          [...]   |
+----------------------------------------------------------------+
```

| 영역 | 내용 |
| --- | --- |
| [H] 「편집...」 | 만들기 창과 같은 칸(앱 id는 읽기 전용) |
| [H] 「...」 | 「시험 호출...」·「판 기록」·「내리기...」 |
| [O] 「작업 더하기...」 | 작업 창을 연다 |
| 작업 줄 「...」 | 「편집...」·「복제...」·「시험 호출...」·「지우기...」 |

**작업 창** — 칸 넷은 폼, 나머지 넷은 JSON 칸이다(모양이 자유로워 폼으로 담기 어렵다).

```
+----------------------------------------------------------------+
| Operation                                                      |
|  name ______  group [v]  method [POST v]  path /v2/____         |
|  description ________________________   [x] idempotent         |
|  [Input] [Output] [Request body] [Response]      <- tabs (JSON) |
|  +----------------------------------------------------------+  |
|  | { ... }                                                  |  |
|  +----------------------------------------------------------+  |
|  errors (E3, per field)                                        |
|                                      [Cancel] [Test...] [Save] |
+----------------------------------------------------------------+
```

| 칸 | 내용 |
| --- | --- |
| 「이름」 | 그림의 `operation`과 같은 글. 고치면 그 이름을 부르던 그림이 깨진다 — 바꾸면 경고 |
| 「묶음」·「메서드」·「경로」·「설명」·「다시 불러도 됨」 | `group`·`request.method`·`request.path`·`description`·`idempotent` |
| 「입력」·「출력」 탭 | `input_schema`·`output_schema` JSON |
| 「요청 본문」 탭 | `request.body`(·`query`·`headers`) — `{{input.<칸>}}` 템플릿 |
| 「응답」 탭 | `response.output`(제한 JSONPath)·`error_when` |
| 오류 | 저장하면 Center가 E3로 보고 칸별 사유를 그 탭 아래 보인다. 창은 닫지 않는다 |

**저장 = 새 판** — 앱 정보·작업 하나를 저장할 때마다 Center가 판의 끝자리를 올리고 서명한다. 저장 전에 확인 창:

| 경우 | 확인 창 |
| --- | --- |
| 이 앱을 고정한 배포가 없다 | 「<id> <옛 판> → <새 판>으로 올립니다. 다음 일감부터 새 정의로 부릅니다.」 |
| 고정한 배포가 있다 | 위 글 + 「이 판을 고정한 배포 n개는 옛 판으로 돕니다 — 새 판을 쓰려면 다시 승인·배포합니다.」 + 그 배포 목록 |

**시험 호출** — 작업 하나와 입력 JSON을 받아 Center가 `origin: test` 일감을 올리고 맡은 일꾼이 **시험 주소**로 부른다. 결과(출력 또는 오류 코드·사유)를 창 안에 보인다. 맡은 일꾼이 없거나 붙어 있지 않으면 단추가 꺼지고 툴팁으로 까닭을 말한다. **저장한 판으로만 시험한다** — 작업 창의 「시험...」은 저장하지 않은 고침이 있으면 꺼지고 툴팁 「저장한 뒤 시험합니다」(일꾼은 서명된 정의만 받는다).

**내리기** — 그 앱의 판을 모두 철회한다(`extension_revoke`). 그 앱을 부르는 배포가 있으면 확인 창에 목록과 「그 BPM 프로세스는 시작하지 못합니다」를 보인다. 되살리지 않는다 — 같은 id로 다시 만들면 더 높은 판으로 시작한다.
