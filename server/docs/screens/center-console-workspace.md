# Center 콘솔 — 작업공간 (CON-20)

[center-console.md](center-console.md)의 나머지다 — **설계자가 브라우저에서 BPM 프로세스를 만들고 돌려 보는 화면**
([ADR-0143](../../../docs/decisions/0143-design-happens-in-the-console.md)). 재료는 **C17**이고, 캔버스는
`@bpm/bpmn-canvas`(bpmn-js)다. 공통 틀·표기 규칙은 그 파일과 [06-screens.md](../../../docs/06-screens.md)를 따른다.

데스크톱 Studio의 **STU-01·02·04·05·06·07·08·09·12를 대신한다.** 없어지는 것이 아니라 **자리를 옮기는 것**이라,
아래 표마다 「STU-NN이 하던 일」을 적어 둔다 — 옮기다 흘린 것이 있으면 그 줄이 비어 보인다.

> 상태: **「설계」·「시험 실행」 탭이 돈다** (M11 조각 4a~4e). CON-20a 홈, 탐색기·캔버스·상세
> 패널(`bpm:*` 폼은 C14 모델에서 생성), 결정표 격자, 케이스 편집기, 아래 탭 「변수」·「로그」,
> 그리고 돌려 보기(케이스·수행 모드·목록·로그·노드 색·변수·중지)까지다.
> **아직 없는 것**: 「정보」 탭·실행 전 검사·배포 후보로 만들기·공유 BPM 프로세스 설치·리소스에서
> 노드 만들기(4f) · 이벤트 칸 폼·결재 답 폼(4f) · 패널 접기.
> 탭 셋은 [ADR-0147](../../../docs/decisions/0147-workspace-has-three-tabs.md)이다.
> 코드보다 이 문서를 먼저 고친다 ([ADR-0002](../../../docs/decisions/0002-docs-first-and-adr.md)).

> **화면 글에서는 「BPM 프로세스」를 「프로세스」로 쓴다** ([ADR-0121](../../../docs/decisions/0121-center-console-says-process.md)) —
> 작업공간 안에서도 같다. 이 문서의 설명 글만 뜻을 분명히 하려고 「BPM 프로세스」를 그대로 쓴다.

## CON-20a 작업공간 홈

메뉴 레일 맨 위(「설계」), 주소 `/workspaces`. **설계 권한이 있는 계정의 첫 화면**이다
([ADR-0145](../../../docs/decisions/0145-console-is-workspace-shaped.md) §2) — 보기 전용 계정에게는 레일에 이 자리가
없고 첫 화면이 운영 현황이다.

```
+----------------------------------------------------------------+
| [H] title                      [Import] [New workspace]        |
| [F] filter card: search                                        |
| [G] workspace cards (grid)                                     |
+----------------------------------------------------------------+
```

| 영역 | 내용 |
| --- | --- |
| [H] 머리 띠 | 제목 「작업공간」. 오른쪽에 「파일에서 가져오기」(`.bpmn` 하나 또는 옛 작업 폴더 zip — C17 `POST …/import`)와 **주 단추** 「새 작업공간」 |
| [F] 필터 | 「이름으로 찾기」 한 칸 (C17 `?q=`). 회사가 정해진 계정은 **제 회사 것만** 보이므로 회사 칸을 두지 않는다 (C16) |
| [G] 카드 | 작업공간마다 카드 하나 — 이름(굵게) · 설명 한 줄 · 「v<판>」 · 「<마지막 손댄 때> · <누가>」 · 업무 자리(「<회사> › <부서> › <직원>」, 없으면 안 보인다). 누르면 CON-20b. 빈 상태: 「작업공간이 없습니다. 「새 작업공간」으로 만들거나 「파일에서 가져오기」로 들이세요.」(U12) |

- 카드에 **배포 상태를 적지 않는다** — 작업공간과 배포된 패키지는 **다른 것**이다 (C17: 지워도 패키지는 그대로다).
  지은 뒤의 일은 CON-06(공통 패키지)·CON-15(배포)가 말한다. 카드가 「배포됨」이라 말하면 **작업공간을 고치면
  현장이 바뀌는 것처럼** 읽힌다.
- 「새 작업공간」은 작은 창 하나다: 「id」(`^[a-z0-9][a-z0-9._-]{0,63}$` — C1 매니페스트 id와 같은 규칙이라 그 자리에
  적는다) · 「이름」 · 「판」(기본 `0.1.0`) · 「설명」. 만들면 바로 CON-20b로 간다. 같은 id가 있으면 그 자리에서
  「이미 있는 id입니다」(C17 409 `exists`).
- **STU-02(BPM 프로세스 탐색기)·STU-05(새 BPM 프로세스)가 하던 일이다.** 그룹(폴더)은 **없앤다** — 작업 폴더가
  서버에 살아 「어느 폴더에서 열었나」가 사라졌다.

## CON-20b 작업공간

주소 `/workspaces/<id>`. **본문을 가득 쓴다** — 공통 틀의 본문 패딩·흰 띠를 두지 않는다 (ADR-0145 §3).

```
+----+-----------------------------------------------------------------+
| [R]| [H] crumb + tabs                            [Check] [Run] [Build]|
| ai +-----------------------------------------------------------------+
| l  | [E]     | [C] canvas                           | [P] detail      |
|    | files   |        (palette)          (minimap)   |     panel       |
|    |         |                                      |                 |
|    |---------+--------------------------------------+-----------------|
|    | [L] bottom tabs: log / check / variables                         |
+----+-----------------------------------------------------------------+
```

| 영역 | 내용 | 대신하는 것 |
| --- | --- | --- |
| [R] 레일 | 전역 아이콘 레일 — 그대로 있다. **언제든 운영으로 나간다** (ADR-0145 §1) | — |
| [H] 머리 띠 | 「작업공간 › <이름> › <탭>」 한 줄과 탭. 오른쪽에 「실행 전 검사」·「시험 실행...」·「배포 후보로 만들기」. 저장 안 한 변경이 있으면 이름 끝에 「 *」 | STU-01 [T]·[M]·[B] |
| [E] 탐색기 | 작업 폴더의 파일 (C17 `GET …/files`) — `process/`(`.bpmn`·`.dmn`) · `cases/` · `libs/`(받아 둔 것, 자물쇠 아이콘) · `memory/`. **진입 정의는 굵게.** 접힌다 | STU-02 |
| [C] 캔버스 | `@bpm/bpmn-canvas` 모델러. 바탕은 **연회색**, 요소가 흰 면. 팔레트는 캔버스 안 왼쪽 위(bpmn-js의 것), 오른쪽 위에 미니맵. 그림 좌표가 없는 정의는 **열 때 자동 배치**하고 그러면 「저장 안 한 변경」이 된다 ([ADR-0088](../../../docs/decisions/0088-auto-layout-for-definitions-without-di.md)) | STU-01 [C] |
| [P] 상세 패널 | **고른 것 하나만** 그린다 (STU-04). 아무것도 고르지 않았으면 그 BPM 프로세스 자체(이름·판·업무 자리·진입 정의 — C17 `PATCH`). 접힌다 | STU-04·STU-06 |
| [L] 아래 탭 | 「로그」(시험 실행이 낸 줄) · 「검사」(실행 전 검사 결과) · 「변수」(입력·출력 정의, 시험 실행 중에는 「지금 값」이 붙는다). 접힌다 | STU-01 [L] |

- **쓰기 단추는 관리자에게만** 보인다 — 「보기 전용」 계정은 캔버스를 **뷰어로** 연다(정말 못 고치는 배포본,
  [ADR-0051](../../../docs/decisions/0051-shared-process-conveniences.md)). 팔레트를 가린 편집기를 「읽기 전용」이라
  부르지 않는다.
- `libs/`의 파일을 누르면 **뷰어로** 열린다 — 받아 둔 것은 편집 대상이 아니다 (C17 경로 규칙).
- 상태 줄([S])을 두지 않는다 — 웹에는 창틀이 없고, 할 말은 머리 띠와 아래 탭이 한다.

**탭은 셋이다** — 「설계」 · 「시험 실행」 · 「정보」 ([ADR-0147](../../../docs/decisions/0147-workspace-has-three-tabs.md)).
탐색기가 파일을 고르면 가운데가 그에 맞춰 바뀌므로 「결정표」·「케이스」를 탭으로 두면 **같은 고르기가 두 자리에**
생긴다. 「검사」는 아래 탭이다 — 지금 보고 있는 그림에 대한 말이라 캔버스와 함께 보여야 한다.

### 「설계」 탭 — 가운데는 고른 파일이 정한다

| 고른 것 | 가운데 | 상세 패널 | 대신하는 것 |
| --- | --- | --- | --- |
| `.bpmn` | BPMN 캔버스 | 고른 요소의 속성 (`bpm:*` 요소마다 폼 — C14 모델에서 짓는다) | STU-04·STU-14 |
| `.dmn` | 결정표 격자 | 그 표의 입력·출력 열 | STU-04a |
| `.cases.json` | 케이스 목록 + 고른 케이스 | 쓰지 않는다 (케이스가 본문을 다 쓴다) | STU-07 |
| `process.json` | 없음 (탐색기에서 고를 수 없다) | — | — |

- **결정표는 캔버스 밖이다** ([ADR-0109](../../../docs/decisions/0109-studio-writes-decision-tables.md)) — 편집기가
  `.dmn`을 직접 쓴다. 그림은 **캔버스(bpmn-js)를 거쳐서만** 고친다 (C17 — 실행 취소 한 걸음·DI 순서·모르는 요소 보존).
- 리소스에서 노드를 만드는 길(STU-03 「캔버스에 추가」·끌어다 놓기)은 **4f**에서 온다. 그때까지 캔버스 팔레트와
  상세 패널로 만든다.
- **결정표는 Center가 읽고 쓴다** ([ADR-0148](../../../docs/decisions/0148-center-reads-and-writes-decision-tables.md)) —
  브라우저는 격자만 다루고 DMN을 해석하지 않는다. 엔진이 거부할 칸은 저장되지 않고(422 `bad_table`) 그 사유가
  격자 위에 뜬다. 경고(겹친 입력 이름·빈 규칙 줄)는 막지 않는다.
- **케이스는 값마다 갈래를 고른다** (글·수·참거짓·JSON) — JSON 글상자 하나로 두면 `"3"`과 `3`을 사람이 가려
  적어야 한다 (STU-07이 지키던 규칙이다). 결재 답·맡기기 결과·메시지는 아직 JSON으로 적는다 (4f).
- **아래 탭 「변수」**는 그림의 `bpm:process`(입력·출력 선언)다 — 작업공간 정보가 아니라 **캔버스 쪽**이고,
  「적용」은 그 요소를 통째로 캔버스에 넘겨 **실행 취소 한 걸음**이 된다.

### 저장 — 「저장」 단추다 (자동 저장이 아니다)

`Ctrl+S`와 머리 띠의 「저장」, 떠날 때 묻기(U11). C17이 `If-Match`로 덮어쓰기를 막고 **두 사람이 같은 파일을
열면 나중 사람이 409 `stale`**을 받는데, 자동 저장이면 그 충돌이 **타자 치는 중에** 뜬다.

충돌 창은 이렇게 말한다: 「다른 사람이 먼저 저장했습니다. 「새로 읽기」를 하면 지금 편집이 사라집니다.」 —
단추는 「새로 읽기」 · 「다른 이름으로 저장」 · 「머무르기」(기본)다. **합치지 않는다** (C17 — 합치면 XML이 깨진다).

### 「시험 실행」 탭

| 영역 | 내용 |
| --- | --- |
| 머리 | 「시험 실행...」을 누르면 작은 창: 「케이스」(없으면 「비교 안 함」) · 「수행 모드」(자율 수행 / 결정 수행). C17 `POST …/test-runs` |
| 목록 | 최근 것부터 — 실행 id(`test_…`) / 상태 / 판정 / 케이스 / 수행 모드 / 시작 / 소요 / 「배운 것 <n>개」 |
| 상세 | 고른 실행의 **로그**(아래 탭 「로그」와 같은 줄) · **노드 색**(캔버스에 그대로 입힌다 — `node_states`) · **변수**(업무 값이라 **키만** 보이고 펼쳐야 값이다 — U10) |

- 판정은 셋이 아니라 **다섯**이다 — 「통과」·「실패」·「비교 안 함」·「중지」·「오류」 (C17 `VERDICT_*`, U6).
  **도는 중에는 판정이 비어 있다** — 끝난 줄로 읽히지 않게.
- 실행 중에는 「시험 실행...」이 **「중지」**가 된다 (U5, C17 `DELETE …/test-runs/{run_id}`).
- **결재·확인은 여기서 답하지 않는다** — Center 결재함(CON-04)으로 간다 (C6·C17). 케이스가 답을 적어 두었으면
  실행기가 그 자리에서 답하므로 결재함에 오지 않는다. 목록에서 운영과 가르는 것은 **실행 id**(`test_`)다.
- 시험 실행은 **작업 지시 목록(CON-05)에 없다** (C17) — 설계자가 돌려 보는 것이라 운영자가 읽을 것이 없다.
- STU-08(실행 대화상자)·STU-09(실행 표시와 결과)가 하던 일이다.
- **케이스는 진입 정의 옆의 파일에서 온다** (`cases/<진입 정의 이름>.cases.json`) — 엔진이 그 자리만
  보기 때문이다 (`core.testrun.runner`의 `read_cases`). 다른 정의의 케이스를 목록에 올리면 돌릴 때
  「케이스가 없다」가 된다.
- **도는 동안 콘솔이 되묻는다** (1.5초마다 `GET …/test-runs/{run_id}`) — 실행기가 진행을 올리는 길이
  `PUT …/test-runs/{run_id}` 하나라 콘솔로 밀어 주는 길이 없다. 끝나면 묻기를 멈춘다.
- **로그와 노드 색은 「설계」 탭에도 간다** — 로그는 아래 탭 「로그」, 노드 색은 캔버스에 그대로다.
  돌려 본 사람이 탭을 오가며 고치는 자리라, 결과를 한 탭에 가두지 않는다.
- **변수는 접어 둔다** — 펼쳐야 값이 보인다 (U10, 업무 값이다).
- **중지는 판정하지 않는다** — 판정이 「중지」이고 통과·실패가 아니다 (C17).

### 「정보」 탭

이름 · 판 · 설명 · 업무 자리(회사 › 부서 › 직원) · 진입 정의 · **받아 둔 공유 BPM 프로세스**(`libs/` — 설치·제거,
C17 `POST …/libs`). STU-06·STU-11이 하던 일이다.

### 실행 전 검사

머리 띠의 「실행 전 검사」를 누르면 아래 탭 「검사」가 열리고 결과가 거기 쌓인다 (C17 `POST …/check`).

- **오류만 돌리기를 막고 경고는 보인다.** 줄마다 「<규칙> — <무엇이> — <어디서>」이고 노드를 가리키는 줄은
  누르면 캔버스의 그 노드를 고른다.
- 담아 둔 결과를 그대로 주면(`cached`) 「<시각>에 검사한 결과입니다」 한 줄을 붙이고 「다시 검사」를 둔다.
- 맡을 서버 실행기가 없으면(503 `no_runner`) 「검사할 서버 실행기가 없습니다 — <까닭>」. 담아 둔 결과가 있으면
  그것을 보이며 **언제 것인지 말한다** (U8 — 모르는 것을 추측하지 않는다).

### 배포 후보로 만들기

머리 띠의 「배포 후보로 만들기」 (C17 `POST …/package`). 작은 창이 **무엇을 짓는지** 묻는다: 「프로세스」 또는
「공유 프로세스」(`process_lib`).

- 짓는 것은 **서버 실행기**다 — 누르면 **202**로 받고 「짓는 중입니다」가 머리 띠에 뜬다. 끝나면 「<패키지 id> v<판>을
  후보로 올렸습니다」와 CON-06(공통 패키지)으로 가는 링크.
- **올린 것은 후보다** — 승인·배포는 바뀌지 않는다 (C2·CON-06·CON-15). 「콘솔에서 설계한 것이 저절로 현장에 가지
  않는다」를 그 자리에 한 줄로 적는다.
- 짓다 실패하면 사유 한 줄 먼저, 상세는 그 아래 (U13).
- 진입 정의가 없으면(422 `no_entry`) 「진입 정의를 먼저 고르세요 — 「정보」 탭」.
- STU-12(공유 BPM 프로세스 내보내기·올리기)가 하던 일이다. **「내보내기」(파일로 저장)는 없앤다** — 작업 폴더가
  서버에 살고 받는 쪽도 Center다.

**「내 PC로 내려받기」를 두지 않는다.** 데스크톱 Studio는 zip을 만들어 사람이 날랐는데, 이제 짓는 것도 받는 것도
서버 안이라 **내려받을 까닭이 없다.** 작업공간을 들이는 길은 「파일에서 가져오기」 하나다. (저장소 밖으로 꺼내야
할 일이 정말 있으면 그때 `GET …/bundle`을 사람 길로도 연다 — 지금은 실행기 키 전용이다.)

## 오류

| 언제 | 보이는 것 |
| --- | --- |
| 남의 회사 작업공간 (404) | 「작업공간을 찾을 수 없습니다」 — **있다는 것조차 알리지 않는다** (C16) |
| 보기 전용 계정이 고치려 함 (403) | 쓰기 단추가 **아예 없다**. 그래도 403이 오면 「이 계정은 설계할 수 없습니다」 |
| 경로 규칙 위반 (422 `bad_path`) | 편집기가 만들지 않는 경로다 — 「저장할 수 없는 경로입니다: <경로>」 |
| 진입 정의를 지우려 함 (409 `entry_in_use`) | 「진입 정의라 지울 수 없습니다 — 「정보」 탭에서 다른 정의를 진입으로 고른 뒤 지우세요」 |
| Center에 닿지 못함 | 공통 틀과 같다 — 본문 대신 한 줄 |
