# Center 콘솔 — 작업공간 (CON-20)

[center-console.md](center-console.md)의 나머지다 — **저작하는 사람가 브라우저에서 BPM 프로세스를 만들고 돌려 보는 화면**
([ADR-0143](../../../docs/decisions/0143-design-happens-in-the-console.md)). 재료는 **C17**이고, 캔버스는
`@bpm/bpmn-canvas`(bpmn-js)다. 공통 틀·표기 규칙은 그 파일과 [06-screens.md](../../../docs/06-screens.md)를 따른다.

데스크톱 Studio의 **STU-01·02·04·05·06·07·08·09·12를 대신한다.** 없어지는 것이 아니라 **자리를 옮기는 것**이라,
아래 표마다 「STU-NN이 하던 일」을 적어 둔다 — 옮기다 흘린 것이 있으면 그 줄이 비어 보인다.

> 상태: **다 돈다** (M11 조각 4a~4f·12). CON-20a 홈, 탐색기·캔버스·상세 패널(`bpm:*` 폼은
> C14 모델에서 생성), 결정표 격자, 케이스 편집기, 아래 탭 「변수」·「검사」·「로그」, 돌려 보기
> (케이스·수행 모드·목록·로그·노드 색·변수·중지), 실행 전 검사, 배포 후보로 만들기,
> 「정보」 탭(설정·업무 자리·진입 정의·공유 프로세스 설치·제거), 그리고 **탐색기의 「리소스」 탭**
> (끌어다 놓기·「캔버스에 추가」 — [ADR-0155](../../../docs/decisions/0155-resources-are-a-tab-in-the-explorer.md))까지다.
> 탭 셋은 [ADR-0147](../../../docs/decisions/0147-workspace-has-three-tabs.md)이다.
> 코드보다 이 문서를 먼저 고친다 ([ADR-0002](../../../docs/decisions/0002-docs-first-and-adr.md)).

> **화면 글에서는 「BPM 프로세스」를 「프로세스」로 쓴다** ([ADR-0121](../../../docs/decisions/0121-center-console-says-process.md)) —
> 작업공간 안에서도 같다. 이 문서의 설명 글만 뜻을 분명히 하려고 「BPM 프로세스」를 그대로 쓴다.

## CON-20a 프로젝트 홈

메뉴 「저작 › 프로젝트」, 주소 `/workspaces`(주소는 그대로다 — 옛 링크를 깨지 않는다). **저작하는 사람이 들어오는
자리**다. 프로젝트가 프로세스(작업공간)를 묶고 회사를 정한다 ([ADR-0175](../../../docs/decisions/0175-projects-hold-processes.md)) —
한 회사가 프로젝트를 여럿 한다. 보기 전용 계정에게도 카드는 보이고 **고치는 단추만 없다**. **첫 화면은 누구에게나
대시보드**다 ([ADR-0151](../../../docs/decisions/0151-console-follows-the-lifecycle.md) §3, CON-21).

```
+----------------------------------------------------------------+
| [H] title                                      [New project]   |
| [F] filter card: search                                        |
| [G] project cards (grid)                                       |
+----------------------------------------------------------------+
```

| 영역 | 내용 |
| --- | --- |
| [H] 머리 띠 | 제목 「프로젝트」. 오른쪽에 「새 프로젝트」 — 다른 목록의 「새 …」와 같은 **옅은 단추**다 ([ADR-0168](../../../docs/decisions/0168-list-header-buttons-are-tonal.md)) |
| [F] 필터 | 「이름」 한 칸 (C17 `GET /projects?q=`, 자리 표시 「(전체)」) + 바로 옆 **아이콘 단추 ↺ 「초기화」** — CON-02와 같은 결이다 ([ADR-0171](../../../docs/decisions/0171-con-02-filter-says-what-the-table-says.md)). **치는 대로 든다** — 멈춘 뒤 0.4초에 서버에 다시 묻고 「좁히기」가 없다 ([ADR-0165](../../../docs/decisions/0165-lists-filter-as-you-go-and-page.md)). JS가 없으면 Enter |
| [G] 카드 | 프로젝트마다 카드 하나 — 이름(굵게) · 설명 한 줄 · 「프로세스 <n>」(공통 패키지가 있으면 「· 공통 <n>」) · 회사 이름 · 「최근 수정 <시각>」. 누르면 CON-20c. 빈 상태: 「프로젝트가 없습니다. 「새 프로젝트」로 만드세요.」(U12) |

- 「새 프로젝트」는 작은 창 하나다: 「id」(`^[a-z0-9][a-z0-9._-]{0,63}$`) · 「이름」 · 「회사」(고르기 — 회사가 정해진
  계정에게는 보이지 않는다, 그 계정의 회사다) · 「설명」. **회사는 만든 뒤 바뀌지 않는다** — 창의 칸 아래에 그렇게 적는다.
  만들면 바로 CON-20c로 간다. 같은 id가 있으면 그 자리에서 「이미 있는 id입니다」(C17 409 `exists`).
- 카드에 **배포 상태를 적지 않는다** — 프로세스와 배포된 패키지는 **다른 것**이다 (C17). 지은 뒤의 일은
  CON-06(공통 패키지)·CON-15(배포)가 말한다.

## CON-20c 프로젝트

주소 `/workspaces/projects/<id>`. 프로젝트 하나 — **두 칸**이다: 업무 「프로세스」와 그 프로세스들이 부르는
「공통 패키지」 ([ADR-0176](../../../docs/decisions/0176-projects-have-shared-packages.md)). **모든 프로젝트에 두 칸이
처음부터 있다** — 공통 패키지가 없어도 칸은 서고 빈 상태를 말한다. 칸은 작업공간의 종류(C17 `kind`)로 가른다.

```
+----------------------------------------------------------------+
| [H] crumb + title                                       [...] |
| [I] info card: company, description                            |
| [B] tabs: processes n | shared n             [Import] [New ..] |
| [F] filter card: search                                        |
| [T] table of the chosen tab                                    |
+----------------------------------------------------------------+
```

| 영역 | 내용 |
| --- | --- |
| [H] 머리 띠 | 지금 자리 「저작 › 프로젝트 › <이름>」, 제목은 프로젝트 이름. 오른쪽에 「⋯」(「이름·설명 고치기...」·「삭제...」) — 프로젝트 전체의 동작만 둔다 |
| [I] 정보 | 회사 · id · 설명. 한 줄 카드 (수는 탭 이름에 있다) |
| [B] 탭 | 「프로세스 <n>」 · 「공통 패키지 <n>」 — 두 칸을 **한 번에 하나**만 보인다(아래로 내려 찾지 않는다). 고른 탭은 주소 `?tab=shared`에 남는다(기본은 프로세스). 오른쪽에 **그 탭의** 「파일에서 가져오기」와 「새 프로세스」 또는 「새 공통 패키지」(옅은 단추, ADR-0168). 탭의 뜻(「배포해서 돌리는 업무 BPM 프로세스」·「이 프로젝트의 프로세스가 설치해서 부르는 공유 프로세스」)은 화면 글이 아니라 **탭의 말풍선**이다 |
| [F] 필터 | 「이름」 한 칸 + ↺ 「초기화」 — **고른 탭의 표를 거른다**. **브라우저에서 거른다** — 한 프로젝트의 프로세스는 수십 개다 ([ADR-0160](../../../docs/decisions/0160-the-filter-runs-as-you-type.md)과 같은 결) |
| [T] 표 | 콘솔의 다른 목록과 같은 `DataTable` ([ADR-0159](../../../docs/decisions/0159-con-02-is-a-table-like-the-others.md)) — 「번호」 · 「이름」(누르면 CON-20b, 아래 줄에 id를 작게) · 「판」 · **「배포」 · 「마지막 시험」 · 「검사」** · 「최근 수정」 · 「⋯」(「공통 패키지로 옮기기」·「다른 프로젝트로 옮기기...」·「삭제...」). 이름 차례. 셋째~다섯째 열은 아래 §표가 말하는 저작 상태다 ([ADR-0185](../../../docs/decisions/0185-project-table-says-where-each-process-stands.md)). 빈 상태: 「프로세스가 없습니다. 「새 프로세스」로 만들거나 「파일에서 가져오기」로 들이세요.」(U12) |
| [T] 「공통 패키지」 탭 | 표는 「프로세스」 탭과 같은 열이고(공통 패키지도 지어 올리고 시험한다) 「⋯」은 「프로세스로 옮기기」·「다른 프로젝트로 옮기기...」·「삭제...」. 빈 상태: 「공통 패키지가 없습니다. 여러 프로세스가 함께 부르는 단계는 여기서 만들어 지은 뒤 설치하세요.」 |

### 표가 말하는 저작 상태 (ADR-0185)

표 한 장에 Center 호출이 **둘**이다 — C17 `GET /projects/{id}/status`(시험·검사·지은 것)와 C5 `GET /deployments?active=true`.
작업공간마다 묻지 않는다. 셈은 콘솔 `lib/authoring.ts`의 순수 함수다(`pnpm test`).

| 열 | 보이는 말 | 셈 |
| --- | --- | --- |
| 「배포」 | 「배포 안 됨」 · 「v<판> · 같음」 · 「v<판> · 배포 뒤 고침」 · 「v<판>」 | 그 프로세스(작업공간 id 또는 지은 패키지 id)의 살아 있는 배포 중 **가장 최근에 서명한 것**의 판. 그 판을 지은 묶음이 지금 묶음과 같으면 「같음」, 다르면 「배포 뒤 고침」. 지은 기록이 없으면(지워졌거나 밖에서 올렸다) 판만 — 추측하지 않는다(U8) |
| 「마지막 시험」 | 판정(「통과」·「실패」 — `status_map` 「시험 판정」) 또는 도는 중이면 상태(「시험 실행」) + 시각. 그 실행이 지금 묶음이 아니면 「· 고치기 전」 | 가장 최근 시험 실행 하나. 없으면 「—」 |
| 「검사」 | 「검사 안 함」 · 「검사 중」 · 「흠 없음」 · 「오류 <n>」(경고가 있으면 「· 경고 <n>」) · 「검사 못 함」 | **지금 묶음의 결과만** — 고치면 「검사 안 함」으로 돌아간다(C17 `GET …/check`와 같은 규칙) |

- 요약을 못 읽어도 표는 선다 — 셋째~다섯째 열이 「—」가 된다(목록은 `…/workspaces`가 따로 준다).
- **CON-20a 카드에는 그대로 배포 상태를 적지 않는다** — 카드는 프로젝트 하나라 한 판을 말할 자리가 없다.

- 「새 프로세스」는 작은 창 하나다: 「id」(C1 매니페스트 id와 같은 규칙) · 「이름」 · 「판」(기본 `0.1.0`) · 「설명」 ·
  「그림 (선택)」(밖에서 그린 `.bpmn` 하나 — 만든 뒤 바로 넣는다, C17 `POST /workspaces/{id}/import`).
  회사는 묻지 않는다 — 프로젝트의 것이다. 만들면 바로 CON-20b로 간다. 「새 공통 패키지」는 **같은 창**이고
  제목만 「새 공통 패키지」다(C17 `kind` = `process_lib`).
- 「파일에서 가져오기」는 **옛 작업 폴더 zip**을 받는다 (C17 `POST /projects/{id}/import`) — 작업 폴더 하나든
  **여럿을 담은 zip**이든(`process.json`이 있는 폴더마다 프로세스 하나) 한 번에 든다. 하나라도 못 들이면 아무것도
  만들지 않고 까닭을 창 안에 보인다(같은 id면 그 id들). **누른 탭이** 든 것
  모두의 칸을 정한다(C17 `?kind=` — 창에서 다시 묻지 않는다, 제목이 「프로세스 가져오기」·「공통 패키지 가져오기」다) — 공통과 업무가 섞인 zip은 두 탭에서 나눠 들인다. `.bpmn` 하나는 여기서 받지 않는다 — 들일 프로세스가
  정해져야 하므로 「새 프로세스」 창의 「그림」 칸으로 넣는다.
- 가져온 zip에 받아 둔 공유 프로세스 사본(`libs/`)이 있었으면 **버리고**, 창이 닫힌 뒤 띠 하나로
  「공유 프로세스 <n>개를 설치해야 합니다」와 「설치」 단추를 보인다 — 누르면 `libs_to_install`대로 C17
  `POST …/libs`를 차례로 부른다. Center에 그 판이 없으면 그 줄만 실패로 남는다.
- 「공통 패키지로 옮기기」·「프로세스로 옮기기」는 칸만 바꾼다 (C17 `PATCH …` `kind`) — 다음에 지을 종류가 바뀌고
  이미 지은 패키지는 그대로다. 묻지 않는다(되돌리기가 같은 메뉴에 있다).
- 「다른 프로젝트로 옮기기...」는 **같은 회사의 프로젝트**만 고르기에 보인다 (C17 `PATCH …` `project`).
- 「삭제...」(프로젝트)는 **프로세스가 하나도 없을 때만** 켜진다 — 함께 지우지 않는다 (C17 409 `not_empty`).

## CON-20b 작업공간

주소 `/workspaces/<id>`. **본문을 가득 쓴다** — 공통 틀의 본문 패딩·흰 띠를 두지 않는다 (ADR-0145 §3).

```
+----+-----------------------------------------------------------------+
| [R]| [H] crumb + tabs                            [Check] [Run] [Build]|
| ai +-----------------------------------------------------------------+
| l  | [E]     | [C] canvas                           | [P] detail      |
|    | files   |        (palette)          (minimap)   |     panel       |
|    |         |                                      |                 |
|    |---------+--------------------------------------+-----------------|
|    | [L] bottom tabs: log / check / variables                         |
+----+-----------------------------------------------------------------+
```

| 영역 | 내용 | 대신하는 것 |
| --- | --- | --- |
| [A] 위 막대 | 전역 위 막대 — 그대로 있다. **언제든 운영으로 나간다** ([ADR-0152](../../../docs/decisions/0152-console-chrome-is-one-top-bar.md)) | — |
| [H] 머리 띠 | 작업 영역 위에 **떠 있는 흰 면**(아래 그림자 한 겹)이라 [E]·[C]·[P]와 갈라 선다. **두 줄이다** — 첫 줄은 지금 자리 「저작 › 프로젝트 › <프로젝트> › <이름> · v<판>」 하나(「프로젝트」는 CON-20a, 프로젝트 이름은 CON-20c로 가는 링크 — 돌아가는 길이 여기 있다), 둘째 줄은 탭과 단추다. 지금 자리와 탭을 한 줄에 세우지 않는다. 이 화면은 본문을 가득 쓰므로 **틀의 지금 자리 대신 제 머리 띠가 그 줄을 그린다** ([ADR-0152](../../../docs/decisions/0152-console-chrome-is-one-top-bar.md) §7). 둘째 줄 왼쪽은 탭 「저작」·「시험 기록」·「정보」, 오른쪽은 **생애주기 차례로** 「실행 전 검사」·「시험 실행...」·「배포 후보로 만들기...」(옅은 단추)이고, 사이를 띄운 **오른쪽 끝에 주 단추 「저장」**이다 — 저장은 편집 동작이고 Ctrl+S와 짝이며, 나머지 셋은 저장한 묶음에 하는 일이다 ([ADR-0185](../../../docs/decisions/0185-project-table-says-where-each-process-stands.md)). 저장 안 한 변경이 있으면 이름 끝에 「 *」 | STU-01 [T]·[M]·[B] |
| [E] 탐색기 | 머리는 **옅은 띠**(`bg.subtle`, [P]·아래 탭과 같다)이고 그 안에 **같은 프로젝트의 프로세스 고르기**(「프로세스」·「공통 패키지」 두 무리로 — 고르면 그 프로세스의 CON-20b로 간다 — 저장 안 한 변경이 있으면 먼저 묻는다). 그 아래 「파일」·「리소스」 고르기 (ADR-0155) — **반반 세그먼트**다. 화면을 바꾸는 머리 띠의 탭(「저작」·「시험 기록」·「정보」, 밑줄·한 단계 큰 글자)과 모양을 달리해 **패널 안의 보기 고르기**임을 말한다. 「파일」은 작업 폴더의 파일 (C17 `GET …/files`) — `process/`(`.bpmn`·`.dmn`) · `cases/` · `libs/`(받아 둔 것) · `memory/`. **진입 정의는 굵게.** 「리소스」는 부를 수 있는 것(아래 절). 접힌다. **폭은 캔버스와의 경계를 끌어 바꾼다** — 200~480(기본 256), 경계를 두 번 누르면 기본 폭, 화살표 키로 16씩. 그 브라우저에 기억한다 | STU-02·STU-03 |
| [C] 캔버스 | `@bpm/bpmn-canvas` 모델러. 바탕은 **연회색에 점 격자**(`bg.canvas`), 요소가 흰 면 — 양옆 흰 패널과 바탕이 달라 그리는 판이 따로 보인다. 팔레트는 캔버스 안 왼쪽 위(bpmn-js의 것). **왼쪽 아래에 둘러보기 도구 띠**: 「축소」·「확대」 | 「화면에 맞추기」·「실제 크기로 가운데」(열 때의 자리) | 「미니맵」(누르면 오른쪽 위에 펴진다, 처음에는 접혀 있다 — `diagram-js-minimap`, 제 여닫는 단추는 숨긴다). 단추 이름은 말풍선이다. 보기 전용 캔버스도 같은 띠다. 그림 좌표가 없는 정의는 **열 때 자동 배치**하고 그러면 「저장 안 한 변경」이 된다 ([ADR-0088](../../../docs/decisions/0088-auto-layout-for-definitions-without-di.md)) | STU-01 [C] |
| [P] 상세 패널 | 머리는 「속성」 옅은 띠. 접기는 **그 쪽으로 닫히는 패널 아이콘**이고([E]도 같다), 접힌 패널은 「펼치기」 아이콘과 세로 글자의 좁은 띠로 남는다. **고른 것 하나만** 그린다 (STU-04). 아무것도 고르지 않았으면 그 BPM 프로세스 자체(이름·판·업무 자리·진입 정의 — C17 `PATCH`). 접힌다. **폭은 [E]처럼 끌어 바꾼다** — 240~560(기본 288) | STU-04·STU-06 |
| [L] 아래 탭 | 「로그」(시험 실행이 낸 줄) · 「검사」(실행 전 검사 결과) · 「변수」(입력·출력 정의, 시험 실행 중에는 「지금 값」이 붙는다). 펴진 탭을 다시 누르거나 오른쪽 접기 아이콘으로 접힌다. **높이는 윗경계를 끌어 바꾼다** — 120~640(기본 288), [E]·[P]의 폭과 같은 손잡이를 눕힌 것이고 그 브라우저에 기억한다 | STU-01 [L] |

- **쓰기 단추는 관리자에게만** 보인다 — 「보기 전용」 계정은 캔버스를 **뷰어로** 연다(정말 못 고치는 배포본,
  [ADR-0051](../../../docs/decisions/0051-shared-process-conveniences.md)). 팔레트를 가린 편집기를 「읽기 전용」이라
  부르지 않는다.
- `libs/`의 파일을 누르면 **뷰어로** 열린다 — 받아 둔 것은 편집 대상이 아니다 (C17 경로 규칙).
- 상태 줄([S])을 두지 않는다 — 웹에는 창틀이 없고, 할 말은 머리 띠와 아래 탭이 한다.

**탭은 셋이다** — 「저작」 · 「시험 기록」 · 「정보」 ([ADR-0147](../../../docs/decisions/0147-workspace-has-three-tabs.md)).
탐색기가 파일을 고르면 가운데가 그에 맞춰 바뀌므로 「결정표」·「케이스」를 탭으로 두면 **같은 고르기가 두 자리에**
생긴다. 「검사」는 아래 탭이다 — 지금 보고 있는 그림에 대한 말이라 캔버스와 함께 보여야 한다.

### 「저작」 탭 — 가운데는 고른 파일이 정한다

| 고른 것 | 가운데 | 상세 패널 | 대신하는 것 |
| --- | --- | --- | --- |
| `.bpmn` | BPMN 캔버스 | 고른 요소의 속성 (`bpm:*` 요소마다 폼 — C14 모델에서 짓는다). 서비스 앱 태스크의 `app_id`·`operation`은 **「리소스」 탭과 같은 목록**(C7 서비스 앱)을 고를 거리로 띄우고, 등록된 것에 없는 이름이면 칸 아래 한 줄로 말한다 — **막지 않는다**(검사는 쓰기를 막지 않는다, 목록을 못 읽었으면 아무 말도 하지 않는다) | STU-04·STU-14 |
| `.dmn` | 결정표 격자 | 그 표의 입력·출력 열 | STU-04a |
| `.cases.json` | 케이스 목록 + 고른 케이스 | 쓰지 않는다 (케이스가 본문을 다 쓴다) | STU-07 |
| `process.json` | 없음 (탐색기에서 고를 수 없다) | — | — |

- **결정표는 캔버스 밖이다** ([ADR-0109](../../../docs/decisions/0109-studio-writes-decision-tables.md)) — 편집기가
  `.dmn`을 직접 쓴다. 그림은 **캔버스(bpmn-js)를 거쳐서만** 고친다 (C17 — 실행 취소 한 걸음·DI 순서·모르는 요소 보존).
- 리소스에서 노드를 만드는 길은 **탐색기의 「리소스」 탭**이다 (아래 절, ADR-0155).
- **결정표는 Center가 읽고 쓴다** ([ADR-0148](../../../docs/decisions/0148-center-reads-and-writes-decision-tables.md)) —
  브라우저는 격자만 다루고 DMN을 해석하지 않는다. 엔진이 거부할 칸은 저장되지 않고(422 `bad_table`) 그 사유가
  격자 위에 뜬다. 경고(겹친 입력 이름·빈 규칙 줄)는 막지 않는다.
- **케이스는 값마다 갈래를 고른다** (글·수·참거짓·JSON) — JSON 글상자 하나로 두면 `"3"`과 `3`을 사람이 가려
  적어야 한다 (STU-07이 지키던 규칙이다).
- **결재 답은 그림을 읽어 폼으로 짓는다** — 케이스를 고칠 때 캔버스가 떠 있지 않으므로 짝이 되는 정의
  (`process/<이름>.bpmn` — 엔진이 보는 그 짝이다)를 글자로 읽는다. 칸의 갈래는 그림이 정하고(C6
  `FormField.type`), **「답한다」를 켜지 않으면 그 결재는 기다린다**(기한 초과를 시험하는 길이다 — 빈 답과
  다르다). 그림에 없는 결재의 답은 **지우지 않고 그 자리에 말한다**(U8). 읽지 못하면 JSON 칸이다.
- **맡기기 결과·메시지는 JSON이다** — 맡길 패키지의 그림이 여기 없고(ADR-0082), 메시지는 보내는 쪽의
  모양이라 그림이 말해 주지 않는다.
- **이벤트 칸도 폼이다** — 그 이벤트가 쓰는 칸만 보인다(타이머·메시지·신호·오류 코드·경계의 「걷는다」).
  정의 수준 요소를 만드는 일이라 **캔버스를 거친다**(ADR-0022), 그래서 「적용」 한 번이 실행 취소 한 걸음이다.
- **패널은 접힌다** — 접어도 여는 띠가 남는다. 기억하지 않는다(새로 열면 펴져 있다).
- **아래 탭 「변수」**는 그림의 `bpm:process`(입력·출력 선언)다 — 작업공간 정보가 아니라 **캔버스 쪽**이고,
  「적용」은 그 요소를 통째로 캔버스에 넘겨 **실행 취소 한 걸음**이 된다.

### 탐색기의 「리소스」 탭 — 부를 수 있는 것 (STU-03)

[ADR-0155](../../../docs/decisions/0155-resources-are-a-tab-in-the-explorer.md). 왼쪽 [E] 패널이
「파일」·「리소스」 **두 탭**이다. 맨 위에 **찾기 칸 하나**(이름·id로 거른다), 그 아래 **뿌리 둘**:

| 뿌리 | 재료 | 줄 | 만드는 것 |
| --- | --- | --- | --- |
| 공유 프로세스 | C5 `GET /packages?kind=process_lib` | 패키지마다 머리(`<이름> v<판>`) + 그 아래 `provides.processes`의 정의들 | `bpmn:CallActivity` + `calledElement` |
| 서비스 앱 | C7 `GET /resources?type=service_app` | 앱마다 머리(`<이름>`) + 그 아래 `operations` | `bpmn:ServiceTask` + `bpm:serviceCall{app_id, operation}` |

- **만드는 몸짓은 둘이고 결과는 같다** — 줄을 **캔버스로 끌어다 놓거나**, 줄 오른쪽의 **「+」**
  (말풍선 「캔버스에 추가」)를 누른다. 끈 자리에 만들고, 단추면 보이는 곳의 빈 자리에 만든다.
  **같은 캔버스 명령 하나**를 부르니 되돌리기도 한 걸음이다 — 만든 바로 뒤에 `Ctrl+Z`가 듣는다
  (아래 「되돌리기」).
- **입력·출력 짝은 짓지 않는다** — 내 변수 이름을 알아야 하는 일이다. 만든 노드는 **골라 둔 채로**
  두어 오른쪽 상세 패널에서 바로 잇는다.
- **설치되지 않은 공유 프로세스의 줄은 꺼진다** — 줄 끝에 「설치 안 됨」, 말풍선은 「「정보」 탭에서
  설치해야 부를 수 있습니다」다 (ADR-0051: 멤버십은 Center 목록 그대로이고 설치 여부만 덧붙인다).
  설치되지 않은 호출은 실행 전 검사 B14가 막는다.
- **묶음 머리와 꺼진 줄은 끌리지 않고 「+」도 없다** — 만들 것이 없는 줄이다. 꺼진 줄 끝은 「잠김」이다.
- **확장이 기여한 자원의 뿌리는 없다** — 지금 깔린 확장이 하나도 없다 (ADR-0114).
- 빈 상태: 「부를 수 있는 것이 없습니다. 공유 프로세스는 CON-06, 서비스 앱은 CON-18에서 옵니다.」(U12)
  닿지 못하면 그 자리에서 까닭을 말한다 — **들고 있지 않는다**.
- **보기 전용 계정에게도 탭은 보이고 만드는 길만 없다** — 무엇을 부를 수 있는지 보는 것은 읽기다.

### 되돌리기 — 단축키뿐이다 (단추가 없다)

[ADR-0156](../../../docs/decisions/0156-undo-is-a-shortcut-only.md). `Ctrl+Z`(macOS `Cmd+Z`)가
되돌리기, `Ctrl+Y`·`Cmd+Shift+Z`가 다시 하기다 — **bpmn-js의 키 그대로**이고 머리 띠에 단추를
두지 않는다.

- **그림이 키를 쥐고 있을 때만 듣는다.** 리스너가 그림(SVG)에 달려 있어, 속성 칸·결정표 격자·
  케이스 편집기에서 글을 쓰다 누른 `Ctrl+Z`는 **그 칸의 되돌리기**다. 그림에 키를 쥐어 주는 것은
  그림을 한 번 누르는 것이고, 아무도 쥐지 않았으면 그림 위로 마우스를 올리기만 해도 된다.
  (`Ctrl+S`는 반대다 — 저장은 파일 하나의 일이라 **화면 어디서 눌러도** 듣는다.)
- **바깥에서 만든 노드도 바로 되돌려진다** — 리소스 탭의 「+」·끌어다 놓기는 만든 뒤 키를 그림에
  돌려준다.
- 되돌릴 자리가 **눈에 보이지 않는다**는 것이 이 결정의 값이다 (ADR-0156 「결과」). 노드 하나를
  지우는 것은 고르고 `Delete`다.

### 저장 — 「저장」 단추다 (자동 저장이 아니다)

`Ctrl+S`와 머리 띠의 「저장」, 떠날 때 묻기(U11). C17이 `If-Match`로 덮어쓰기를 막고 **두 사람이 같은 파일을
열면 나중 사람이 409 `stale`**을 받는데, 자동 저장이면 그 충돌이 **타자 치는 중에** 뜬다.

충돌 창은 이렇게 말한다: 「다른 사람이 먼저 저장했습니다. 「새로 읽기」를 하면 지금 편집이 사라집니다.」 —
단추는 「새로 읽기」 · 「다른 이름으로 저장」 · 「머무르기」(기본)다. **합치지 않는다** (C17 — 합치면 XML이 깨진다).

### 「시험 기록」 탭

돌려 본 시험 실행들의 기록이다. 돌리는 단추는 머리 띠의 「시험 실행...」이다 — 탭과 단추가 같은 이름이면 탭을 누를 때 돌아가는 줄 안다 (ADR-0185).


| 영역 | 내용 |
| --- | --- |
| 머리 | 「시험 실행...」을 누르면 작은 창: 「케이스」(없으면 「비교 안 함」) · 「수행 모드」(자율 수행 / 결정 수행). C17 `POST …/test-runs` |
| 목록 | 최근 것부터 — 실행 id(`test_…`) / 상태 / 판정 / 케이스 / 수행 모드 / 시작 / 소요 / 「배운 것 <n>개」 |
| 상세 | 고른 실행의 **로그**(아래 탭 「로그」와 같은 줄) · **노드 색**(캔버스에 그대로 입힌다 — `node_states`) · **변수**(업무 값이라 **키만** 보이고 펼쳐야 값이다 — U10) |

- 판정은 셋이 아니라 **다섯**이다 — 「통과」·「실패」·「비교 안 함」·「중지」·「오류」 (C17 `VERDICT_*`, U6).
  **도는 중에는 판정이 비어 있다** — 끝난 줄로 읽히지 않게.
- 실행 중에는 「시험 실행...」이 **「중지」**가 된다 (U5, C17 `DELETE …/test-runs/{run_id}`).
- **결재·확인은 여기서 답하지 않는다** — Center 결재함(CON-04)으로 간다 (C6·C17). 케이스가 답을 적어 두었으면
  실행기가 그 자리에서 답하므로 결재함에 오지 않는다. 목록에서 운영과 가르는 것은 **실행 id**(`test_`)다.
- 시험 실행은 **작업 지시 목록(CON-05)에 없다** (C17) — 저작하는 사람가 돌려 보는 것이라 운영자가 읽을 것이 없다.
- STU-08(실행 대화상자)·STU-09(실행 표시와 결과)가 하던 일이다.
- **케이스는 진입 정의 옆의 파일에서 온다** (`cases/<진입 정의 이름>.cases.json`) — 엔진이 그 자리만
  보기 때문이다 (`core.testrun.runner`의 `read_cases`). 다른 정의의 케이스를 목록에 올리면 돌릴 때
  「케이스가 없다」가 된다.
- **도는 동안 콘솔이 되묻는다** (1.5초마다 `GET …/test-runs/{run_id}`) — 실행기가 진행을 올리는 길이
  `PUT …/test-runs/{run_id}` 하나라 콘솔로 밀어 주는 길이 없다. 끝나면 묻기를 멈춘다.
- **로그와 노드 색은 「저작」 탭에도 간다** — 로그는 아래 탭 「로그」, 노드 색은 캔버스에 그대로다.
  돌려 본 사람이 탭을 오가며 고치는 자리라, 결과를 한 탭에 가두지 않는다.
- **변수는 접어 둔다** — 펼쳐야 값이 보인다 (U10, 업무 값이다).
- **중지는 판정하지 않는다** — 판정이 「중지」이고 통과·실패가 아니다 (C17).

### 「정보」 탭

이름 · 판 · 설명 · 업무 자리(회사 › 부서 › 직원) · 진입 정의 · **받아 둔 공유 BPM 프로세스**(`libs/` — 설치·제거,
C17 `POST …/libs`). STU-06·STU-11이 하던 일이다.

- **id는 보이기만 한다** — 배포 후보를 지을 때 그대로 패키지 id가 되므로 바꿀 수 없다 (C17).
- **그림을 고치는 칸은 없다** — 입력·출력은 아래 탭 「변수」(그림의 `bpm:process`)이고 여기는 작업 폴더
  기록(`process.json`)이다. 실행 위치 칸도 없다 ([ADR-0144](../../../docs/decisions/0144-remove-the-pc-runner.md)).
- **회사는 고르지 않는다** — 만들 때 정해지고 바뀌지 않는다 (C16). 부서·직원은 Center의 조직 목록에서
  고르고, 조직이 비어 있어도 화면은 뜬다.
- 받아 둔 것은 **`<id>@<판> · 부를 수 있는 정의 n개`**로 보인다 — 판은 **기록이 안다**(`libs/`는 평평하고
  파일 이름에 판이 없다). 읽지 못한 정의는 부를 수 없다고 그 자리에 적는다 (B14가 같은 말을 한다).
- 「설치...」의 고를 거리는 **C5 패키지 표의 `process_lib`**뿐이다 (C7에 그 갈래가 없다). 같은 id가 이미
  있으면 **갈아 치운다**(「갱신」이 그 길이다). 「제거...」는 확인 창이고 **그 패키지가 넣은 파일만** 지운다.

### 실행 전 검사

머리 띠의 「실행 전 검사」를 누르면 아래 탭 「검사」가 열리고 결과가 거기 쌓인다 (C17 `POST …/check`).

- **오류만 돌리기를 막고 경고는 보인다.** 줄마다 「<규칙> — <무엇이> — <어디서>」이고 노드를 가리키는 줄은
  누르면 캔버스의 그 노드를 고른다.
- 담아 둔 결과를 그대로 주면(`cached`) 「<시각>에 검사한 결과입니다」 한 줄을 붙이고 「다시 검사」를 둔다.
- 맡을 서버 실행기가 없으면(503 `no_runner`) 「검사할 서버 실행기가 없습니다 — <까닭>」. 담아 둔 결과가 있으면
  그것을 보이며 **언제 것인지 말한다** (U8 — 모르는 것을 추측하지 않는다).
- **「흠이 없습니다」와 「아직 검사하지 않았습니다」는 다른 말이다** — 뭉개면 검사한 적 없는 그림이 통과한
  것으로 읽힌다 (U8). 파일을 고치면 담아 둔 결과를 **버린다** — 그 그림의 것이 아니다.
- 돌고 있는 동안 콘솔이 되묻는다 (지시는 하트비트로 내려가므로 주기만큼 늦는다).

### 배포 후보로 만들기

머리 띠의 「배포 후보로 만들기」 (C17 `POST …/package`). **종류를 묻지 않는다** — 프로젝트의 어느 칸에 있는지가
정한다 (ADR-0176: 「프로세스」 칸이면 프로세스, 「공통 패키지」 칸이면 공유 프로세스 `process_lib`). 작은 창은
무엇을 짓는지 한 줄로 말하고(「프로세스로 짓습니다」 / 「공통 패키지로 짓습니다」) 「만들기」를 받는다.

- 짓는 것은 **서버 실행기**다 — 누르면 **202**로 받고 「짓는 중입니다」가 머리 띠에 뜬다. 끝나면 「<패키지 id> v<판>을
  후보로 올렸습니다」와 CON-06(「라이브러리 › 공통 패키지」 — 상세)으로 가는 링크. 승인은 「배포 › 승인 대기」(CON-15)에서 한다.
- **올린 것은 후보다** — 승인·배포는 바뀌지 않는다 (C2·CON-06·CON-15). 「콘솔에서 저작한 것이 저절로 현장에 가지
  않는다」를 그 자리에 한 줄로 적는다.
- 짓다 실패하면 사유 한 줄 먼저, 상세는 그 아래 (U13).
- 진입 정의가 없으면(422 `no_entry`) 「진입 정의를 먼저 고르세요 — 「정보」 탭」. **공유 프로세스는 묻지 않는다** — 진입이 없다 (C1).
- STU-12(공유 BPM 프로세스 내보내기·올리기)가 하던 일이다. **「내보내기」(파일로 저장)는 없앤다** — 작업 폴더가
  서버에 살고 받는 쪽도 Center다.

**「내 PC로 내려받기」를 두지 않는다.** 데스크톱 Studio는 zip을 만들어 사람이 날랐는데, 이제 짓는 것도 받는 것도
서버 안이라 **내려받을 까닭이 없다.** 작업공간을 들이는 길은 「파일에서 가져오기」 하나다. (저장소 밖으로 꺼내야
할 일이 정말 있으면 그때 `GET …/bundle`을 사람 길로도 연다 — 지금은 실행기 키 전용이다.)
